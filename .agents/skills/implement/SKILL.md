# 实施与交付

将一个已获授权的明确目标落实为可验证的改动。输入可以是聊天要求、规格或工单；小任务直接实施，多工单协调见 [implement-spec](../implement-spec/SKILL.md)。已有诊断或测试流程进入本技能时，复用其基线与结果，从尚未完成的步骤继续。

## 1. 核对目标与基线

读取原始要求及后续修正；引用议题时按[议题跟踪约定](../../../docs/agents/issue-tracker.md)读取正文与相关评论。依据[现状与目标规则](../../../docs/agents/change-workflow.md#现状与目标依据)分别核对受影响机制与正确预期，并检查[交接条件](../../../docs/agents/change-workflow.md#阶段交接与可实施条件)。

编码前按[实施前设计核对](../../../docs/agents/change-workflow.md#实施前设计核对)判断是否触发，补齐适用的独立结论；已有结论核对范围与版本后复用，局部变更沿用简短核对。

按[分支与 PR 交付](../../../docs/agents/issue-tracker.md#分支与-pr-交付)确定任务分支、目标分支与已有 Issue／PR，核对完整差异是否属于本次范围。保留修改前基线，区分原有改动与本任务范围；核对原始目标、适用规则、影响、假设和验证安排，交付时按[简短记录约定](../../../docs/agents/change-workflow.md#任务记录试行)合并保存，已有记录直接沿用。已有用户决定、接缝和授权继续有效；仅补充会改变方案的缺口。

**完成条件：** 能用来源解释现有机制和目标，前置依赖已满足，关键假设已解决，基线与本次范围可定位。

## 2. 分步实现与验证

按影响逐步修改并核对调用者和依赖；受审设计决定变化时，按[实施前设计核对](../../../docs/agents/change-workflow.md#实施前设计核对)补查后继续相关实施。测试先行、缺陷回归或集成测试使用 [tdd](../tdd/SKILL.md)，复用现有接缝；缺陷修复沿用 [diagnosing-bugs](../diagnosing-bugs/SKILL.md) 的复现、定位和回归结果。技能回引时继续当前任务，复用已完成工作。

按[验证依据与覆盖](../../../docs/agents/change-workflow.md#验证依据与覆盖)选择能验证目标行为的检查。开发中运行相关非浏览器测试，收尾执行[维护手册要求的检查](../../../docs/MAINTENANCE.md#每次改动)，按影响选择定向或完整测试；发布前运行完整测试。纯文档按文档检查范围执行。发现新影响或原假设不成立时，更新任务记录并补查。

按[证据版本与检查配置](../../../docs/agents/change-workflow.md#证据版本与检查配置)直接执行适用检查并保存对应版本及结果；需要机器核验旧结果适用性时按该规则选择证据工具。高风险验收条件在实现前独立核对，检查配置变化对照任务基线审查；结果失效后补查并复查受影响范围。

按[文档影响规则](../../../docs/agents/change-workflow.md#文档影响与维护)同步维护受影响正文，或记录现有描述仍准确的依据。领域术语、当前行为和历史决定沿用各自权威位置。

已约定的广泛重构若将整体通过条件放在最终集成工单，本工单须完成约定的局部验证，并记录暂未通过的整体检查、原因及承担者；不能据此宣称整体完成或发布。约定范围外的失败仍须处理。

**完成条件：** 目标场景和保留行为有依据或验证，错误路径、覆盖限制和文档影响明确，本工单约定检查通过；留给最终集成的检查和人工验收单独记录。

## 3. 独立审查与修正

使用 [code-review](../code-review/SKILL.md) 审查完整本次改动，提供原始目标、修改前基线、相关规则与当前文件版本。按[发现与交接规则](../../../docs/agents/change-workflow.md#发现与交接)处理阻断项，判断建议的收益和范围；修正后按影响重跑检查，并交回审查者复查。

**完成条件：** Spec 与 Standards 对同一交付版本明确结论，阻断项已解决，修正内容已验证和复查，剩余限制已记录。

## 4. 提交与交付

完成格式化等写入后，逐项核对[交付记录](../../../docs/agents/change-workflow.md#交付与验收记录)中的版本、检查有效性、覆盖、最终审查、阻断项及验收状态；使用证据工具时实际执行 `verify`。缺失或过期的必要证据按影响补齐，复用结果保留核对依据。

检查最终差异与暂存范围，将本任务改动提交到任务分支；原有无关改动保持独立。使用 [pr](../pr/SKILL.md)从最终差异和有效证据整理正文，按[议题与 PR 约定](../../../docs/agents/issue-tracker.md)推送任务分支、创建或更新 PR 并回读结果。已有明确仅本地安排时沿用，远端失败时保留本地成果并标明未完成；合并另行授权。

按[交付与验收记录](../../../docs/agents/change-workflow.md#交付与验收记录)分配材料：PR 保存公开结果、文档影响、验证与审查摘要和剩余验收项，本机保存详细证据、必要取舍及关联索引。交付实际 PR 链接与状态；仅本地或远端尚未完成时给出本机位置和待办。后续反馈与修复沿用同一事项。

**完成条件：** 交付记录各项有可定位依据，检查和两轴最终审查适用于实际提交内容，当前阻断项已解决并复查；本地检查、远端发布、CI、人工验收与合并状态分别明确，待人工验收版本附适用验收项；远端失败可交付本地阶段，不宣称 PR 已完成。
