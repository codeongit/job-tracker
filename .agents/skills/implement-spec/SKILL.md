# 协调规格实施

输入是明确且获授权的规格及其关联工单，目标是在同一集成分支交付完整规格。实施者按 [implement](../implement/SKILL.md)完成分派的实现与检查，主协调者承接独立审查、修复调度、提交和合并，并负责整体验证。只有一个明确实施单元时，直接使用 implement 完成全部步骤。

工单构成带前置依赖的**任务图**。当前可开始的工单必须满足[变更共用规则](../../../docs/agents/change-workflow.md#阶段交接与可实施条件)，且所需前置结果已经合入集成分支。按实际资源、接口稳定性和写入冲突安排并行，同一集成分支的合并与修复串行执行。

## 1. 核对规格与任务图

读取原始规格、关联工单及后续修正；GitHub 议题按[议题跟踪约定](../../../docs/agents/issue-tracker.md)读取正文和评论。核对目标来源、确认状态、范围限制、整体验收条件，以及各工单对规格的覆盖关系。

记录前置依赖、可并行部分和跨工单验证责任。尚未解决的关键决定交回需求澄清，仍可独立实施的部分继续推进。依赖冲突或循环须先解决，生成工单和标签本身不证明工作已经可实施。

主协调者按[实施前设计核对](../../../docs/agents/change-workflow.md#实施前设计核对)核对任务图涉及的设计结论；缺失时在相关分派前补齐，并据此调整边界和依赖。实施中受审决定改变时，同样由主协调者组织补查及受影响工单的交接。

**完成条件：** 规格验收项均有实施或验证归属，当前可开始的工单明确，关键未知与授权边界已记录。

## 2. 准备集成分支与上下文

按共用规则保留[修改前基线](../../../docs/agents/change-workflow.md#现状与目标依据)，通过规格、工单、PR 和原始日志传递必要交接材料。沿用用户指定的集成分支，或按仓库约定创建本任务分支。记录每个工单的负责人、分支、基线、合入提交及验证状态。

以**上下文指针**交接原始规格、工单、研究材料、决定来源和前置提交，附上理解当前任务必需的摘要。需要探索代码或外部契约时，可先分派研究子代理；材料放在所有后续实施者可读取的位置，并按仓库隐私规则保留。

主协调者按[议题与 PR 约定](../../../docs/agents/issue-tracker.md)确定对外分支、PR 和议题关联；正文使用 [pr](../pr/SKILL.md)。内部工单候选只交给协调者，不各自发布重复 PR。保留既有仅本地安排，默认远端操作在任务实施授权内，合并远端目标分支另行授权。

**完成条件：** 集成分支、基线、任务图及交接材料可定位，外部操作沿用已有授权。

## 3. 分派单个工单

从当前可开始的工单中，选择能独立推进的任务分派给实施子代理。每个实施者使用独立 worktree 和分支，从包含所需前置提交的集成分支开始，按 [implement 第 1—2 步](../implement/SKILL.md#1-核对目标与基线)完成目标核对、实现和必要检查。涉及高风险变更时，主协调者在实现前安排独立验收核对，并将适用结论交给实施者。

交接时给出工单范围、必须保留的行为、来源指针、前置提交、接口约定及回报要求，并明确本次分派止于候选交接，独立审查由主协调者调度。实施者返回 worktree、分支和基线、完整候选差异及相关新增文件、实际检查结果与适用版本、文档影响、剩余限制及接口变化；通过协作消息返回结果及已有材料引用。交出候选后结束本次执行，释放执行槽位，保留工作树供审查或修复；后续修复由主协调者再分派。共享文件或未稳定接口会造成冲突时，缩小并行范围或先完成前置任务。

**完成条件：** 实施者的边界及工作区明确，候选材料可定位并由主协调者承接。候选交接只表示本次实施执行结束，工单完成及依赖解除仍须满足下节条件。

## 4. 固定候选、统一审查并串行合并

主协调者取得候选后，核对本任务范围和检查版本，在实施工作区创建本地候选提交，或明确安排实施者代为提交；原有无关修改保持独立。随后按 [code-review](../code-review/SKILL.md#4-分派独立审查)固定完整材料并直接分派独立审查，统一安排容量；保留同一 Spec 审查者先基线后差异的顺序及独立 Standards 结论，复用仍适用的前置或局部判断。

发现阻断项时，将问题及复查要求交回原实施工作区，实施者修正并补查后返回新候选，由协调者组织追加提交、结束本次执行；主协调者更新受影响材料并交回审查者复查。候选或规则变化时核对检查与审查适用性，工单未完成期间保留其依赖阻塞。

候选满足 [implement 第 3—4 步](../implement/SKILL.md#3-独立审查与修正)的检查、两轴审查及阻断项条件后，核对候选提交与受审版本一致，再由一个合并责任人合入任务集成分支。此为本机候选集成，不替代对外 PR 及其目标分支合并授权。可使用合并子代理，但同一时刻只有一个责任人修改集成分支；发生冲突时使用 `resolving-merge-conflicts`追溯双方意图。

每次合并后按影响验证连接、更新工单状态与任务图。只有前置结果已合入且依赖接口成立，才启动后续工单；已有并行分支受新变化影响时，先同步依赖并补充验证。工单因新发现受阻时，记录原因、解除条件及仍可继续的工作。广泛重构已约定中间批次不能独立通过全部检查时，沿用各工单的局部验证及最终集成责任，完整通过条件在最终集成工单兑现。

**完成条件：** 工单的必要检查与两轴审查完成，阻断项已解决并复查，提交与受审版本一致；已合入内容与任务图状态一致，合并或接口变化有相应验证，后续工单使用有效的前置结果。

## 5. 验证并审查完整规格

全部实施单元合入后，以原始规格的整体验收条件核对跨工单行为、必须保留的约束和文档影响。按[维护手册](../../../docs/MAINTENANCE.md#每次改动)运行适用检查；逐票通过不能替代整体连接验证，人工验收与未验证部分单独标明。

对同一最终分支版本调用 [code-review](../code-review/SKILL.md)，提供原始规格、修改前基线、完整改动、各工单的来源与验证记录。指定实施者在已有授权内解决阻断项，修复串行合入，再按影响验证并交回独立审查者复查；变更后的结论对应新的文件版本。

按[证据复用规则](../../../docs/agents/change-workflow.md#审查证据与发现)承接仍有效的逐票检查和审查，最终补查跨工单连接、集成差异与整体验收缺口；逐票记录的存在本身不能证明这些连接成立。

**完成条件：** 整体目标与约束有对应证据，阻断项已解决且受影响部分已复查，剩余限制和人工验收项明确。

## 6. 交付与清理

按[交付与验收记录](../../../docs/agents/change-workflow.md#交付与验收记录)汇总最终提交、规格覆盖、实际验证、审查结果及剩余验收项。按[议题与 PR 约定](../../../docs/agents/issue-tracker.md)发布或更新最终 PR，复用已有有效证据并回读远端状态；满足上一步完成条件时可标为可审查。可审查不等于人工验收通过或已获合并授权。

确认必要提交、任务材料及恢复线索已保留后，只清理本任务创建且不再需要的实施 worktree。保留尚有未合入成果或未保存材料的工作区，并说明其用途；清理范围不包含用户原有工作区或无关分支。

**完成条件：** 交付物与验证版本一致，规格整体状态如实可查，本任务临时工作区已清理或说明保留原因。
