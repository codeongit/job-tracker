# 求职工作台

供个人使用的求职管理网页：岗位、沟通时间线、下一步行动、Markdown 导入、JSON 备份和 GitHub 私有仓库同步。

## 本地使用

推荐 Node.js 24 LTS（维护与 CI 固定此版本），无第三方运行依赖。在 macOS 双击 `启动.command`，或运行：

```sh
pnpm start
```

浏览器打开终端显示的 `http://127.0.0.1:4317`。v0.8.0 本机版把正式记录保存到 `.local/workspace/`；第一次升级必须在保存正式记录的原浏览器先导出并核对完整迁移备份（含草稿、数量和 SHA-256），再执行迁移。缺少原工作区、工作区与草稿均为空，或备份后内容发生变化时都会停止，不能误用空浏览器初始化。迁移完整保留原记录、同步基线、冲突及原始迁移副本；浏览器 IndexedDB 此后作为缓存，同一本机服务下的浏览器访问同一份正式工作区。另一浏览器若仍有不同的 IndexedDB，不会被服务静默覆盖：必须先下载完整备份，再明确切换到服务正式数据；并发初始化也不会把另一来源误报为迁移成功。

也可用 `pnpm service start` 手动启动后台服务，`pnpm service status` 查看状态，`pnpm service stop` 停止。没有登录自启；启动服务本身不访问 BOSS，重启服务后也不会自动恢复跟踪。本机服务不可用时可查看已有缓存、保留草稿，正式保存需要服务恢复。手机和公开静态版仍独立使用 IndexedDB，手动同步 GitHub。

初次打开时选择 Markdown 文件导入，默认年份为当前年份，历史记录可选择 2026 等年份。预览会显示重复岗位和疑似填反的公司/岗位，确认后导入。岗位 ID 相同的源行默认跳过，不覆盖已经补记的记录。JSON 支持合并恢复和回到快照，操作前自动保留本机快照；建议另行下载完整备份。

主导航保留“行动、岗位”两个业务入口，“数据与同步”用于设置。打开网页默认进入“行动 → 今天”：今天展示逾期和今天到期的待办；“接下来”按计划日期展示未来待办；“待整理”分别展示建议核实、未设日期的行动和未设下一步的岗位。今天的“今天新增 · 待安排”入口带数量，可以直达待整理中的具体岗位。建议核实把“简历被索要”和原记录中的“带人经验”分别列出，可以确认“已发送/已答复”，或直接加入今天的行动；完成这种核实待办时也保存确认结果，无关待办不遮挡核实项。`createdAt` 用于判断今天是否新增，`appliedAt` 始终表示首次联系日期。

岗位没有待办时，“新增行动”会根据明确的招聘阶段和简历状态预填建议。例如简历已发送或对方已接收后，建议“询问面试安排”。计划日期默认是本地日历的 2 天后，也可以用快捷按钮改成今天、明天、1 周后或不设日期。预填内容可以直接修改；暂缓、已结束或已有待办的岗位保持空白，已保存的草稿优先恢复。

“岗位”使用每页 10 个岗位的列表，提供公司/岗位/联系人关键词、当前招聘阶段及日期筛选，条件同时满足才显示。默认全部阶段、全部日期，包含已结束岗位和无日期岗位。全部日期下按添加时间从新到旧排列，编辑岗位不改变排序；没有有效添加时间的旧记录排在后面，保留原相对顺序。指定日期时按当天事件排序。

手动新增岗位时，公司名与已有记录规范化后完全相同，会在公司输入框下提示现有岗位和当前阶段；公司与岗位都相同时加强提示为“可能是重复岗位”。匹配忽略首尾及连续空白、全半角和英文大小写，不做模糊匹配；已结束岗位仍提示，已删除岗位不提示。该提示最多展示 3 条并显示总数，不阻止保存。

人工消息状态只有“未读、已读”，手动新增岗位默认未读。招聘阶段从“已触达”开始，不再提供“待联系”。旧记录的“待联系”按“已触达”显示和筛选；既有人工记录的未知或未填写消息状态按“未读”显示。BOSS 自动接入的岗位若尚无人工作出消息状态，则显示独立的“平台观察”，不会把送达或未知呈现为平台确认的“未读”。明确保存岗位后才更新人工消息状态。导入时没有明确消息状态则默认未读，同时保留原始状态文字。

BOSS 岗位选择简历“已发送”或“对方已接收”时，表单会将消息设为已读，将已触达推进到沟通中，保存后生效；面试、Offer、已结束阶段保留。记录发送简历、核实已发送和完成“发送简历”行动也会同步更新。该联动按 BOSS 跟进流程设置，不用于其他渠道，也不批量修正历史数据；“被索要”和取消行动不会触发。

分天查询直接使用岗位页的日期框；选定日期后可以逐日前后切换或回到今天。“全部日期”只清除日期，“清空筛选”恢复全部条件。所选日期有计划、完成/取消、沟通或首次联系的岗位各显示一次，列表展示当天事件；打开详情可查看完整当天记录。跨日完成的行动分别保留在计划日和实际完成日，同日计划并完成只显示一次，导入产生的同日首次联系活动也会去重。页面显示当前招聘阶段，不还原历史阶段。

从行动或岗位列表打开岗位，都在当前页面查看详情；桌面使用右侧面板，手机使用带返回按钮的全页详情。关闭详情、保存编辑、恢复草稿或离开后返回，都会保留当前筛选、页码和浏览位置；主动修改筛选时列表回到第一页。刷新网页后回到“行动 → 今天”，岗位筛选恢复全部。详情顶部可记录沟通、安排下一步或更新阶段；在历史日期下查看岗位时，新沟通仍默认今天，完成/取消按实际操作时间保存。修改后岗位不再匹配当前筛选时，详情会保留并提示；关闭后继续查看剩余结果。

本地快捷导入可通过 `.local/config.json` 配置（此文件被 Git 忽略）：

```json
{ "sourceMarkdown": "/absolute/path/to/your-records.md" }
```

源文档通过只监听本机的开发服务读取，不复制到 `dist/`。公开网页只提供手动文件导入。

## BOSS 只读接入

BOSS 说明按阅读目的分为三份：

- [设计说明](docs/boss/DESIGN.md)：当前流程、采集与业务规则、动作预算和失败行为。
- [实现说明](docs/boss/IMPLEMENTATION.md)：模块、身份和字段、私有材料、交付与恢复契约。
- [使用与排障](docs/boss/OPERATIONS.md)：配置前提、命令、状态统计、补录与恢复步骤。

先完成本机工作区迁移、私有配置和账号绑定，再明确开始跟踪：

```sh
pnpm service start
pnpm boss start
pnpm boss status
```

服务和跟踪是独立生命周期；服务重启不恢复跟踪。平台只读，GitHub 由用户手动同步。停止、暂停、任务页恢复及纯本机补交按[命令与操作](docs/boss/OPERATIONS.md#命令与操作)执行；授权和隐私边界见[自动化操作规约](docs/AUTOMATION_POLICY.md)。

## 草稿与自动备份

新增/编辑岗位、下一步行动、沟通记录的输入会自动保存在当前浏览器。关闭表单保留草稿；刷新或关页后，从顶部“草稿箱”点击“继续填写”。正式点击保存才进入记录；设置中的令牌不进入草稿。不同岗位及页面的草稿各自保留。原岗位被另一页修改后，旧编辑草稿会提示核对，避免覆盖新内容。

本机网页和服务打开时，修改约2.5秒后自动备份，30秒检查重试。位置为项目内被 Git 忽略的 `.local/backups/`，每个浏览器来源保留最近30个备份日期的首份和最新一份。备份包含正式记录、同步基线、冲突双方及草稿，不包含 PAT、SSH 会话或密钥；不依赖 GitHub 连通。

在“数据与同步 → 独立磁盘备份”查看最近成功时间、立即备份、浏览/下载或恢复预览。即使清理浏览器，重开同一本机服务仍可列出旧来源的备份；全新空状态不会覆盖旧文件。刚输入就关页可能尚未写入磁盘，重新打开后会再备份。服务停止时网页会显示原因；单台电脑的磁盘备份不能抵御整机丢失，仍可下载到其他私有位置。

## GitHub 同步

### 本机 SSH 模式

本机开发服务可复用系统中已经配置好的 SSH key 和 SSH agent，不需要在网页输入 GitHub 令牌。私钥不会传入网页，也不会被复制到项目中。

在被 Git 忽略的 `.local/config.json` 中添加固定同步目标：

```json
{
  "sshSync": {
    "owner": "codeongit",
    "repo": "personalNote",
    "path": "简历准备/job-tracker/data.json"
  }
}
```

保留已有 `sourceMarkdown` 字段，重启服务并刷新网页。页面的同步目标与此配置一致时，会自动使用 SSH，“数据与同步”中显示“本机 SSH 同步 / 无需令牌”。

服务使用独立的 `.local/ssh-cache.git` bare 缓存，读取远端最新分支，只为指定 JSON 生成提交，然后普通 push。它不操作你的 Obsidian 工作树，不执行 force push。缺少 SSH 授权、远端不可达、目标公开或版本冲突时会停止；缓存和私钥都不通过静态目录提供。

本机写接口需要同源请求和随机页面会话凭证，客户端不能指定其他 Git 远端或文件路径。每次 SSH 读取会由服务签发绑定正式 revision、远端 SHA 与上传内容摘要的一次性同步事务；PUT 只能上传该计划，成功后网页只用事务标识确认，不能把任意整库作为“已同步”提交。上传期间的新编辑由服务在确认时重基并继续保持待同步。无需手动配置会话凭证。仓库可见性通过无令牌的公开元数据接口结合 SSH 访问核实，因此断网或接口限流时仍会暂停同步。

### 手机和公开网页的令牌模式

在“数据与同步”填写账户、私有仓库及 JSON 路径。项目默认目标为 `codeongit/personalNote` 的 `简历准备/job-tracker/data.json`，可自行更改。

1. 创建 fine-grained personal access token，仅选择数据仓库，并赋予 Contents: Read and write。
2. 在网页设置中填入令牌并保存。令牌只在当前页面内存中使用，刷新后需重新填写。
3. 点击“立即同步”。首次创建云端数据文件会明确显示仓库和路径，由用户发起初始化。
4. 换设备后用相同目标同步即可读取记录。发生冲突时选择本机或云端版本，再次同步提交。

同步只读写指定数据文件，但 GitHub 令牌权限本身覆盖所选仓库，无法限定到一个文件。只在自己信任的网页上配置令牌；如希望进一步隔离，可以改用专门的私有数据仓库。

手机/公开静态版离线时已打开的页面仍可保存到自己的 IndexedDB；本机模式正式保存始终依赖本机服务，服务断连不会降级成另一份浏览器正式库。没有缓存完整应用用于离线启动，也没有后台云同步。清理浏览器仍会删除该浏览器草稿及静态版未同步记录；本机正式提交独立保存在磁盘。

## 公开部署

界面代码可以公开，求职数据必须放在私有仓库。`dist/` 不包含实际岗位数据，项目也不读取私有仓库来构建网页。

准备发布到新的公开仓库时，仅提交项目源代码，保留 `.gitignore`。可手动部署 `dist/` 到 GitHub Pages，或在确认目标仓库后配置 Pages 工作流。公开代码仓库为 https://github.com/codeongit/job-tracker；已配置代码检查工作流，未配置公开网页部署。

## 结构

- `dist/model.js`：数据校验、Markdown 导入、去重、三方合并和删除标记。
- `dist/storage.js`、`local-workspace.js`：本机命令适配、IndexedDB 缓存及静态模式事务。
- `dist/github.js`：私有仓库校验、Contents API、SHA 冲突检测和同步快照确认。
- `dist/app.js`：实际操作界面及可选的 WebMCP 打开新增表单入口。
- `dist/boss/contracts/`、`rules/`：共用格式、岗位身份、简历含义、归属和岗位证据规则。
- `dist/boss/application/`、`dist/source-ledger.js`：浏览器和服务共用的业务应用、人工决定及来源账本；`dist/boss/client.js` 负责浏览器服务连接。
- `dist/jobs.js`、`dist/daily.js`：岗位列表筛选，以及按岗位合并的日期记录。
- `scripts/serve.mjs`：仅监听本机的工作区服务、队列消费与显式跟踪控制。
- `scripts/workspace-store.mjs`、`workspace-consumer.mjs`：不可变正式提交、CAS、命令幂等及后台录入。
- `scripts/service-control.mjs`、`boss-control.mjs`：手动服务与跟踪生命周期入口。
- `scripts/ssh-store.mjs`：使用独立 Git 缓存，通过系统 SSH 读写固定的私有数据文件。
- `scripts/local-api.mjs`：限定同源和会话的本机 SSH 桥接接口。
- `collector/boss/`：platform/history/details/materials/persistence 分别负责平台读取、历史阶段、详情阶段、采集模型和私有保存恢复；`tracker.mjs` 编排一轮任务。
- `scripts/boss/control/`、`delivery/`、`shared/`：授权和预算、已保存材料交付、固定路径与脱敏诊断。根 `scripts/boss-control.mjs`、`boss-integration.mjs` 保留 CLI 薄入口。
- `test/`：纯函数及模拟 GitHub 同步回归测试，不访问真实仓库。

```sh
pnpm test
pnpm check
```

三方合并以稳定 ID 对齐记录；不同记录以及同一岗位的不同字段可自动合并，同字段人工分歧交由用户选择。冲突两侧都带上已确认的独立字段变化，选择后不会丢掉另一字段的修改。删除保留标记，岗位删除与新增关联任务冲突时会提示处理。

上传成功只确认实际上传的快照；上传前服务再次核对写者、同步目标、基线和冲突状态，上传期间的新编辑仍保留为待同步。存在同步冲突时，人工编辑和后台导入都只阻止冲突岗位及其依赖，独立岗位可以继续提交并同步重基到待解决候选；直接编辑冲突实体、恢复或切换同步目标仍要求先解决对应冲突。远端文件在已有同步基线后意外消失、远端单方面转移本机 BOSS 账号归属、失败、无权限或非法远端 JSON 都不会被当作可自动接受的数据，也不会清空正式记录。

## 长期维护

当前应用为 0.10.23、BOSS 规则 v17，版本以 [package.json](package.json) 和页面版本为准。开发使用固定 pnpm 与锁文件；本机服务没有数据库依赖。

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm check
pnpm format:check
```

`pnpm check` 以 Node 24 静态解析生产模块依赖，检查层级、循环、安全路径、dist 独立部署及采集器递归语法，并核对公开资源、版本和文档；不执行被检查模块，不替代运行行为测试。

真实浏览器相关测试由用户人工负责。代理负责代码、非浏览器测试和静态检查，交付时列出人工验收项；默认不启动浏览器或执行包含浏览器测试的 `pnpm verify`。现有浏览器脚本与 CI 保留，具体分工见 [维护手册](docs/MAINTENANCE.md#真实浏览器测试分工)。

“数据与同步”提供完整备份、本机快照、版本与连接检查。静态模式保留最近 20 个操作前浏览器快照；本机服务保留不可变完整提交与原始迁移副本。浏览器草稿的独立备份仍需要页面在线，请另行下载完整备份。
