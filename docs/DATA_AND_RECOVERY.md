# 数据升级、备份与恢复

## 三类版本

- 应用版本：`package.json` 与 `dist/version.js` 中的 `APP_VERSION` 必须一致。
- 共享数据格式：`schemaVersion: 1`，包含 opportunities、activities、tasks、imports。v0.3.0 没有改变云端格式。
- 本机工作区：`workspaceVersion: 2`，包含 data、base、config、generation、lastSync、pending。备份外层另有 `backupVersion: 2`，新增 drafts；读取兼容 v1 和旧数据 JSON。

IndexedDB 名称仍是 `job-tracker-v1`，数据库版本升为 2，新增 snapshots store。旧工作区第一次成功读取时，在同一事务中保存升级前原始快照并迁移；失败时不写半成品。旧页面阻止数据库升级时，关闭其他工作台页面再刷新。

## 新字段的维护规则

1. 共享字段发生变化时提升 DATA_VERSION，添加逐版本纯迁移函数；不能只改字段白名单。
2. 对 data、base、pending.data、pending.remote 和冲突记录双方一致迁移；保留稳定 ID、删除标记、未上传修改。
3. 使用合成的旧版本、有冲突、有关联删除的数据验证升级及幂等性，提交 fixture。
4. 遇到未来版本、缺少迁移或未知字段时停止写入；不得把未知字段丢掉后重新同步。
5. 迁移前快照必须与迁移写入同一事务成功。页面启动失败时保留原始导出入口。

目前没有虚构 v1→v2 的云端迁移；注册表在实际新增格式时补相应函数。本次真实迁移是本机工作区 v1→v2。

## 备份

“导出完整备份”保存当前完整工作区，包括未解决冲突的本机/远端版本和草稿，不包含令牌、SSH 会话或密钥。下载文件要单独存放在私有位置；不要提交到公开代码仓库。

本机自动快照在删除岗位、Markdown 导入、恢复备份、工作区升级和同步前生成，最多保留 20 个。快照失败会阻止相应修改。它们与 IndexedDB 一起被清理，不能替代下载到浏览器之外的独立备份。

页面无法启动时，“导出原始本地状态”跳过模型校验，保存原始数据供修复使用。损坏或未来格式的原始文件可能仍需修复/升级后才能导入，不能当作空数据处理。

## 草稿与独立磁盘备份

草稿单独存入 localStorage，最多200份；输入、下拉选择和中文组合输入结束均保存。表单关闭不等于丢弃；需要时在草稿箱继续填写或明确丢弃。草稿只包含岗位/行动/沟通字段，不包含设置。页面间恢复使用新 ID；原页面继续输入仍有自己的副本。提交校验失败保留草稿，成功只清除提交版本，提交期间的新输入仍保留。

本机默认将完整备份放入 `.local/backups/<浏览器来源 UUID>/`，无需配置 SSH。每次修改约2.5秒后写入，页面打开时每30秒重试；每日首份固定，latest 保存最近成功内容，各来源最多保留30个日期及 latest。没有内容变化不重复写入；全新空浏览器跳过备份，不覆盖其他来源历史。此目录被 Git 忽略且不属于静态服务目录。

“数据与同步 → 独立磁盘备份”显示状态，并提供立即备份、查看文件、下载和恢复预览。浏览器清理之后也可列出所有旧来源备份。备份不需要 GitHub 网络，但需要本机服务和网页同时运行；立即关页可能来不及写磁盘，重开后重试。设备丢失仍需另存到其他私有位置的副本。

完整备份v2读取兼容v1；旧v0.2.0不识别v2完整备份，不应降级后恢复新备份。浏览器内的20个操作快照仍仅保存工作区，不包含草稿历史；完整导出和磁盘备份包含草稿。恢复时保留已有草稿，并以新 ID 加入备份草稿；数量/配额预检失败不会先改正式工作区。草稿准备中发生异常会回滚本批副本；跨 localStorage 与 IndexedDB 无统一事务，若页面在两步之间被强制终止，可能留下未提交的恢复草稿副本，可从草稿箱核对整理。

## 两种恢复

| 操作     | 行为                                                                                                        |
| -------- | ----------------------------------------------------------------------------------------------------------- |
| 合并恢复 | 相同 ID 采用备份记录，本机独有记录保留；备份中的删除标记会联动关联记录                                      |
| 回到快照 | 采用快照记录，将本机和当前基线里快照没有的记录标记为删除；保持当前同步目标和 base，恢复作为一次新的本机修改 |

普通恢复不自动上传，也不把恢复后的数据直接标为已同步。恢复前总会保存当前快照；先核对结果，再手动同步。若云端自上次同步后又有编辑，仍需正常处理冲突，不能绕过版本检查。

含未解决冲突的完整备份只允许“回到快照”，恢复原同步目标、基线和冲突双方，随后先选择冲突版本。当前工作区已有未解决冲突时，先导出完整备份并处理冲突，再执行恢复。

旧版只包含 schemaVersion 的数据 JSON 仍可导入。Markdown 导出用于阅读，布局不同于原六列表格，不作为完整往返备份。

## 恢复演练

使用独立浏览器配置和合成记录：新增岗位 → 导出备份 → 删除 → 从本机快照恢复 → 核对任务/沟通记录 → 同步到合成远端 → 刷新再核对。自动浏览器测试覆盖这条流程、快照写入失败回滚、旧工作区升级和原始导出。

换电脑时：先在旧设备解决冲突并同步，同时下载独立备份；新设备配置同一个私有数据目标，先同步；只在需要找回本机未同步记录时导入备份。始终使用同一个浏览器和地址，localhost、127.0.0.1、不同端口、公开站点属于不同存储空间。
