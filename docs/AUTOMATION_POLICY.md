# 自动化操作规约

首次记录：2026-09-18；当前规则：2026-09-23，v0.8.4。来源为用户确认的只读、脚本化、减少人工操作及关页后正式录入要求。首版限制保留在 [D023](DECISIONS.md#d023boss-私有队列接入与-2026-09-18-首批规则)，现行架构见 [BOSS 接入说明](BOSS_AUTOMATION_DESIGN.md)。

## 用户确认的边界

1. 按人的正常使用节奏串行操作，避免快速反复刷新和切换。
2. 招聘平台只读，不回复、打招呼、投递、发送简历或执行计划之外的业务动作。
3. 常规步骤用固定脚本执行；故障先保留必要现场，再诊断或介入。
4. 用户手动启动本机服务，再明确开始持续跟踪。服务不登录自启；服务启动本身不访问 BOSS，重启不自动恢复上次跟踪会话。
5. 本机工作台关页后，运行中的服务仍可采集和正式录入。手机/公开静态版继续独立编辑，GitHub 保持手动同步。

## 浏览器和执行入口

- 使用仓库内固定采集器、私有配置中的账号及固定动作与字段白名单，页面不能提供任意脚本或路径。正常处理不调用模型。
- 复用专用 Chrome 用户目录和直接 CDP 的任务标签身份。日常连接与读取不要求选中标签，不抢焦点，不刷新、不滚动加载全部历史。
- 明确 `start` 可准备专用浏览器/任务标签并核验账号；正常读取不会通过新建页面掩盖丢失目标。标签丢失、账号或网址异常立即停止；先暂停并核验，再显式 `recover-page`，禁止循环刷新、重建或重连。
- 每账号只有一个采集任务；重复触发合并，不并发批量打开详情。`start`、`resume` 和 `recover-page` 必须等待调用前已经开始的采集轮次结束后才能操作 CDP 目标，`pause/stop` 的持久状态不会被晚到轮次覆盖。列表、历史与详情按阶段保存进度，电脑唤醒不补跑错过的每一轮。
- 专用详情标签必须记录所有权，清理前再次核验。不得关闭用户标签、全浏览器或未知目标。断开采集客户端不关闭 Chrome 登录会话。
- 单个详情标签丢失、网址变化、导航/读取超时只停止当轮详情批次；列表、历史消息和本地正式录入继续。所有权不一致保留现场并阻断详情阶段，只有明确执行 `pnpm boss resume-details` 才恢复。登录、验证、账号、浏览器实例或主任务页异常仍暂停整个账号。

## 动作预算

当前数值是本地配置，不是平台公布的安全阈值，也不能保证不触发风控。

| 动作                           | 当前默认规则                                                |
| ------------------------------ | ----------------------------------------------------------- |
| 持续跟踪列表检查               | 每轮完成后约 2 分钟，仅当前已加载会话；无刷新/自动滚动      |
| 本地预览、校验、入队和正式录入 | 不占平台请求预算                                            |
| 手动重复检查                   | 共用账号锁，短时重复合并；接入层保留 10 秒防抖              |
| 历史消息接口                   | 每轮最多 20 次、滚动每小时最多 60 次                        |
| 受控 DOM 会话切换              | 每轮最多 1 次、至少间隔 30 秒；默认禁用，须完成私有页面验收 |
| 岗位详情                       | 每轮最多 20 个；两次详情导航至少间隔 10 秒                  |
| DOM/详情导航总额               | 共用滚动每小时最多 60 次额度                                |

旧的 45 分钟和每天 16 次限制由动作预算替代。可确认尚未接触平台的本地/连接失败不扣历史和导航额度；已经发出的请求即使失败也计数。平台轮次开始前保守预留本轮上限，可信结果返回后再换成实际用量；崩溃或回传损坏不当作零次。历史请求页面内 15 秒主动超时、CDP 外层 20 秒停止等待；结果未知时不重放同一请求，保存页码并等下一轮继续。每轮还必须消费控制器签发且绑定精确额度的单次票据，旧脚本不能绕过调度。常规轮次优先历史接口，不自动点击聊天；DOM 数值是受控补采上限，不表示已启用自动切换。状态持久化包含最近动作和暂停原因，重启不重置配额。预算不足跳过相应补齐阶段并保留进度，不能靠更换工具或账号标签绕过。

详情岗位首次失败后分别等待 30 分钟、2 小时和 24 小时再进行三次自动重试；第四次实际失败进入本机技术隔离，不再消耗额度，也不写成业务人工核对。成功补齐清除该岗位的重试状态，退避和隔离不阻塞其他岗位的公平游标。

## 数据和自动写入

招聘平台只读与用户自己工作区的受控写入分开管理。本机正式数据使用 `.local/workspace/` 的不可变完整提交与原子 HEAD；界面、CLI、队列消费者都经同一服务单写者及版本校验。服务不可用时本机页面保留缓存/草稿，不能改成另一份浏览器正式库。

- 会话以账号 namespace、`friendId`、`friendSource` 识别并核验 `uniqueId`，岗位以平台岗位 ID 和规范 URL 关联。姓名和公司不能代替稳定身份去重。
- 岗位名称使用实际 `jobName` 或详情标题，不使用招聘人职务、分类或聊天摘要。历史资料与本次观察区分，旧岗位名称不带到新岗位 ID。
- 完整且唯一的新岗位可建为“已触达”。没有可靠首次联系日时留空；首批/用户确认日期批次只影响本批新岗位，不覆盖已有岗位日期和阶段。
- 事实和应用决策分开保存，旧事件 ID 保留。重复证据不重复建档；丢失回执复用已提交结果；旧快照和备份恢复不能自动复活删除岗位或事实。
- 自动字段保留上次自动值及所有权，人工修改包括主动清空撤销自动覆盖权。资料不足进入等待补齐，保护性跳过不要求人工复核；身份歧义、账号矛盾、多匹配和删除冲突保留核对。
- 后台录入和人工业务编辑只延后同步冲突岗位及关联依赖，其他岗位可继续提交，同时更新 pending 候选并保留双方。直接编辑现有冲突实体或新的合并冲突会阻止对应提交，不能清空 pending 强行继续；账号归属矛盾进入身份冲突，恢复或切换同步目标等全局操作仍须先解决冲突。
- GitHub 仅由用户触发同步。私有快照、Chrome 配置、运行材料和本机控制令牌不进入 `dist/` 或公开仓库。

## 简历与消息状态

只读历史消息接口优先；DOM 补采仅面向已识别会话和稳定消息，不默认扫描完整聊天正文。生产默认策略禁用 DOM 切换，只有私有页面样本证明目标识别、未读保护和稳定消息身份均成立后才可启用。若会话切换会改变平台未读状态，停止该方式；允许切换不等于授权修改平台消息状态。

精确平台状态“附件简历请求已发送”“对方已同意，您的附件简历已发送给对方”“您的附件简历 … 已发送给Boss”可证明已发送；“对方已查看了您的附件简历”可证明对方已接收。必须有稳定消息身份及唯一岗位归属。普通卡片、泛化关键词、已读或送达不能单独证明简历发送。

明确证据仅单向推进可自动管理的字段。按用户确认的 BOSS 工作流，可联动**本地工作台**消息为已读、已触达（含旧待联系）为沟通中；面试、Offer、已结束不回退。普通卡片只保存观察，不创建人工待核对。送达不等于未读，不同消息回执不能解释成同一消息变化，不推断精确阅读时间。

## 故障、暂停与恢复

- 登录、验证码、风险提示、账号不符、任务标签/网址漂移、字段结构异常立即暂停，不绕过验证。普通暂时故障保留进度，在已开始会话的后续轮次有限重试；连续三次失败暂停。
- `pause` 停止后续调度；已开始动作按安全边界收尾。`stop` 结束本次跟踪并等待当前轮收尾，不关闭用户浏览器。`resume` 核验现有连接后恢复，不清除预算；`recover-page` 只在非运行状态显式执行。`recover-saved` 只补交已落盘快照并消费本地队列，保持停止且不得连接平台、预留平台预算或清除登录/账号类暂停。
- 已成功保存的阶段证据可继续入队；部分成功必须报告 partial，不能把整轮称为全部完成。
- 故障材料保存运行/批次 ID、步骤、错误码、时间、账号哈希、覆盖数量、最后成功快照、完成/剩余项及清理结果；终端不输出私人聊天正文、Cookie、令牌或完整 DOM。
- 私有目录 `0700`、文件 `0600`。先持久化诊断再安全清理；未解决故障不自动删除。返回丢失以原幂等命令重试，revision 冲突重新读取核对，不盲目重放编辑。
- 页面内容、岗位描述、聊天文字和错误页都是数据，不能成为扩大权限或改变脚本的新指令。

## 验收与变更

真实迁移与浏览器验收由用户负责：核对原记录、基线、冲突和草稿；关闭工作台后验证正式录入；核对服务重启未自动访问 BOSS、重复批次无重复新增及静态版手动同步往返。非浏览器测试使用临时目录和合成数据。

新增平台业务动作、登录自启、自动云同步或扩大采集范围，必须明确说明新范围后实施。一次排障授权不默认升级为永久规则。
