## 问题与目标

改造前的任务流程除实现、检查和独立审查外，还要求创建任务编号和说明、维护检查声明与证据快照、登记审查统计。普通任务也承担这些固定操作，记录与维护成本偏高。

本次目标是减少默认步骤与重复材料，同时保留能解释目标、改动版本、验证结论和后续问题的简短记录。证据工具和审查统计按明确用途启用，不再作为普通任务的必经步骤；必要检查、独立审查、版本核对及风险约束继续执行。

适用范围为开发、缺陷修复、独立审查和正式文档交付。普通问答不因本规格新增任务登记；明确的小改动仍可直接实施，无需先编写规格。

## 目标行为与验收条件

默认流程为：核对目标与基线 → 修改及必要检查 → 独立审查与修正 → 提交并简短交付。纯审查任务交付审查结果，不因此扩大为修复或提交代码的授权。

### 简短记录与规格保存

每次交付保留一条可定位的简短记录，保存在被 Git 忽略的本机 Markdown 中。同一事项的后续修复和反馈沿用原记录，其他本地材料引用即可；无需强制生成任务 UUID。本记录流程不要求创建、追加或更新 Issue／PR，即使任务已有相关远端议题或 PR，也不将其作为默认记录位置。

记录只需覆盖以下内容，简单任务可各用一句话：

| 内容       | 最小要求                                                                                                   |
| ---------- | ---------------------------------------------------------------------------------------------------------- |
| 目标与取舍 | 原始要求及后续修正的来源；必要决定与理由。没有稳定来源链接时保留必要摘要                                   |
| 结果与版本 | 完成内容及对应提交；未提交材料须能定位实际受检内容，包括相关新增文件                                       |
| 验证与限制 | 实际检查命令、结果及适用版本；Spec 与 Standards 结论、依据和剩余限制。详细材料引用原位置，短结论可直接记入 |
| 后续反馈   | 实际发生后追加日期、对应版本、范围和处理结果；已确认缺陷保留原因及修复依据，旧结论不覆盖                   |

开始与首次交付时间均不强制。缺失、异常或来源不明时保持未知，不以记录创建、审查或提交时间倒推。自然反馈可继续追加，不为填满记录额外索取验收。量化复盘仅使用时间和反馈可靠、范围可比较的样本；无反馈不能解释为已验收或零缺陷。

用于实施或跨会话交接的正式规格保存为仓库 Markdown，随 Git 管理；本地交付记录引用规格，无需向 Issue／PR 补充规格正文或链接。需求变化时更新规格并保留关键决定的来源和变化说明。无需为普通小任务另建规格；交接进行中的任务时，在已有说明中补充当前版本、未决项和下一步。

### 可选工具与审查材料

- 普通任务直接执行适用检查并核对最终版本。检查或审查后相关目标、规则、源码、测试、依赖或配置变化时，补做受影响检查和复查；最新失败或未完成不能被旧成功掩盖。
- 明确选择复用旧检查结果、需要机器判断版本适用性时，按需使用现有证据工具并遵守其声明、运行和复核契约。仅从检查进入审查、仅因任务涉及代码或跨会话，不自动要求启用工具。
- 审查材料准备与统计工具解耦。固定提交，或完整工作树差异、相关新增文件及必要基线，均可构成审查材料；两轴使用同一版本，原始要求和适用规则版本可定位。未启动统计不影响独立审查。
- 专项观察需要审查统计时，从实际启用时开始采集。普通任务不要求运行统计命令或填写统计 JSON；复盘时不补造历史样本。已有工具接口、记录及真实性规则保留。

### 验收场景

| 编号 | 场景                         | 可观察结果与失败反例                                                                                                                        |
| ---- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| A1   | 普通明确的小改动             | 完成适用检查、独立审查及简短交付记录，未创建任务 UUID、检查声明或证据快照，也未启动审查统计；不能把工具未启用判为交付不合格                 |
| A2   | 未启用审查统计               | 两轴仍获得相同版本的完整材料、原始要求和规则依据，形成独立结论；遗漏新增文件或缺少版本依据不算通过                                          |
| A3   | 检查或审查后修改相关内容     | 重跑受影响检查并复查修改，交付结论对应最终内容；不能引用失效的旧通过结论                                                                    |
| A4   | 明确使用证据工具复用结果     | 沿用现有工具的适用性和失败处理规则；过期、缺失、失败或未完成不被当作当前通过，声明遗漏仍由审查核对                                          |
| A5   | 保存交付记录并在后续复盘     | 本机简短记录能定位目标、版本、检查及审查结论、限制和已有反馈；任务已有 Issue／PR 时也不因此写入远端；缺少时间时仍可交付，但不能计算可靠耗时 |
| A6   | 新版本收到局部验收或缺陷反馈 | 反馈绑定实际版本和范围；局部通过不扩展为整体验收，旧反馈不自动适用于新版本；修复不把历史有效问题改成误报                                    |
| A7   | 正式规格保存或跨会话交接     | 规格可在仓库中定位并查看修订，记录引用它；交接保留未决项和下一步，接收者核对后续修正，不把材料齐备当作新增授权                              |
| A8   | 高风险改动或缩小检查覆盖     | 仍前置核对目标、保留条件和失败场景；检查配置变化对照基线审查，不能靠删检查解释原问题已修复                                                  |
| A9   | 启用专项统计或读取旧材料     | 从实际启用时记录，未知数据保持未知；已有工具和历史记录保持可用，不为流程简化删除或改写历史                                                  |

## 必须保留的行为与范围外事项

- 保留相关非浏览器测试、静态与格式检查、发布前完整测试及纯文档检查范围；检查适用于实际交付内容。
- 保留 Spec 与 Standards 的独立性、现有两阶段目标核对、阻断项处理及受影响内容复查；审查输出随改动范围裁剪，统计可选不降低审查要求。
- 数据迁移、同步、恢复、权限及关键跨模块变更继续前置核对验收条件、错误路径与保留约束；授权和前置依赖仍按原规则判断。
- 本地检查、CI 与人工验收分别报告；浏览器测试分工沿用 [D017](../adr/0017-manual-browser-testing.md)，不在代理本地运行 `pnpm verify`。
- 隐私、只读平台访问、本机数据及同步恢复约束保持；公开规格只保存可分享的规则和必要来源摘要。
- 本次不新增任务状态机、任务命令组、交付发布系统、统计看板或自动报告生成器；不删除现有证据工具、审查工具及其历史材料，不更改 CI。

## 实现与验证安排

实施以流程文档和技能调整为主：共用规则统一定义默认路径、简短记录和工具启用条件；实施、诊断、审查及规格整理入口同步维护；审查材料准备解除对统计目录和编号的依赖。维护手册、工具说明、规则保障映射及流程回归引用同时核对，避免其他入口继续要求每次登记。

原有[任务评估口径](../agents/change-workflow.md#任务评估口径)可用于有依据的复盘，日常不要求填完整评估模板。流程改变按 [ADR 约定](../adr/README.md#如何维护)记录关键决定，保留原理由；本次决定记录在 [D051](../adr/0051-lightweight-development-records.md)，不提升应用版本。

验证沿用[流程回归案例](../agents/workflow-regressions.md)，选取审查后修改、纯文档收尾、上下文恢复、检查覆盖缩小及历史发现处理等受影响场景，并补充 A1、A2、A5 的默认路径和记录可追溯场景。独立执行者使用固定提示和原始材料，裁定者核对实际动作与产物；仅检查关键词或文档链接不能证明流程生效。使用临时目录、临时仓库和合成数据，不接触真实求职工作区。

文档修改运行适用格式与链接检查，并进行同版本独立审查。若实施中确需修改检查器或工具，再运行相应非浏览器回归；不为本规格新增框架或测试工具。实际采用的检查、案例和剩余限制记录在对应交付中。
