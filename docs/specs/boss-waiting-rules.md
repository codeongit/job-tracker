# BOSS 等待观察规则修正与核对体验

## Problem Statement

用户核对历史等待观察时，发现已有资料仍不能处理：招聘方与用人公司名称不同被当作资料矛盾，合法岗位链接被部分采集校验拒绝，人工补建岗位后缺少身份字段的旧观察仍停留在等待。用户难以理解为什么确认了岗位还未解决问题。

同一消息的普通观察与送达回执分别展示，容易被理解为两个岗位或两段聊天。平台职位关闭也缺少独立标识，容易与个人招聘阶段混淆。目标是让处理结果可解释、可人工结束，同时保留来源事实及归属防错。

## Solution

分阶段实施。优先修正招聘方与用人公司的区分、统一岗位链接解析，并提供针对指定普通旧观察的人工资料核对处理。随后改善同一消息的分组展示。平台职位关闭标识单独安排后续规格，当前不扩展正式数据字段。

人工处理展示为人工决定，不伪装成平台补证。用户先核对候选岗位与所选观察，再确认操作；未确认的观察继续等待。简历业务含义和现有归属关卡保持。

## User Stories

1. As a 求职跟踪用户, I want to 区分招聘方和用人公司, so that 猎头岗位不会仅因公司名称不同而被错误拦截。
2. As a 求职跟踪用户, I want to 查看双方公司名称及差异原因, so that 我能判断差异是否属于真实矛盾。
3. As a 求职跟踪用户, I want to 明确确认某个岗位的招聘方与用人公司对应关系, so that 人工核对只作用于指定岗位。
4. As a 求职跟踪用户, I want to 未确认的公司差异继续受到拦截, so that 不会把所有同名或猎头岗位自动关联。
5. As a 求职跟踪用户, I want to 合法岗位 ID 中的波浪号被正确处理, so that 已能打开的岗位链接不会被程序拒绝。
6. As a 求职跟踪用户, I want to 保存不含临时访问参数的岗位链接, so that 访问凭据不会进入正式记录或公开诊断。
7. As a 求职跟踪用户, I want to 同一岗位在采集、入队、应用和恢复中使用相同链接规则, so that 不会出现手动能保存但自动处理失败的情况。
8. As a 求职跟踪用户, I want to 继续拒绝其他域名及畸形岗位链接, so that 链接兼容修正不会扩大平台访问范围。
9. As a 求职跟踪用户, I want to 核对指定旧普通观察与候选岗位后结束其资料等待, so that 已人工补齐的资料无需无限补录。
10. As a 求职跟踪用户, I want to 保存前看到所选观察、目标岗位和处理范围, so that 不会误处理其他聊天。
11. As a 求职跟踪用户, I want to 人工核对结果与平台归属验证分开展示, so that 我不会把人工决定误认为平台提供了身份字段。
12. As a 求职跟踪用户, I want to 普通观察的人工处理不改变简历状态, so that 简历联动仍受现有归属检查保护。
13. As a 求职跟踪用户, I want to 已忽略或否决的观察保持原决定, so that 补证和重放不会恢复自动应用。
14. As a 求职跟踪用户, I want to 版本变化或目标删除时重新核对, so that 确认操作不会使用过期目标。
15. As a 求职跟踪用户, I want to 同一消息的普通观察与回执分组展示, so that 我能看出它们来自一条消息。
16. As a 求职跟踪用户, I want to 分组内仍能看到每项观察的类型、原因和结果, so that 分组不会掩盖不同处理状态。
17. As a 求职跟踪用户, I want to 数量明确区分消息组与来源观察, so that 不会把两项观察理解成两个岗位。
18. As a 求职跟踪用户, I want to 分组中的忽略操作列出实际选择的观察, so that 我不会意外忽略整个会话的新消息。
19. As a 求职跟踪用户, I want to 打开岗位详情后返回原核对位置并保留有效选择, so that 核对过程无需反复查找。
20. As a 求职跟踪用户, I want to 人工处理在备份、同步和恢复中保留, so that 换设备或重放时仍能解释处理结果。
21. As a 求职跟踪用户, I want to 写入失败时整次操作不生效, so that 不会出现部分观察处理成功的情况。
22. As a 求职跟踪用户, I want to 后续单独看到平台职位关闭情况, so that 我能区分平台可用性与自己的跟进进度。
23. As a 求职跟踪用户, I want to 无法取得标题不被自动判定为职位关闭, so that 网络或采集失败不会改变业务判断。

## Implementation Decisions

- 优先阶段范围为公司语义、链接兼容和普通旧观察人工处理；观察分组为随后阶段，关闭标识仅记录后续边界。此规格不是对全部方案已经上线的声明。
- 公司差异不再只有字符串相等这一种解释。招聘方、用人公司及其对应关系必须有明确来源；平台材料缺失时，由用户核对指定账号、观察和岗位后确认。不得根据“猎头”关键词、同名公司或唯一候选自动认定关系。
- 有稳定岗位 ID 和链接时，二者必须一致；公司角色差异须明确确认，其他岗位、账号、链接或参与者矛盾仍拦截。普通资料可按确认的公司角色关系处理，但该关系不证明简历观察归属。
- 提供唯一共用的岗位链接解析与身份校验规则，支持已经遇到的合法 `~` 字符。保留固定 HTTPS 平台主机、岗位详情路径、长度和身份一致性约束；用户输入中的查询参数和片段不作为岗位身份并在保存前去除。旧不可变材料不原地改写。
- 人工处理复用来源应用账本：仅对当前有效、具备稳定事实身份的普通等待或资料核对观察，记录人工完成核对的无自动业务效果结果及固定原因；原始事件和事实 ID 不变，不补写平台身份，不自动推进招聘阶段、沟通状态或简历状态。
- 无岗位身份的普通观察允许由用户明确指定现有有效岗位作为人工核对目标，展示该决定为人工目标，不能冒充自动验证的来源绑定。未知归属、跨岗位消息冲突及明确身份不一致不能通过此资料处理命令消除；这些仍需原有核对或忽略流程。
- 人工处理与人工忽略不同：前者记录用户已完成资料核对，后者持续禁止同一事实自动应用。二者均保留审计；本轮人工完成的普通观察在补证、重复消费和恢复重放时保持人工结果，新消息独立判断，原始观察继续参与跨岗位检查。
- 新人工操作使用版本化固定服务命令、预期工作区版本与持久幂等键；提交具体来源应用及目标岗位列表。提交前重新校验资格、账号、删除标记及相关同步冲突，批量全部成功或全部失败；精确重试返回原结果，版本冲突要求重新核对。
- 源事实、人工结果及其目标关系必须纳入正式校验、备份、同步和恢复。优先使用既有来源应用结构；若现有字段无法无歧义表达人工目标或持久决定，实施时先完成显式数据版本迁移设计，迁移数据、基线和待处理冲突，不能偷偷扩展 v3 白名单或使用临时私有缓存替代正式决定。
- 观察展示按账号、会话、稳定消息身份分组；不合并底层事实或应用，不改变历史事件 ID。不具有稳定身份的观察保持独立，不用正文、公司名称或时间猜测归组。
- 分组保留逐项选择，默认不勾选；确认清单展示实际来源应用及数量。现有观察总数保持观察语义，可另列消息组数；等待、冲突、人工保护、已忽略和人工完成分开说明。
- 保留 D034 跨观察防错、D035 会话关联前提、D036 持续忽略和 D037 精确资料复用。人工编辑岗位仍不自动确认或忽略旧观察。“附件简历请求已发送”的既定含义保持。
- 实施关键规则时新增下一编号 ADR，明确对既有决定的调整并保留旧 ADR；应用版本、规则版本及兼容说明根据最终实现更新，不在规格阶段预先宣布升级。

## Testing Decisions

- 用户已确认沿用现有测试入口。主要从工作区服务命令与批次消费入口断言正式岗位、来源应用结果及恢复行为；链接采用既有采集转换测试，展示采用既有渲染测试。
- 好的测试只检查外部可见结果及安全边界，不绑定内部函数调用顺序、不复制实现。使用合成账号、消息和岗位、临时磁盘目录，不读取真实工作区或访问招聘平台。
- 公司场景覆盖角色差异经人工确认、未确认差异、真正矛盾、同公司不同岗位、跨账号、多个目标、已删除目标和人工字段保护。断言公司角色确认不能绕过简历归属。
- 链接场景覆盖合法波浪号、旧字符格式、查询和片段移除、错误域名/协议/路径、超长 ID、链接与岗位 ID 不一致，以及同一观察在正常消费、旧队列与恢复入口结果一致。
- 人工处理场景覆盖缺标题、缺岗位身份、无稳定事实身份、简历观察拒绝、明确冲突拒绝、同步冲突、版本变化、精确重试、批量保存失败及目标删除；断言无部分修改、无原始证据改写、无岗位状态联动。
- 延续现有持久忽略及恢复测试模式，覆盖人工结果的重复消费、新材料、旧队列、旧备份恢复、同步往返和回执缺口；旧备份缺少决定时按既有恢复语义处理，磁盘回执不替代当前事实检查。
- 渲染覆盖同消息多个事实、不同账号相同消息 ID、不同会话、缺稳定身份、组内不同状态、准确计数、逐项确认清单、HTML 转义及不泄露正文/凭据。详情返回与选择保留由现有非浏览器测试能覆盖的部分验证，真实交互交给用户。
- 每阶段运行相关非浏览器测试；交付前运行完整 `pnpm test`、`pnpm check`、`pnpm format:check`。不运行包含浏览器测试的本地验证命令，真实浏览器验收保持待用户确认。

## Out of Scope

- 本规格发布不执行代码实现、真实岗位批量修改、自动忽略或额外补录。
- 不恢复身份字段排查、不安排临时采样、不新增平台请求、长期跟踪、自动同步或服务启动授权。
- 不放宽简历含义、账号隔离、联系人/参与者检查、跨岗位拦截、人工保护、否决、删除或恢复缺口检查。
- 不建立通用公司别名库、不用公司名称或唯一候选批量匹配岗位，不重写存储架构。
- 本轮不实现平台职位关闭字段、控件或迁移。后续单独明确未知/开放/关闭的表达、依据和时间、人工维护与兼容方案；不能把详情失败等同于关闭，不能自动结束跟进、删除记录或忽略观察。
- 不发布真实岗位、公司、联系人、消息 ID、聊天内容、私有诊断或带访问凭据的链接。
