# 岗位详情异常的人工处理

## 问题与目标

详情采集失败并技术隔离后，网页目前只显示汇总错误。用户无法直接找到失败岗位、核对原链接、补齐本机资料或明确结束该岗位的详情采集待办。本次补充逐岗位人工处理入口，区分本机采集任务已人工处理、平台详情取得和正式岗位资料保存三个结果。

## 来源与决定状态

- 来源：用户在 [PR #15](https://github.com/codeongit/job-tracker/pull/15) 对应排障中询问异常的人工路径，随后通过 `ask-matt` 明确同意继续完善“查看失败岗位、人工核对、补齐资料或单次重试或停止详情采集、保留处理记录”。
- 用户于 2026-11-05 明确选择：停止详情采集是仅本机任务决定，重启保留，不随求职数据同步。岗位资料仍采用现有保存、备份和同步规则。
- 本轮实施基线：`ce5d173eb2389d14e7854db71e5b7b1881d9e6db`。既有资料确认与忽略边界见 [D042](../adr/0042-data-sync-guided-resolution.md)，定点重试边界见 [D060](../adr/0060-explicit-isolated-detail-retry.md)。
- 本文为本次实施规格；独立目标核对已完成，设计核对和最终实现验收结果随 PR 记录。实现状态不能由本文件存在推定。

## 目标行为与验收条件

### 查看与补齐

1. 本机设置页按岗位列出当前详情失败：可辨识的已有资料、原岗位链接、失败原因和最后尝试时间。链接来自当前已观察且校验的岗位身份，不根据公司名称或错误页面猜测。
2. 查看清单、编辑资料及保存人工决定均不访问招聘平台。用户主动打开原链接属于人工查看，不被记录为自动采集成功。
3. 有唯一精确匹配的现存岗位时，直接进入既有岗位编辑；没有时进入已有新增岗位入口并保留可核对链接。多个候选、删除记录或身份矛盾不得自动合并或复活。
4. 补齐资料仍经过原有正式工作区命令。保存后普通观察按已有规则重新判断，简历、归属、同步冲突及人工字段保护保持。
5. “资料已补齐，停止详情采集”必须再核对当前唯一精确且完整的现存岗位，以及用户审阅的工作区版本。业务资料保存和停止采集分别反馈；其中一步失败不能显示两步都完成。

### 人工结束与撤销

1. 用户也可明确选择“无需继续采集详情”，不要求已经建立正式岗位。该决定仅针对当前绑定账号下的所选岗位。
2. 决定持久保存在本机采集控制状态，记录处理原因、时间及对应身份。原失败次数、错误和诊断保留，不能改成成功平台证据。
3. 决定保存后，该岗位移入“人工处理记录”，从当前详情采集待办中移出。普通采集与显式重试均不能绕过该决定；新消息不自动撤销决定。
4. 可以从处理记录撤销，重新显示仍适用的原技术故障。撤销不清空失败次数、不发起重试、不恢复账号跟踪。
5. 仅在跟踪已停止且无在途平台轮次时保存或撤销。页面明确说明当前状态及停止入口，不把查看清单当成停止或平台授权。
6. 人工处理完成只针对详情采集任务，不关闭职位、不结束跟进、不忽略来源观察、不停止其他消息采集。工作区恢复撤回岗位资料时，业务缺项继续独立显示；本机停止决定不被工作区恢复清除。
7. 本机决定不在求职数据 JSON、工作区业务备份或 GitHub 同步中传播。恢复或复制整个本机采集控制目录与业务工作区恢复是不同操作。

### 单次重试与失败反馈

1. 未人工停止且符合 D060 的隔离任务可从页面明确触发一次定点重试；保留停止状态、精确目标、统一预算和停批规则。需要先撤销人工停止决定时明确提示。
2. 进行中不允许重复触发。响应丢失显示结果尚未确认，通过本机状态与实际尝试记录核对，不自动重发平台请求。
3. 本机人工命令包含版本、预期决定 revision、任务版本及持久幂等键。重复同请求返回已保存结果；同键不同内容拒绝；状态或任务变化要求重新核对。
4. 失败保存不消除提示；原子替换后的附属失败须通过同请求回查已持久状态，不把已完成操作当成可盲目重做。

## 实现与验证安排

人工决定归统一控制器所有，采用严格版本化本机状态；旧格式迁移保留原件，旧服务拒绝新格式，未知字段或未来版本拒绝写入。控制器向既有单次票据及采集链传递精确的停止集合，详情选择与数量计算共用同一排除规则。集合及持久记录有明确大小上限，超限拒绝提交，不截断或丢弃决定。

完整 tracking 文件最终序列化 UTF-8 上限为 5 MiB，完整单次票据为 80 KiB，读写采用相同边界且所有写入前预检。排除集合单独限 1000 个唯一岗位 ID、完整策略 JSON 64,000 字节；它不替代整个文件的容量检查。持久回执不淘汰，达到容量时保留旧状态并拒绝新修改。

原子替换后附属步骤失败时，回读候选并重新完成权限和目录持久化屏障，全部确认才返回成功。无法确认或屏障仍失败则进入写入故障状态，阻止后续生命周期及状态写入，避免旧内存覆盖已落盘决定；重启后重新校验。对应容量边界和故障注入为实施前独立审查 MD-01、MD-02 的验收条件。

逐岗位状态从当前采集快照、技术任务、本机决定及正式工作区投影，不依赖旧汇总推断完成。状态读取与耗时的本机批次消费分开。业务资料仍复用既有编辑与普通资料确认，不新建来源事实或改写原观察。

非浏览器验证覆盖：

- 网页客户端至真实服务处理器、控制器和临时持久存储的保存、撤销、冲突与幂等；断言人工动作没有平台读取。
- 控制器至单次票据、integration、tracker 和详情选择的连接，证明普通轮次及定点重试都遵守同一账号的停止决定，其他账号和岗位不受影响。
- 重启、旧格式迁移、未知字段与未来版本拒写、保存失败和响应未知；原失败历史和额度不丢失。
- 本机资料补齐、无目标、重复或删除目标、工作区恢复撤回资料后仍显示业务缺项；人工完成不冒充平台成功。
- 页面渲染、交互协调与状态刷新；实际浏览器由人工验收，不启动代理浏览器测试。

## 范围与交接

沿用本轮实施授权，设计通过后可进入实现，无需再确认已明确事项。本轮不重新访问真实招聘平台、不替用户为既有任务作人工停止决定，也不合并或发布版本。最终交付包含适用检查、同版本 Spec 与 Standards 审查、PR 和简短人工界面验收步骤。
