# D027：采集器源码与工作台同仓、私有状态分离

- **记录日期 / 状态：** 2026-09-23 / 有效。
- **来源：** 用户确认继续迁移，并追问独立采集器是否尚未完全融入跟踪仓库。
- **问题：** 主服务虽已统一调度，但仍通过私有配置中的外部绝对路径执行采集器；源码、测试和工作台版本可能分叉，源码目录也混有私有快照及浏览器状态。
- **决定：** 采集器保持独立进程和故障边界，但源码、纯测试及规约迁入本仓库 `collector/boss/`，由主项目统一版本、测试和发布。执行路径由服务内部固定，网页及私有配置不能选择任意脚本。快照、连接、检查点、岗位导出和专用 Chrome profile 统一保存在忽略的 `.local/boss-collector/`。
- **原因：** 同仓可避免接口与采集实现分叉，并让一次提交完整表达采集、转换和正式录入规则；源码与私有状态分离后，公开仓库仍不包含真实求职资料。
- **备选与取舍：** 独立仓库有单独发布边界，但当前只有一个工作台消费者，会增加跨仓版本和部署协调；把采集器并入服务同进程更简单，但会扩大浏览器故障对正式存储单写者的影响，因此继续保持进程隔离。
- **约束：** 迁移不改变平台只读、显式开始、动作预算、人工真实浏览器验收或手动 GitHub 同步。旧外部目录先保留为回退副本；真实样本不得进入公开测试，使用等价合成数据覆盖迁移规则。
- **重新评估条件：** 采集器出现多个独立消费者、需要独立发布周期，或进程间协议成为明显性能/维护瓶颈。
- **替代关系：** 细化 D026 的“独立进程、同一业务协议”，不改变其运行、存储和安全语义。
