# D052：由主协调者承接多工单审查与提交

- **记录日期 / 状态：** 2026-10-27 / 已确认；适用于本地多工单协调，实际验证范围随交付记录保存。
- **来源：** 用户反馈上一轮研发流程改造耗时偏长，认可仅调整职责分配并回复“可以”：实施者交出可审阅候选后释放槽位，主协调者统一安排独立审查、修复和提交；验证限于候选交接与审查调度。
- **问题：** 原 `implement-spec` 要求每个实施者完成实现、检查、独立审查和提交，实施者等待自己分派的审查者时仍占用执行容量，增加嵌套调度。已有记录能证明等待和补查发生，但不能拆算各步骤耗时或承诺节省比例。
- **决定：** 多工单实施者按 `implement` 的目标核对、实现与检查步骤产出完整候选及版本依据，结束本次执行并保留工作树。主协调者直接分派独立审查，安排修复及复查，在条件满足后组织提交和串行合并。具体职责以 [implement-spec](../../.agents/skills/implement-spec/SKILL.md) 为准。
- **保留条件：** 候选交接不表示工单完成或依赖解除；仍须完成必要检查、Spec 两阶段、独立 Standards、阻断项修正和同版本复查。高风险验收核对由主协调者在实现前安排。后续工单仅使用已合入且有效的前置结果，单工单继续使用完整 `implement` 流程。
- **替代关系：** 替代提交 `b8e72fafa5794a34eabebaaf7fb28c09222ad48d` 中 `implement-spec` 将逐票独立审查与提交全部交给实施者的安排；原安排由 Git 历史保留。沿用 [D051](0051-lightweight-development-records.md) 的本地简短记录与按需工具决定，不降低其检查和追溯要求。
- **范围与取舍：** 调整执行责任与槽位使用，不新增任务状态机或工具，不改变产品、CI、外部发布授权和应用版本。验证集中在候选交接、主协调者分派审查及完成边界，其他已有效的验证沿用；实际耗时改善留待后续可比任务观察。
- **重新评估条件：** 候选频繁缺少版本或检查依据、协调者成为明显瓶颈，或独立审查与依赖门槛被绕过时，针对实际缺口调整交接职责。
