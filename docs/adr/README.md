# 架构决策索引

本目录保存全项目的编号 ADR；每项决定独立保存，编号保持稳定。下面是唯一决策索引，保留原有状态与来源；状态中的实施或验收记录不等于所有真实场景已经验收。

当前 BOSS 行为见[设计说明](../boss/DESIGN.md)，代码与技术契约见[实现说明](../boss/IMPLEMENTATION.md)，使用及排障见[操作说明](../boss/OPERATIONS.md)。共享系统职责、正式数据和开发发布分别见[架构](../ARCHITECTURE.md)、[数据与恢复](../DATA_AND_RECOVERY.md)、[维护手册](../MAINTENANCE.md)。版本变化见[CHANGELOG](../../CHANGELOG.md)。

## 如何维护

- 改动前按主题读取相关 ADR，核对决定来源、取舍、替代关系及重新评估条件。当前说明直接描述生效行为，ADR 保留决定发生时的理由。
- 新的关键决定使用现有编号最大值加一，在本目录新建同编号文件，并在下表登记一次；文件一级标题、编号和索引链接保持一致。
- 改变关键决定时新增 ADR，写明来源及替代关系，保留旧理由和历史状态；日常修复、内部重构及文档整理通常无需新增 ADR。
- 新用户明确要求优先于旧决定。正文、代码和测试在同次变更中核对；未来方案明确标为待实施，真实验收未确认时保留待验收状态。
- 文档影响按[变更共用规则](../agents/change-workflow.md)说明。公开文档只使用规则、合成样例及必要历史信息，不记录真实求职经历、简历或凭据。

## 新决策模板

编号占位 `DNNN` 和文件名 `NNNN-topic.md` 在新建时替换，编号从现有文件计算，不在模板中固定下一编号。

```markdown
# DNNN：一句话说明决定

- **记录日期 / 状态：** YYYY-MM-DD / 待定或有效；实施与验收状态单独说明。
- **来源：** 用户明确要求、实现选择，或所替代的决策编号。
- **问题：** 需要解决什么实际问题？
- **决定：** 采用什么方案，适用范围是什么？
- **原因：** 哪些需求和证据支持这个选择？
- **备选与取舍：** 其他可行方案及其代价；区分实际讨论与事后比较。
- **约束：** 需要保留的边界、兼容性和已接受的限制。
- **重新评估条件：** 什么变化会使这个决定不再合适？
- **替代关系：** 如有，关联旧编号并更新索引中的替代状态，保留旧理由。
```
