# D047：按明确系统结构识别简历发送与查看确认

- **日期 / 状态：** 2026-10-09 / 已实现；真实采集与界面待用户验收。
- **来源：** 用户指出真实简历发送未统计，授权只读核对指定会话，随后要求总结原因、改进并修正数据。已加载消息缓存与平台公共转换代码确认发送文字来自 `body.hyperLink.text`，查看文字来自 `body.text`；本次未取得完整原始历史接口响应，不把合成回归当作真实采集验收。
- **原因与决定：** 原提取器未读取链接消息的发送确认，并将外层类型 4 一律排除，连明确的查看系统消息也被存成普通卡片。新增两种严格的结构与精确文案组合：发送为 `type=3 / bizType=13 / body.type=12 / body.templateId=1 / body.hyperLink.hyperLinkType=6`，仅匹配既有附件发送文案；查看为 `type=4 / body.type=1 / body.templateId=3`，`bizType` 与链接类型缺省，精确匹配既有查看文案。普通聊天、引用文字与通用卡片不证明发送或接收；“附件简历请求已发送”的既定含义保持。
- **交付与消费：** 新语义依据 v2 保留外层类型、固定字段路径、脱敏状态文字及最小判别字段；附件名称使用固定占位。所有有业务目标的简历观察都在消费时重验语义，语义与归属必须来自同一观察，生产者标签不能代替证据。旧 v1 合法语义保留，旧 v1/type4 仍不足，`field=none` 仍只是观察。快照与交付批次显式升至 v6、历史检查点升至 v4；兼容旧读取，旧容器不得装入 v2 依据，未来版本与未知字段继续拒绝。
- **历史和数据修正：** 不批量提升旧卡片、不改写原观察与稳定 ID，不自动重开已存档的 `no_effect`。新明确发送或查看确认按独立事实处理，继续核对账号、会话、岗位、跨岗位异常及人工字段。用户授权的定点状态修正通过现有 `edit_data`、预期 revision、持久 commandId 和私有前后备份完成，保留人工所有权；不为人工修正补造平台确认事实。已应用历史、人工否决、忽略、删除、同步冲突及恢复缺口保护保持。
- **替代与运行：** 部分调整 [D044](0044-boss-card-semantics-evidence.md) 将全部类型 4 视为卡片的实现边界，补足其消费语义核对；保留 [D043](0043-boss-observation-only-archive.md) 的纯卡片存档和 [D019](0019-boss-resume-status-link.md) 的发送/接收联动。应用 0.10.18、规则 v13；共享数据 v4、工作区 v3、备份 v2、服务协议 v1 不变。升级服务后跟踪保持停止，用户显式开始后才继续平台读取，不自动同步 GitHub。
