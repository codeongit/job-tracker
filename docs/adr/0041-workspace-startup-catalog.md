# D041：以提交索引缩短工作区启动并按需校验旧历史

- **日期 / 状态：** 2026-10-06 / 已实施，完整非浏览器检查、首次转换和普通冷启动已核对；真实界面待人工验收。
- **来源：** 用户要求重新设计长时间启动，确认正常启动只严格校验当前状态与持久命令索引，旧历史按需严格校验并提供显式完整审计；明确接受未访问旧历史异常的发现时机延后。
- **问题：** 每次启动逐条读取完整 JSON 历史、计算摘要、迁移校验工作区并重建幂等索引，成本随累计完整快照增长。D040 减少重复纯计算后，整个历史仍在就绪前反复处理。
- **决定：** 保留不可变完整提交和单服务写者，新增不可变 catalog。正常启动严格验证最新提交的摘要、工作区及全部冲突侧，并验证 HEAD 绑定的完整 catalog；旧命令重放和结果查询重新完整校验对应提交及工作区，显式 `auditHistory` 完整检查历史链条与各提交格式。启动不自动执行完整历史审计，首次读取旧 HEAD v1 时完整审计历史后建立 catalog 并原子发布 HEAD v2。
- **索引含义：** catalog 仅保存 commandId、请求摘要、revision、提交文件与摘要，不保存业务快照或命令结果。它必须完整覆盖 1 到 HEAD revision，每个 revision 恰好一条，commandId 唯一，工作区身份、末条提交及 HEAD 指针一致。每次启动校验 catalog 自身格式和摘要；索引失效、缺失、未知字段或未来版本停止写入，不能返回空索引或将旧命令误判为新命令。它的完整性来自首次完整审计和后续受信单写者的原子追加，不代表每次启动重新验证了旧档案。
- **事务：** 完整候选提交和 catalog 各自独占写入、文件 fsync、所在目录 fsync 后，原子替换同时包含两者指针的唯一 HEAD，再 fsync 工作区目录。HEAD 发布前失败只留下未确认候选；发布后响应丢失可按原命令核对。HEAD 目录同步报错时核对包含 catalog 的完整根，只重试持久化屏障；持续失败隔离写者，不确认业务保存或队列回执。私有目录 0700、文件 0600，拒绝符号链接和任意路径。
- **历史异常：** 当前提交、catalog 和本次输入中的损坏、未知字段或未来格式继续立即拒写；未读取旧档案的缺失、篡改或未知格式可能到按需读取或完整审计才发现。这是发现时机的明确调整。按需读取必须重新校验原提交，不能只返回索引中的成功结果；发现历史异常隔离写者并保留故障材料，不能重新执行业务命令、跳过坏历史或盲目重建空索引。SHA 与 HEAD 提供受信单写者模型下的完整性，不承诺防止同一用户重写整套文件或完整磁盘回滚。
- **恢复与备份：** 业务备份恢复仍是追加新编辑，当前同步基线、删除标记、冲突双方和旧 commandId 保留；catalog 或队列回执不能证明恢复后的当前数据仍含来源事实。复制完整磁盘工作区需一并保留 HEAD 指定 catalog；索引损坏需保留原件，明确安排完整审计和修复，不从当前快照推测历史，也不自动重建。原始历史、迁移原件、队列和检查点不删除。派生 catalog 保留当前及必要的上一版本，清理失败不改变已持久化提交的成功结果。
- **生命周期：** 服务启动状态显示 starting、ready、failed 及阶段时间，重复 start 复用现有启动实例，不再派生第二个进程。启动、重启、索引转换、按需读取及显式完整审计只处理本机材料，不访问 BOSS，不恢复跟踪，不触发云端同步；平台访问仍需用户明确开始跟踪。
- **兼容：** 应用 0.10.3、BOSS 规则 v10、共享数据 v4、工作区 v3、完整备份 v2。本机 HEAD 格式升为 v2、catalog 为 v1，历史提交和 identity 保持 v1；服务命令协议保持 v1，本机客户端接受 storageVersion 2。服务运行记录为 v2，兼容读取 v1，独占启动意图为 v1。旧代码遇到新 HEAD 格式停止写入，不能为原地回退去掉 catalog 或手改 HEAD。
- **备选与取舍：** 每次启动仍扫描全部历史 hash、仅延后旧工作区迁移的改动较小，但完整读取和摘要仍随快照体积增长；继续完整启动审计保留原发现时机但无法消除累计成本。采用整份小型 catalog 避免引入数据库、分段日志或签名平台；它的读取和每次更新成本仍随命令数量增长，首次旧盘转换仍可能较慢，不承诺固定启动时限。
- **替代关系：** 调整 [D026](0026-local-authoritative-workspace.md) 中损坏历史链在启动时拒写的发现范围，以及 [D040](0040-boss-repeated-work-and-stable-reevaluation.md) 中每次启动完整验证历史、不引入持久索引的约束；两份原 ADR 保留。D026 的单写者、CAS、幂等、完整提交和恢复规则，D040 的纯计算复用与稳定同事实重评继续有效。[D007](0007-versioned-data-migrations.md) 对当前状态、输入候选及实际读取历史的完整迁移和未知格式拒写规则保持。
- **验收：** 合成测试覆盖 catalog 与 HEAD 绑定、完整覆盖和重复命令、首次旧盘转换、未知格式、历史按需损坏、完整审计、各写入及目录 fsync 中断、丢响应、恢复缺口和清理失败。完整 `pnpm test` 602/602、`pnpm check`、`pnpm format:check` 通过。首次旧 HEAD v1 完整审计并发布 HEAD v2 与 catalog 已实际核对，正式 revision 和完整工作区摘要与升级前相同；转换后的本地重复消费未产生新提交，未发现故障或恢复缺口。随后普通冷进程启动及 starting 期间重复 start 复用同一实例已实际核对，storageVersion 2、协议 v1，BOSS 跟踪保持停止。真实界面仍待人工确认；实际测量不作为普遍启动时限承诺，普通启动成本仍随当前工作区和 catalog 命令数量增长。
- **重新评估条件：** catalog 的体积或更新成本不可接受、需要历史自动裁剪、多写者、远程服务、防恶意改写或磁盘回滚保证时，另做存储与信任模型决定。
