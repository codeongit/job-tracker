# D024：BOSS 日期标签的用户确认补录规则

> 2026-09-21：用户给定日期与不覆盖已有字段的规则继续有效；下述每日详情批次预算已由 [D026](0026-local-authoritative-workspace.md) 的实际动作预算替代。

- **记录日期 / 状态：** 2026-09-21 / 有效。
- **来源：** 用户要求把最新已保存快照中时间标签为“昨天”的数据导入，并明确日期为 2026-09-20。
- **问题：** 常规增量批次已保存这些观察，但因没有可靠首次联系日期、且多数记录缺正式岗位名称，不能直接把日期或占位名称写入正式岗位。
- **决定：** 增加 `enqueue-yesterday --date YYYY-MM-DD`，以确定性策略 ID 筛选当前检查点的原始“昨天”标签。用户给定日期只用于该批新建岗位的 `appliedAt`，阶段为“已触达”；已有岗位的日期、阶段和人工字段不覆盖。允许在聊天观察未变化时复用之后完成的详情补齐，批次和检查点保持幂等推进。
- **约束：** 岗位名必须来自实际 `jobName` 或完整详情标题；缺名称、缺岗位 ID、公司冲突或身份歧义继续待核对。详情补齐仍受每天一批、每批最多 3 个、导航至少 60 秒限制，且平台全程只读。
- **原因：** 既保存用户确认的日期事实，又不把相对标签、招聘人职务或旧岗位日期错误扩散到其他记录。
- **重新评估条件：** 平台提供稳定绝对时间、详情补齐预算改变，或用户明确要求修改已有岗位的人工日期。
- **替代关系：** 补充 D023 的后续日期规则，不替代 D009 的不推断缺失事实或 D023 的人工字段保护。
