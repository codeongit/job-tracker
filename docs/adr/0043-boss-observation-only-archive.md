# D043：纯简历卡片观察只存档

- **日期 / 状态：** 2026-10-08 / 已实现；真实界面验收待用户确认。
- **来源：** 用户明确批准纯简历卡片观察只保存来源记录，不计为待处理；真实发送、接收及明确归属冲突继续执行原有关卡。
- **问题与取舍：** 普通简历卡片没有可改变岗位的业务含义，归属材料不足时仍列为 waiting 会制造与岗位状态更新无关的处理负担。选择保存事实和应用结果、结束这类等待，保留可核对的原始材料；不把存档结果解释为发送、接收或归属确认。
- **唯一范围：** 以 `dist/resume-rules.js` 的共享规则为准，仅 `target === null` 的 `sent_candidate` 和 `resume_card_other` 属于本次纯存档观察。未知类型继续拒绝，不能依据名称、摘要或卡片方向扩大范围。
- **应用决定：** 对具有稳定消息身份且通过既有准入的纯存档观察，统一归属判断为 `insufficient` 或 `verified` 时记录 `no_effect / observation_only`，正式目标保持为空，不建立岗位关联，不修改岗位、沟通记录、简历状态或联动字段。`insufficient` 仍表示归属材料不足，存档不能将它提升为已验证。
- **冲突与采集问题：** 归属判断为 `conflict` 时继续 `review` 并保留原原因，不用纯存档掩盖明确矛盾。缺稳定消息身份仍属于采集问题，不创建来源事实或应用，也不通过本决定消除问题。
- **历史与重评：** 来源事件、事实、观察候选及稳定 ID 保留。现有 waiting 或证据不足项由既有纯本机消费按新规则重评，符合范围的项不再计入待处理；相同材料和业务结果不产生重复提交。不撤销已应用历史，也不覆盖人工字段保护、否决或忽略决定。
- **保护与恢复：** 账号隔离、删除标记、同步冲突、恢复缺口和回执事实存在性检查继续生效；存档不是绕过这些关卡的入口。恢复缺失事实仍需按当前 revision 明确核对重放，磁盘回执不能证明当前工作区中事实存在。
- **真实简历状态：** 具有非空业务目标的发送、接收观察继续执行 D030/D031/D034/D035 的归属、唯一有效岗位关联、跨观察检查及人工字段所有权规则；本决定不放宽状态联动。
- **运行与兼容：** 应用 0.10.12、BOSS 应用规则 v11；共享数据 v4、工作区 v3、完整备份 v2、服务协议及各私有格式不变，无数据迁移。重评不新增平台采集、CLI 或写命令，不启动持续跟踪；服务重启仍不恢复 BOSS 授权，不自动同步 GitHub。
- **替代关系：** 部分调整 [D033](0033-boss-import-convergence.md) 将纯存档且归属不足观察也列为 waiting 的边界；保留其统一归属判断、明确冲突及正式应用前检查。[D031](0031-explicit-resume-semantics.md) 的唯一语义定义、[D036](0036-boss-waiting-observation-ignore.md) 的人工忽略和 [D040](0040-boss-repeated-work-and-stable-reevaluation.md) 的稳定重评继续有效。
- **验收与重新评估：** 完整非浏览器测试 700/700、`pnpm check`、`pnpm format:check` 通过；真实界面由用户验收。应核对两类纯卡片在不足或已验证材料下只存档、正式目标为空且不计待处理，明确冲突仍可见，缺消息身份仍显示采集问题，实际发送接收及人工决定不变。新增纯存档类别、改变业务含义或要求终结归属冲突时须重新确认范围。
