# D060：显式定点补查已隔离的岗位详情

- **记录日期 / 状态：** 2026-11-05 / 已决定；实现及真实补查结果随 PR 记录。
- **来源：** 用户在详情故障修复后指出“部分岗位详情未取得”仍存在，询问重试是否能解决，并同意对两个已隔离岗位做一次受控补查、失败不反复重试。
- **问题：** 四次失败后的技术隔离会持续阻止普通采集选择该岗位。修复代码或解除详情所有权阻断不代表已经取得资料，也不能清空失败历史来恢复自动循环。
- **决定：** 增加显式 `retry-details` 命令，指定唯一岗位 ID 集合，只允许在跟踪停止且无在途轮次时补查。每次请求最多 20 项，必须仍为当前合格且已隔离的详情任务。统一预算须足够覆盖整组，票据精确绑定目标；不读新列表、历史消息或执行 DOM 切换。失败继续隔离，停批错误保留后续未执行目标，不自动重发。
- **保存与诊断：** 平台读取前保存原隔离摘要；关闭自有任务标签前保存仅含身份哈希、固定状态及布尔结果的诊断。成功资料先保存，再确认对应失败任务结束；普通公平游标不变。全失败也保存本轮快照及详情级结果，已发动作仍计额度。诊断或保存失败时保留已取得资料，停止确认运行进度及本次交付；后续只恢复已有材料，不用再次访问平台替代恢复。
- **取舍：** 通过明确命令给予一次选择例外，不提供清空失败计数或永久恢复自动重试的开关。复用统一控制、锁、票据、采集及交付链路；命令返回丢失先回查记录，不自动重发。
- **约束：** 保留账号、任务页、网址、所有权、暂停及预算保护；全局详情阻断不被绕过。服务重启及补查完成均不恢复持续跟踪。命令能力本身不是访问平台的授权，本次两项目标的授权不扩展到其他岗位或后续批次。
- **替代关系：** 补充 [D026](0026-local-authoritative-workspace.md) 的详情隔离恢复方式；原普通采集退避、隔离及显式跟踪原则保持。
- **重新评估条件：** 需要自动解除隔离、批量扩大目标、持续重复补查或新增平台读取字段时，重新核对范围与授权。
