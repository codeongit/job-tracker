# D018：精简消息与招聘状态，岗位只保留分页列表

- **记录日期 / 状态：** 2026-09-14 / 有效。
- **来源：** 用户要求消息状态去掉“未知”、默认未读，认为“待联系”没有作用且公司多时看板不便使用，并确认旧“待联系”归到“已触达”、删除看板。
- **问题：** 低频状态增加选择负担，看板在岗位较多时不利于连续查找和处理。
- **决定：** 消息状态只提供“未读、已读”，新增岗位默认未读；招聘阶段保留“已触达、沟通中、面试中、Offer、已结束”。岗位只使用每页 10 个结果的列表，保留关键词、当前阶段及日期的交集筛选，以及共用详情和上下文保留规则。
- **兼容：** `getOpportunityStatus` 将旧“待联系”按“已触达”使用，消息状态保留“已读”，其余按“未读”使用；展示、查询、Markdown 导出和恢复编辑草稿使用相同映射。新 Markdown 导入缺省未读，保留原始状态文字。旧数据继续通过校验；不批量改写 `data`、同步 `base`/`pending` 或草稿 `original`，只有明确保存岗位才写入当前状态。仅做兼容归并时不添加阶段变化活动。
- **原因与取舍：** 分页列表配合筛选适合逐条处理较多岗位，减少重复展示入口；状态归并通过读取时映射完成，避免自动改写同步基线或影响草稿并发比较。
- **约束：** 不改变共享数据、工作区、备份及草稿格式，不增加迁移或提升本轮版本号；已保存活动和导入原文保持原样。D017 的人工浏览器测试分工继续有效。
- **替代关系：** 调整 [D016](0016-two-entries-unified-detail.md) 的看板及展示方式切换安排；保留其两个业务入口、日期查询、分页、统一详情与上下文保留规则，保留原条目的设计原因。
- **重新评估条件：** 出现需要区分尚未联系岗位的明确工作流程，或需要跨阶段统计等列表筛选无法满足的需求。
