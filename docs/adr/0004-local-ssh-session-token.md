# D004：本机复用 SSH，公开网页使用会话令牌

- **记录日期 / 状态：** 2026-09-11 / 有效。
- **问题：** 用户已经配置 SSH key，能否避免在本机网页填写令牌？
- **决定：** 本机服务通过系统 Git/SSH 访问固定私有目标，使用独立 bare 缓存；浏览器调用同源本机接口。手机或公开网页使用 GitHub REST 与当前页面内存中的 PAT，刷新后重新填写。
- **原因：** 用户提出使用 SSH key 的偏好。本机桥接可以复用现有配置，同时让私钥保持在系统 SSH 环境中；浏览器静态网页本身不具备直接使用本机 SSH key 的能力。
- **备选与取舍：** 全部使用 PAT 配置简单，但本机会重复填写；原生桌面应用或 OAuth 服务可以提供其他授权体验，但引入额外平台或服务维护。持久化令牌的方便性需要另行权衡，当前不做。
- **约束：** 本机只监听回环地址，校验 Host、Origin 和随机会话；目标由服务端配置固定，不能从网页任意选择远端。不操作 Obsidian 工作树，不强推。PAT 权限覆盖所选仓库，应用的路径限制并不等于 GitHub 提供文件级授权。
- **重新评估条件：** 手机成为主要入口、需要持续登录或后台同步，或希望更细的授权范围。
