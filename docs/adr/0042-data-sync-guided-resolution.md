# D042：数据与同步按任务引导异常处理

- **日期 / 状态：** 2026-10-07 / 已实施代码；真实界面待人工验收。
- **来源：** 用户指出设置页仅分开运行信息和处理记录仍难以理解，要求整理完整异常处理流程；确认保留现有防错规则，简化普通资料核对与同步冲突，不新增旧聊天归属冲突的终结流程。
- **问题：** 采集、录入、同步与备份的信息堆叠在同一页面，用户需要展开多层详情才能发现问题；冲突展示完整 JSON，不能直接说明哪些字段不同、影响哪些记录及保存后还需做什么。
- **页面决定：** 数据与同步页按 BOSS 接入、手动 GitHub 同步、备份与文件三项任务组织。各卡展示当前状态、最近成功时间和主要动作，需要处理时直接进入对应问题；每项异常说明原因、影响与下一步。当前问题由已有状态计算，不新增任务或持久提醒。额度等待与跟踪停止显示为运行状态，人工保护、已忽略、回执及技术参数收进处理记录或运行详情。
- **普通资料确认：** 为已有命令 `resolve_boss_job_details` 提供网页入口，仅处理普通消息及回执中的 `missing_job_details / identity_conflict`。目标必须是同账号下岗位 ID、规范链接一致的唯一现存岗位；本次入口不处理多目标或已删除重复岗位。确认时重新读取正式工作区，展示候选岗位、消息及观察数量，以最新 revision 和持久幂等键整批保存。结果为 `no_effect / user_confirmed_job_details`，表示人工资料核对完成；原始观察、简历归属及人工岗位状态独立保留。
- **原有核对与忽略：** 候选岗位查看、明确保存岗位编辑，以及有效 waiting 的多选忽略继续使用现有流程。查看和编辑不确认观察归属，也不自动忽略观察。归属 review 保留原因和核对路径，本次不新增通用“不采用”、忽略冲突或确认归属操作；缺稳定消息身份的观察转入采集排障说明。
- **同步冲突：** 按岗位及关联记录分组，用可读标签展示双方分歧，完整 JSON 仅放技术详情；账号绑定、来源应用等不能唯一归到岗位的冲突独立说明。逐组核对只改变页面选择，最终一次保存全部冲突决定。岗位及任务的原子字段组仍整体选择，不自由拼接，不按更新时间默认选边。保存后说明本机决定已保存、尚待上传，同屏提供用户明确触发的 GitHub 同步入口。
- **重新检查反馈：** 用户保存岗位资料或解决同步冲突后，复用现有约 30 秒纯本机消费与状态刷新，展示当前已解决或仍缺什么；相同材料和结果不产生新提交。不新增重评命令、平台请求或循环补录，不承诺固定完成时间。服务失联时保留旧结果并提示状态待更新；恢复缺口仍需按当前 revision 明确核对固定批次，不能自动重放。
- **保存与恢复：** 所有正式修改继续经过单写者、版本比较、持久幂等及原子提交。响应不确定时精确重试原请求，revision 冲突重新读取并核对；同步 pending 仍阻止普通资料确认和忽略等既有受限命令。本机正式历史、浏览器旧快照及独立磁盘备份分别说明，备份失败保持可见，不把浏览器缓存视为正式数据源。
- **兼容：** 应用 0.10.6；BOSS 规则 v10、共享数据 v4、工作区 v3、完整备份 v2、服务协议及私有格式不变，无数据迁移。已有事件、事实及应用 ID、人工决定、删除标记、账号隔离、同步双方和恢复事实存在性检查保留。
- **替代关系：** 部分调整 [D038](0038-boss-job-details-and-observation-groups.md) 的“不新增人工补齐界面”边界，为受限普通资料确认提供入口，保留其详情优先、消息汇总、关闭状态和人工处理语义。[D039](0039-boss-manual-retired-job-resolution.md) 的明确删除重复项处理仍保留在原有服务范围，不扩大为本次通用网页入口。[D005](0005-three-way-merge-conflicts.md)、[D033](0033-boss-import-convergence.md)、[D036](0036-boss-waiting-observation-ignore.md) 和 [D040](0040-boss-repeated-work-and-stable-reevaluation.md) 的合并、归属、忽略及稳定重评规则继续有效。
- **取舍：** 采用现有命令和现有本机重评减少用户步骤，保留事务与证据边界。各异常给出相应操作或排障步骤，不新增一套通用冲突关闭状态、自动平台重采、自动上传或长期异常处理系统。服务启动和重启不恢复 BOSS 跟踪授权。
- **验收：** 完整非浏览器测试 655/655、`pnpm check` 与 `pnpm format:check` 通过，覆盖页面渲染、异常引导、普通资料准入、最新 revision、精确重试、批量原子保存、同步差异与完整选择、结果反馈和转义。真实页面的直达、逐组选择、返回位置、展开及选择保留由用户验收，未反馈前不宣称完成；浏览器回归脚本与 CI 配置保留。
