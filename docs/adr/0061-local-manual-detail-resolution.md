# D061：详情异常的本机人工处理

- **记录日期 / 状态：** 2026-11-05 / 已决定；实施及验收结果随 PR 记录。
- **来源：** 用户在详情定点补查仍失败后询问异常的人工处理路径，明确同意继续完善网页处理流程；随后选择人工停止决定仅在本机采集任务生效，重启保留，不随求职数据同步。
- **决定：** 设置页提供逐岗位原链接、失败原因、资料编辑、明确单次重试及人工停止入口。人工停止按账号与岗位绑定，保留原失败和诊断；处理记录可撤销，撤销仅移除抑制并按当前材料重新判断，不重置失败次数或自动发起平台请求。新消息不自动撤销决定，其他消息采集和岗位跟进保持独立。
- **资料边界：** 业务补齐复用正式工作区的新增、编辑和受限资料确认。没有唯一目标时不猜测归属、不复活删除项；新增入口只预填已观察的规范岗位链接。“资料已补齐”记录用户核对时的工作区 revision，不保证以后资料永远完整，不与业务编辑宣称跨存储原子提交；用户也可明确决定无需继续采集详情。
- **存储与恢复：** 本机决定属于统一采集控制器，采用 tracking v2、独立决定 revision 和持久命令回执。它不进入求职 JSON、业务工作区备份或同步。工作区恢复不清除停止决定，业务资料被撤回时仍独立显示缺项。旧控制状态升级保留原件，未知字段或未来版本拒写；写入结果不明时隔离后续写者，不能用旧内存覆盖已落盘决定。
- **执行约束：** 保存及撤销仅在停止且无在途轮次时执行，核对账号、任务版本及预期 revision。同幂等请求回查原结果，不同内容复用命令 ID 拒绝。普通和定点详情选择均遵守单次票据精确绑定的停止集合；人工保存与查看清单不访问平台。界面分别显示人工处理、实际采集与业务资料结果。
- **取舍：** 不新增共享人工资料实体或迁移求职数据；本机控制状态单独承担采集偏好。保留技术失败比删除任务更能解释后续撤销和排障。容量达到上限时拒绝新修改并保留旧状态，不淘汰幂等回执或截断决定。
- **替代关系：** 补充 [D060](0060-explicit-isolated-detail-retry.md) 的网页重试与人工停止边界，以及 [D042](0042-data-sync-guided-resolution.md) 的异常处理入口；原资料确认、观察忽略和平台访问约束保持。
- **重新评估条件：** 若需跨设备共享决定、自动撤销人工停止、批量关闭不同异常或让人工输入成为平台证据，应重新核对数据所有权和业务边界。
