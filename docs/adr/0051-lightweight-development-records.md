# D051：简短本地记录与按需证据工具、审查统计

- **记录日期 / 状态：** 2026-10-27 / 已实施；记录位置与默认远端交付由 [D054](0054-issue-pr-delivery.md) 部分替代，其余决定保留。原隔离场景与工具契约验证通过，实际使用效果待自然反馈。
- **来源：** 用户指出“现在的任务这块套有点复杂”，要求保留复盘材料，并修正“不补充到 Issue／PR 中”的保存约定；[流程精简规格](../specs/workflow-simplification.md)的 S1–S7 保存来源、取舍及实施授权。规格和本地工单完成后，用户对按依赖实施全部工单回复“可以”，授权本地改造与验证，不含远端发布。
- **问题：** 普通任务也须登记 UUID、维护检查声明和快照、启动审查统计，固定成本超过其记录需要；审查材料准备与统计目录耦合，简单交付仍需维护完整台账。
- **决定：** 默认直接执行适用检查、完成独立审查并保留一条本机简短记录。记录覆盖目标与取舍、结果与版本、验证与限制及自然发生的后续反馈，位置可定位即可，起止时间和任务 UUID 不强制。同一事项沿用原记录，已有 UUID 材料无需迁移；正式规格保存在仓库 Markdown，随 Git 管理。已有 Issue／PR 不触发正文、记录或引用的自动补充。
- **按需能力：** 明确选择复用旧检查结果且需要机器判断版本适用性时使用现有证据工具；专项观察需要时启用审查统计，从真实启用时间采集。普通检查与审查无需声明、快照、统计编号或 JSON。材料可用固定提交，或完整差异、相关新增文件及必要基线定位，两轴使用同一版本，来源与规则可回查。
- **保留条件：** 检查与审查必须对应实际交付版本；相关变化补查并复查，失败、中断或未完成不能退用旧通过。保留 Spec 两阶段目标核对、Standards 独立审查、高风险前置验收和检查覆盖变动审查。证据工具内部 UUID、声明、运行、复用及核验契约，统计接口、真实性口径和历史材料均保留；工具通过不证明授权、声明完整或人工验收。
- **取舍：** 减少默认填报，同时由执行者与独立审查者核对版本及覆盖；需要机器辅助时仍可选用既有工具。短记录支持个案复盘，但缺少可靠时间或反馈的样本不能计算可靠耗时或推断已验收、零缺陷。未选择五实体模型、统一任务命令、自动报告或看板，避免新增维护体系。
- **替代关系：** 替代提交 `ebeadedd3becaae5c953c0b68a6e2a7c58a5d348` 中共用流程及技能的默认任务登记、证据和统计要求；此前没有对应编号 ADR，原规则由 Git 历史保留。原要求用于版本固定和追溯，这两个目标继续保留。[D008](0008-lightweight-static-architecture.md) 的可复现检查能力及 [D017](0017-manual-browser-testing.md) 的浏览器分工继续有效，不被本决定替代。
- **范围与验证：** 仅调整研发流程、技能入口和配套说明，不改变产品、CI 或应用版本。沿用[流程回归案例](../agents/workflow-regressions.md)验证默认交付、无统计审查、版本变化、检查覆盖缩小、来源恢复和本地反馈；工具契约使用既有合成测试。具体结果随实际交付版本记录，案例通过不等于长期效果已经改善。
- **重新评估条件：** 真实反馈显示关键来源、版本、审查或反馈追溯经常缺失，或专项观察证明机器核验有稳定收益时，再调整相应入口；不从时间和反馈缺失推导需要恢复全量登记。
