# D059：独立接入本地 UML 源码浏览器

- **记录日期 / 状态：** 2026-10-31 / 已决定；实施、检查与桌面交互验收随本次 PR 记录。
- **来源：** 用户在比较 Archify 与 `unclebob/uml-viewer` 的模块下钻能力后，明确要求“单独接一下这个工具到项目中”。
- **问题：** 需要从目录组件逐层进入模块与源码。上游原生支持该导航，但其扫描器跳过作为本项目源码的 `dist/`，不同扫描根不能完整连接相对导入，默认启动流程还会拉起 Grok companion。
- **决定：** 以可选开发工具接入，提供独立 `pnpm uml` 命令。固定上游提交，将 checkout、运行依赖缓存和生成图放在忽略的 `.local/uml-viewer/`。项目适配器统一读取 Git 跟踪的公开生产源码，静态提取跨目录导入并生成层次 EDN；查看器沿用原生下钻和只读源码窗口。自有启动器禁用 companion、mailbox 和 proposal 写入，工具不控制应用服务。
- **原因与取舍：** 复用已有桌面下钻能力，并保留本项目的源码与隐私边界。增加 JVM/Clojure 开发依赖和固定版本适配维护成本；Archify 继续负责可分享的系统说明。图仅表示静态模块依赖，成员提示沿用上游解析器的能力范围，不代表完整调用图或测试指标。
- **约束：** 保留 D008 的轻量应用及 `dist/` 直接维护约定，工具代码和缓存不进入公开部署。只读取允许的公开源码，不执行业务模块、不扫描私有材料、不跟随符号链接；生成失败不发布部分图。上游代码不复制进本仓库，固定提交或本机 checkout 不符时停止启动。上游目前未提供 LICENSE，后续再分发或合入其源码前需核对许可状态。
- **替代关系：** 新增开发工具，不替代 D008、D017、D057 或既有 Archify 图表；不扩大浏览器、平台访问、同步、版本发布和合并授权。操作入口见[UML 工具说明](../UML_VIEWER.md)。
- **重新评估条件：** 上游正式提供独立启动、可配置扫描和跨根解析，许可状态改变，固定适配失效，或用户要求网页内下钻时重新评估。
