# D048：按动作结构确认发送，受限补现存岗位状态

- **日期 / 状态：** 2026-10-10 / 已实现；真实补状态与界面待核对。
- **后续补充：** [D049](0049-boss-versioned-opaque-action-evidence.md) 补充已核实转换版本下的不透明字符串扩展；本文原始规则与理由保留。
- **来源：** 用户指出指定会话的简历发送状态漏统计，授权只读核对并要求修复，随后要求当日“补状态就行了”。已加载消息缓存及平台公共转换代码表明原始 `type` 原样映射，`body.type=4 / body.action.aid=40` 生成“附件简历请求已发送”文案，`extend.annexType=1` 表示作品集。本次没有取得对应的完整原始历史接口响应，缓存及公共转换代码不能替代真实历史采集验收。
- **原因与决定：** D047 只补充了链接发送及查看系统确认，动作型消息的原始 `body` 没有对应文案时仍会漏采。新增严格的数字 `type=1 / body.type=4 / body.templateId=1 / body.action.aid=40` 组合，只以已核实动作产生固定发送含义，不从 `body.text` 或普通聊天引用推断。`extend` 缺省、null、空串，或合法 JSON 对象缺少 `annexType` 时保存 null；明确数字 0 保存 0。数字 1 是作品集，其他取值、无效 JSON、数组或非字符串扩展均不确认。未知 `annexType` 值不被默认为缺省，普通 type 1 文本以及旧 v1/v2 type 1 依据不足；通用卡片继续按现有规则存档。
- **交付与消费：** 新语义依据 v3 仅包含 `version`、`messageType`、`field`、`text`、`bodyType`、`templateId`、`actionAid`、`annexType` 八个字段，路径为 `body.action`，文字为固定已发送文案，不保留原始扩展串、聊天正文、附件名或凭据。私有快照/批次升至 v7、历史检查点升至 v5，继续读取旧快照/批次 v1–v6 和检查点 v1–v4，旧容器不得携带 v3 依据，v2 的原版本门槛保持。服务消费重验同观察内的语义与归属，生产者分类不代替确认依据，未知字段与未来版本仍拒绝。
- **补状态范围：** 用户授权的当日任务只更新现存岗位的自动状态，不新建岗位。临时补查复用已有 `runResumeHistoryRequests`、串行请求、持久预算、账号锁、不可变快照、简历批次队列及正式服务消费；不新增 CLI、页面入口或长期配置，也不以普通增量导入或详情补齐扩大范围。没有唯一现存目标、归属不足、人工所有权、删除或同步冲突时保留对应结果并报告；实际覆盖、截断、观察保存和正式应用数量需执行后分别核对，有限页数不保证全部旧消息已覆盖。
- **保留与取舍：** 补充 [D047](0047-boss-explicit-system-confirmations.md)，旧 ADR 原文保留，不改变其中链接发送、查看及同观察语义核对规则。继续保留 [D043](0043-boss-observation-only-archive.md) 的纯卡片存档、[D019](0019-boss-resume-status-link.md) 的发送/接收联动及 0.10.19 普通资料修复。已应用历史、原始观察和稳定 ID 不批量改写，人工否决、忽略、字段、账号隔离、删除、冲突和恢复缺口保护保持；不通过全面放开 type 1 或旧文字依据弥补漏采，因为引用文字及作品集会形成误报。
- **运行与版本：** 应用 0.10.20、规则 v15；共享数据 v4、工作区 v3、完整备份 v2、服务协议 v1、HEAD/catalog 与正式提交格式不变，无正式整库迁移。补状态前后保留私有完整备份，正式写入仍经唯一服务写者及持久幂等交付。服务重启不恢复 BOSS 跟踪，本次不启动持续跟踪或自动 GitHub 同步，临时授权不转为长期平台访问授权。
- **验收与重新评估：** 非浏览器合成回归覆盖动作确认、缺省与数字 0、作品集和未知扩展拒绝、普通文字及旧 type 1 依据不足、服务消费重验、旧容器门槛及人工/恢复保护。真实补查与正式回读分别核对，界面验收由用户确认明确发送/查看联动且普通卡片、作品集不误报；出现新的平台动作结构或扩展含义时，先取得最小只读依据再评估，不能凭模板或泛化关键词放宽规则。
