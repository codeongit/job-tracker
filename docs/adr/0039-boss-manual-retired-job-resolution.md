# D039：人工指定现存岗位处理旧观察

- **日期 / 状态：** 2026-10-06 / 已实施并核对正式处理结果；真实界面待人工验收。
- **来源：** 用户在了解两条旧观察分别缺少本机岗位 ID、存在已删除重复岗位后，回复“可以”，授权补齐精确身份并将普通旧观察指定到现存岗位。
- **问题：** 已有规范岗位链接的人工岗位可能缺少平台岗位 ID；同一职位还可能同时保留现存记录和已删除重复记录。直接拒绝所有这种人工处理，会使已经明确确认的普通资料观察继续处于核对状态。
- **决定：** `resolve_boss_job_details` 允许从与目标一致的规范链接原子补入空的 `externalId`；已有非空 ID 不一致时仍拒绝。指定目标必须是现存岗位；可选 `retiredOpportunityIds` 必须精确列出同一规范岗位身份的全部已删除重复记录，不能漏列、多列、包含现存记录或带有矛盾身份。任何仍有效的来源绑定指向这些旧记录时，继续拒绝处理。
- **处理结果：** 保留原始观察、事实、稳定 ID 和删除标记，仅保存既有 `no_effect / user_confirmed_job_details` 人工决定及必要的空岗位 ID 补齐。公司、岗位名称、简历状态和招聘阶段不改写。该决定不是平台详情证据，也不成为简历归属依据。
- **约束：** 账号、同步冲突、跨岗位消息、人工否决、已忽略观察等检查保持有效；命令继续使用预期工作区版本、持久幂等键及整批原子提交。自动导入仍将已删除记录纳入多目标检查，不采用人工命令的排除列表。无需新增页面或平台访问；服务重启不恢复跟踪。
- **替代关系：** 仅调整 [D038](0038-boss-job-details-and-observation-groups.md) 中人工资料处理遇到已删除匹配记录时一律拒绝的实现边界；保留 D038 详情依据、展示、平台状态和兼容规则，以及 [D035](0035-boss-conversation-association-application.md) 简历归属规则。旧 ADR 保留。
- **兼容：** 应用升至 0.10.1，规则仍 v9、共享数据仍 v4。排除列表是显式命令参数，不增加共享实体或采集协议字段；工作区、备份与私有批次版本不变。
- **重新评估条件：** 若需要普遍合并重复岗位、迁移旧绑定或恢复已删除岗位，应另行设计；本决定只结束已经明确指定目标的普通资料观察。
