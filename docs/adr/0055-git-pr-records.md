# D055：以 Git 与 PR 承接研发记录

- **记录日期 / 状态：** 2026-10-29 / 有效；实现、验证与最终审查状态随 PR 记录。
- **来源：** 用户在 Issue／PR 流程实施后指出 task 目录文件过多，连续追问必要性与移除影响，指出未提交审查快照过于复杂、日志已有原位置无需再复制，随后调用 `ask-matt` 回复“继续”。取消常规本机任务台账、使用本地候选提交和沿用原日志是已讨论方向；退役可选证据工具是为解除目录耦合作出的实施选择。
- **问题：** 默认本机交付记录与 PR 重复维护，工作树审查还需保存源码副本。证据工具另要求 UUID、声明及快照，固定写入 `.local/tasks/`；迁到另一目录仍会保留同等管理负担。
- **决定：** 需求与后续修正沿用 Issue 或规格，关键决定沿用 ADR；Git commit 固定源码和审查版本，PR 承接公开验证、审查、风险与验收反馈。日志及私有诊断保持原位置。取消常规 task 目录、`delivery.md` 和关联索引要求；复盘从已有来源定位材料，缺少证据时明确限制。
- **提交与审查：** 实施完成格式化及适用检查后，仅对本任务改动创建本地候选提交，再分派同一 commit 的独立审查；修复追加提交并补查。多工单由主协调者组织候选提交、审查及串行集成。候选 commit 不代表检查或审查通过、工单完成、依赖解除或获准合并。纯只读工作树审查不擅自提交，直接核对范围与首尾内容变化。
- **工具取舍：** 退役 `pnpm task:evidence`、脚本及其专用测试。该工具未被应用运行时或其他工具调用；移除它会失去声明范围内的自动失效和复用判定，由现有版本、依赖、环境和检查配置核对承接，无法证明适用的结果重跑。保留按需审查统计及现有检查入口；工具专用测试不再运行，不将测试数减少解释为产品覆盖改善。
- **保留条件：** 检查结果与受检内容对应；Spec 两阶段、独立 Standards、原始目标核对、覆盖与检查配置变化审查、失败不能沿用旧成功均继续有效。PR 发布与合并授权、隐私及浏览器分工不变。仅本地或远端失败时以当前对话交付 commit、结果和待办，无需另建记录；公开摘要不依赖私有文件链接。
- **历史与恢复：** 历史 `.local/tasks/`、快照和日志不删除、不迁移。旧工具及契约可从提交 `f1a94a379d4ef5672ce67d10a0e8ad6887350428` 回查；必要历史核验使用旧版本解释，原输入或环境缺失时不保证重放，不声称当前仍有该命令或旧结果适用于当前版本。规则回退可由 Git 恢复，但不能撤回已发生的远端操作。
- **替代关系：** 部分替代 [D051](0051-lightweight-development-records.md) 的默认本机短记录及证据工具保留决定、[D052](0052-coordinator-owned-ticket-review.md) 的审查后提交顺序、[D054](0054-issue-pr-delivery.md) 的本机关联索引要求；其余独立审查、协调职责与 PR 交付约束保留。
- **验证与重新评估：** 检查文档与技能引用、普通任务候选提交及无关改动隔离、版本变化后的证据适用性、从已有来源复盘。若实际出现必要来源、版本或结论无法追溯，针对缺失位置补齐，不因一次材料缺失恢复全量任务台账。后续耗时与效果需真实可比样本，不由文件减少推定。
