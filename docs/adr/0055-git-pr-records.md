# D055：以 Git 与 PR 承接研发记录

- **记录日期 / 状态：** 2026-10-29 / 有效；说明组织由 [D056](0056-review-results-in-pr.md) 后续调整，实际验证状态随 PR 记录。
- **来源：** 用户在 Issue／PR 流程实施后指出本机过程文件过多，连续追问必要性与移除影响，指出未提交审查快照过于复杂、日志已有原位置无需再复制，随后调用 `ask-matt` 回复“继续”。以本地候选提交固定版本、在 PR 汇总结果并沿用原日志是已讨论方向。
- **问题：** 默认本机交付记录与 PR 重复维护，工作树审查还需保存源码副本。另建目录仍会保留同等管理负担。
- **决定：** 需求与后续修正沿用 Issue 或规格，关键决定沿用 ADR；Git commit 固定源码和审查版本，PR 承接公开验证、审查、风险与验收反馈。日志及私有诊断保持原位置。复盘从已有来源定位材料，缺少证据时明确限制。
- **提交与审查：** 实施完成格式化及适用检查后，仅对本任务改动创建本地候选提交，再分派同一 commit 的独立审查；修复追加提交并补查。多工单由主协调者组织候选提交、审查及串行集成。候选 commit 不代表检查或审查通过、工单完成、依赖解除或获准合并。纯只读工作树审查不擅自提交，直接核对范围与首尾内容变化。
- **保留条件：** 检查结果与受检内容对应；Spec 两阶段、独立 Standards、原始目标核对、覆盖与检查配置变化审查、失败不能沿用旧成功均继续有效。PR 发布与合并授权、隐私及浏览器分工不变。仅本地或远端失败时以当前对话交付 commit、结果和待办，无需另建记录；公开摘要不依赖私有文件链接。
- **历史与恢复：** 已有本机材料保留原状。原决定全文见 Git 提交 `c7a5e8f61330435cdfc85780789f9f4eaefd1fb0` 的同名文件；历史结果不代表当前验收，原输入或环境缺失时不保证重放。规则回退可由 Git 恢复，但不能撤回已发生的远端操作。
- **替代关系：** 部分替代 [D051](0051-lightweight-development-records.md) 的默认本机记录安排、[D052](0052-coordinator-owned-ticket-review.md) 的审查后提交顺序、[D054](0054-issue-pr-delivery.md) 的材料组织安排；其余独立审查、协调职责与 PR 交付约束保留。
- **验证与重新评估：** 检查文档与技能引用、普通任务候选提交及无关改动隔离、版本变化后的证据适用性、从已有来源复盘。若实际出现必要来源、版本或结论无法追溯，针对缺失位置补齐，不因一次材料缺失恢复全量任务台账。后续耗时与效果需真实可比样本，不由文件减少推定。
