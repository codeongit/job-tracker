# D050：滚动采集材料保留连续相同证据的首末观察

- **日期 / 状态：** 2026-10-20 / 已实现；本机恢复通过，真实界面待验收。
- **来源：** 用户确认修复快照持续增大导致的暂停、补交已保存材料，并在验证后恢复跟踪。具体保留算法及大小边界为实现选择。
- **问题：** 列表岗位名称证据的身份包含观察时间。即使资料不变，每轮仍追加同义证据；采集端可以保存超过交付端读取上限的快照，导致本机补交持续受阻。
- **决定：** 新生成的滚动材料仅压缩 `loaded_jobName` 证据。按会话、岗位、规范链接和来源分流，再按原观察时间及相同时间下的原顺序检查连续观测段；除 `id / observedAt` 外所有字段完全相同的一段，只保留首次与末次原记录。同毫秒并列记录全部保留，避免改变稳定排序及选中的原时间文字。保留原 ID、时间和字段，不拼接观察。缺少完整会话身份的旧证据保持原样。
- **变化与冲突：** 岗位名称、公司或任一其他字段变化均开始新段，A→B→A 的每次变化保持。不同会话或岗位不合并；详情、旧命名资料、候选、人工确认、消息与简历观察保持。三种资料投影的选择、原最新证据时间、详情计划及稳定事件、事实、应用身份须保持。
- **原件与边界：** 已保存的不可变快照及其原始字节摘要不改写、不删除。新快照使用紧凑 JSON；采集读取、采集写入和交付读取共用 50,000,000 字节的有界上限。写入按最终 UTF-8 字节检查，超限时不生成新快照或确认配套进度。未知字段及未来版本继续按原规则拒绝，不借压缩丢弃未知信息。50 MB 是本机实现边界，不是平台限额或正式共享数据大小限制。
- **恢复与运行：** 先保存完整私有备份，在副本预演全部未交付快照、队列及等待重评；出现预期外岗位业务变化时暂停核对。旧超限材料经严格读取和原字节摘要核对后，使用现有本机恢复与唯一服务写者交付；回读事实、应用、岗位、检查点与回执，并重复恢复检查幂等。恢复不发平台请求、不清空预算。服务重启不恢复跟踪，只有已获明确授权并核对本机结果后才显式恢复。
- **取舍：** 保留每轮相同观察会造成无变化增长；仅提高大小上限会延后同一故障。按取值全局只留首末会丢失中间返回同一取值的变化，因此采用连续观测段。新滚动材料省略同义段内的中间时刻，完整历史原件仍可单独审计；真实材料和变化仍可能达到有界大小限制，需要另行分析，不能承诺无限容量。
- **兼容：** 应用 0.10.25，规则 v17；共享数据、工作区、备份、服务协议、快照、批次和检查点格式均保持，无正式数据迁移。
- **替代关系：** 细化 [D027](0027-collector-source-colocation.md) 的私有采集材料维护，以及 [D040](0040-boss-repeated-work-and-stable-reevaluation.md) 的重复材料处理边界。保留 [D026](0026-local-authoritative-workspace.md) 的唯一写者、显式跟踪及正式不可变提交保护；本决定不授权裁剪正式历史、清理原快照或放宽归属、简历和人工保护规则。
- **验证与重新评估：** 合成验证连续重复不持续增长、所有真实变化保留、三种投影与既有身份输出一致、旧超限材料恢复、UTF-8 字节边界、保存失败与重复恢复。若真正不同的证据仍逼近上限，再独立设计材料分卷或存储方案，不自动扩大上限或删除历史。
