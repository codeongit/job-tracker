# D025：允许受控读取会话详情并设计简历状态采集

- **记录日期 / 状态：** 2026-09-21 / 有效；精确平台状态自动提升已完成首批真实样本验收。
- **来源：** 用户明确取消“禁止自动切换聊天”的限制，并要求分析简历状态采集方案。
- **问题：** 列表快照不能可靠证明简历是否发送、被索要或已被对方接收；直接点击未读会话又可能改变平台已读状态。
- **决定：** 允许在任务独占后台页中受控读取已识别会话，优先使用求职端只读历史消息接口而非点击可见聊天。结构化消息保留稳定消息 ID、方向、时间和岗位身份；四类用户确认的精确平台状态进入白名单：“附件简历请求已发送”“对方已同意，您的附件简历已发送给对方”“您的附件简历 … 已发送给Boss”映射为已发送，“对方已查看了您的附件简历”映射为对方已接收。
- **约束：** 不导航用户原标签，不输入、发送、投递、上传或调用写接口；若 UI 切换会改变平台未读状态则停止。状态只单向提升已关联岗位的 `resumeState`；成功提升后执行 D019 的本地工作台联动，将消息设为已读，并仅把已触达（含旧待联系）推进到沟通中。人工修改、主动清空和更高状态受保护。缺岗位 ID 时只允许使用会话的唯一岗位关联，普通简历卡片和宽泛关键词只做观察。
- **原因：** 历史消息接口已能提供稳定消息身份，精确状态文案在真实样本中完成验证；严格白名单和唯一岗位约束可在不保存聊天正文、不猜测语义的前提下更新简历状态。
- **重新评估条件：** 平台文案或接口结构变化、出现会话多岗位样本、需要新增“被索要”状态来源，或联动范围需要改变。
- **替代关系：** 调整 D022/D023 中“禁止切换聊天”的范围，但保留只读、低频、故障停止和不推断业务事实的其他边界；不自动启用 D019 的人工联动。
