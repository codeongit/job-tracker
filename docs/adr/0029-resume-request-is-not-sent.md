# D029：附件简历请求不等于简历已发送

- **记录日期 / 状态：** 2026-09-24 / 有效。
- **来源：** 用户指出同公司两个不同岗位的会话中，只有一个实际发送了简历；另一个仅有普通聊天，却被统计为“已发送”。本机最小证据核对显示，错误岗位只保存了 `resume_request_sent` 请求卡片，没有发送或查看确认。
- **决定：** “附件简历请求已发送”只证明存在请求，至多将岗位简历状态从“未知”推进为“被索要”；它不证明求职者已发送简历，也不联动消息已读或招聘阶段。“对方已同意，您的附件简历已发送给对方”和“您的附件简历 … 已发送给Boss”继续映射为“已发送”；查看确认继续映射为“对方已接收”。较高状态不因后到的请求证据回退。
- **历史纠正：** 已被旧规则误提升的本机正式记录只能通过版本化、按具体岗位和请求事件限定的纠正命令修改。命令要求来源字段仍由自动化拥有，并核对该岗位没有发送或查看确认；只恢复误提升的字段，保留原始来源事实、应用记录、不可变历史及人工字段所有权。同步冲突期间拒绝纠正；纠正不会自动上传 GitHub。
- **原因：** 请求卡片与发送完成是两种不同业务事实。原规则把请求也当发送，使仅有请求的岗位呈现错误状态。
- **约束：** 不重新访问招聘平台，不修改真实原始快照或聊天记录，不批量猜测其他岗位。真实浏览器显示仍由用户验收。
- **替代关系：** 仅替代 [D025](0025-controlled-conversation-detail-read.md) 中“附件简历请求已发送 → 已发送”的映射；保留其只读采集、精确证据和其他状态规则，以及 [D019](0019-boss-resume-status-link.md) 对真正已发送状态的联动。
- **重新评估条件：** 平台明确证实该卡片代表已完成发送，或出现可验证的新请求、发送状态格式。
