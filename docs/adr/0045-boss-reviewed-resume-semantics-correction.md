# D045：按明确核对清单纠正卡片发送误判

- **日期 / 状态：** 2026-10-08 / 已确认；实现与验收见版本记录。
- **来源与问题：** 用户核对本机审计清单后，明确授权纠正其中缺少独立发送依据、仍由自动简历字段记录为已发送的岗位，并保留有独立发送依据的记录。D044 已阻止新卡片与旧未应用材料误联动；只修识别规则不会撤销此前已经应用的错误判断。
- **决定：** 使用 `correct_boss_resume_semantics` 服务命令提交已审阅的来源应用 ID 清单，整批重新验证后原子保存。它只将符合条件的自动简历状态从“已发送”纠正为“未知”，保留消息状态、招聘阶段及这两个字段的所有权与自动来源记录，所有人工字段继续保护。
- **否决与事实：** 对同一来源事实的全部兼容应用映射记录 `protected / user_rejected_wrong_resume_semantics`，保留原始来源事实与观察，不改写卡片枚举或稳定身份。人工否决持续阻止同一事实通过补录、旧队列或恢复重放再应用；同一会话的新消息独立处理。其他有效发送或接收事实阻止回退，纯存档卡片不提供发送支持。
- **安全与交付：** 命令沿用服务协议、当前工作区账号绑定、预期 revision 与持久 commandId，服务重新核对每项事实、目标、自动字段及支持材料。状态变化、人工控制、删除、账号或身份矛盾、同步冲突及其他准入失败均中止整批，不部分保存；丢失响应只精确重试原命令，版本变化重新核对清单。只有已确认的正式提交才能报告纠正成功。
- **恢复保护：** 合并恢复和回到快照仅在同一事实、应用及目标仍有效，且已有未删除的同事实原始观察时保留当前人工否决；单个旧观察别名已删除不取消其余有效材料的保护。含冲突备份的正式数据与本机待合并候选分别保护，远端材料和冲突双方保持。旧备份仅恢复自动已发送、且没有其他有效发送支持时，继续纠正该简历字段及必要的自动来源记录；人工值与其他真实发送支持保留。缺失或删除的事实、应用、目标及原始观察不补造或复活；同事实观察全部缺失或删除时保留恢复缺口，仍需明确核对，旧回执不能证明它们存在。
- **取舍：** 无差别回退所有已发送状态会撤销真实发送和人工决定，因此依据明确清单实行受限人工纠错。保留其他自动联动字段是本次用户确认的范围，不把简历纠正扩大为重写历史跟进过程，也不从缺证据断言未曾发送。
- **替代关系：** 补充 [D044](0044-boss-card-semantics-evidence.md) 的“已应用历史不自动批量回退”边界，增加明确清单的人工纠错命令；D044 的识别、语义依据、隐私与前瞻应用规则继续有效。沿用 [D030](0030-reject-misattributed-resume-observation.md) 的人工否决保护与 [D026](0026-local-authoritative-workspace.md) 的单写者和原子命令，不新增自动历史回退策略。
- **格式与运行：** 应用 0.10.16，规则 v12；共享数据 v4、工作区 v3、完整备份 v2、服务协议 v1 及现有私有格式保持，无迁移。不新增平台访问、采集任务、页面入口或 GitHub 同步；服务重启不恢复 BOSS 跟踪。
- **重新评估条件：** 用户扩大已审阅清单或要求纠正其他联动字段时，应重新核对支持事实和人工所有权，明确授权范围；不能借此命令自动选择所有缺依据的历史记录。
- **后续调整：** 用户指出招聘阶段遗漏后，[D046](0046-boss-resume-correction-linked-stage.md) 部分替代本记录的阶段保留边界，撤回明确清单中符合条件的自动联动“沟通中”；其余纠错及保护规则继续有效。
