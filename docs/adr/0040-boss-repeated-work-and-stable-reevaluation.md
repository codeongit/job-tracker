# D040：减少重复计算并稳定同事实重评

- **日期 / 状态：** 2026-10-06 / 已实施，非浏览器检查及实际启动、重复消费核对通过；真实界面待人工验收。
- **来源：** 用户同意优化本机服务长时间启动和等待项重复处理，采用身份计算复用、去除重复迁移处理、统一同事实观察候选三个收敛措施。
- **问题：** 同一稳定来源身份在完整历史校验中反复计算；v3→v4 迁移重复执行来源账本适配；同一事实的不同旧观察分别重评时，等待原因可能来回变化，造成没有新业务结果的重复提交。
- **决定：** 对确定性身份计算采用进程内有界复用，只复用完整输入一致的纯计算结果。v3→v4 的账本适配只执行所需的一次，仍完整迁移工作区 data、base、pending 及冲突各侧。正式消费从当前已有材料构建临时的同事实观察候选集合，使相同材料得到稳定判定；业务决定及字段均未变化时，不因重复消费制造新提交。
- **归属边界：** 每份候选保留自己的完整身份依据，独立执行同一纯归属关卡，不拼接不同观察的字段。verified 必须由一份完整且一致的候选支持；已有候选及跨候选的非空身份矛盾必须保留，不能由另一个通过的候选或最新材料遮住。候选按账号、会话、稳定消息及事实类型区分，不把同一消息的不同观察类型混为一份证据。均为证据不足时使用固定原因优先级，不随批次顺序切换。采集阶段仍只评估该阶段实际可见的材料。
- **历史与恢复：** 启动继续验证完整提交链、每个提交摘要及工作区格式。内存复用不缓存“历史已验证”结论，不引入延迟历史校验、可信检查点或历史删除；进程结束即失效。恢复后从当前来源材料重建候选，不沿用恢复前的缓存判断，回执不能替代事实存在性。
- **约束：** 人工字段、人工资料补齐、否决、忽略、已应用历史、删除标记、账号隔离、同步冲突和恢复缺口规则保留。附加候选只来自当前账号绑定、交付及恢复检查可处理且诊断保存成功的材料；失败批次或账号后续受阻材料不参与。正式诊断使用正式消费时的材料及上下文，诊断保存失败不确认相关交付。不新增平台请求、采集任务、CLI、页面或私有协议字段；服务重启仍不恢复 BOSS 跟踪。
- **替代关系：** 补充 [D033](0033-boss-import-convergence.md) 的共用处理链路和 [D034](0034-boss-cross-observation-attribution.md) 的临时上下文，稳定 [D035](0035-boss-conversation-association-application.md) 同事实重评的材料选择；保留各决定的归属检查及历史保护。保留 [D038](0038-boss-job-details-and-observation-groups.md) 的资料与展示规则及 [D039](0039-boss-manual-retired-job-resolution.md) 的人工处理边界。
- **兼容：** 应用 0.10.2、规则 v10，共享数据仍 v4。原事件、事实和应用 ID 不变；工作区、备份、私有快照、队列及检查点格式不变。
- **验收与取舍：** 用合成数据验证身份输出不变、迁移各侧保留、候选顺序无关、冲突不隐藏、人工保护、恢复及诊断失败语义，再测量实际服务启动时间和重复消费结果。不承诺固定启动时限；完整磁盘读取及历史校验仍随提交规模增长。相比跳过历史检查，本次保留安全检查并减少其中的重复工作。
- **本机核对：** 已核对新版实际启动和连续本地消费。首轮规则重评后，相同材料的后续消费不再产生提交，完整工作区摘要保持稳定；其他数据集合、已完成应用、人工决定与删除记录保持。等待、核对和保护数量不因优化变化，没有隔离故障或恢复缺口，BOSS 跟踪保持停止。
- **重新评估条件：** 实际测量仍显示启动不可接受时，再针对剩余成本提出独立方案；不得将本决定扩展为删除历史或信任未验证历史索引。
