# D054：按需 Issue 与正式变更的 PR 交付

- **记录日期 / 状态：** 2026-10-29 / 有效；规则实施、情境验证及实际远端交付结果随任务记录保存。
- **来源：** 用户从 PR 技能分析追问与项目流程融合，再要求整理需求；[需求规格](../specs/issue-pr-workflow.md)的 S5–S7 明确所有正式仓库变更走 PR、任务获准实施后可推送任务分支及维护相关 Issue／PR、合并另行授权，涉及界面时先完成适用人工验收。S8 调用 `ask-matt` 要求“可以继续，技能描述用中文”，授权实施。Issue 触发条件及具体接入位置为沿用讨论的实施选择。
- **问题：** 已有 Issue 约定、PR 模板和 CI，但交付默认停留本机，公开需求与最终变更之间缺少统一关联；PR 技能与模板结构分离，正文偏重界面图示。
- **决定：** 正式代码、测试、配置、文档和技能变更经任务分支与 PR 交付；Issue 按任务需要建立和复用。获准实施涵盖本任务分支推送及相关 Issue／PR 的创建更新，合并与部署等操作分别授权。操作要求由[议题跟踪约定](../agents/issue-tracker.md)维护，证据与材料归属由[变更共用规则](../agents/change-workflow.md)维护；`pr` 与模板统一中文摘要、证据及风险表达，技能描述用中文。
- **材料与状态：** Issue 或规格承接需求，PR 承接最终实现和公开交付摘要，本机保留详细证据、私有材料及关联索引。草稿、可审查、CI、人工验收和合并分别表达；响应未知先回查，不重复建单或宣称成功。一个 PR 不足以完成整个议题时保留剩余事项。
- **保留条件：** 沿用 D051 的短记录、按需证据工具和统计、版本与覆盖核对；沿用 [D052](0052-coordinator-owned-ticket-review.md) 的协调职责、[D053](0053-pre-implementation-design-review.md) 的前置设计核对及 [D017](0017-manual-browser-testing.md) 的人工浏览器分工。正式文档编辑不授权实施其方案。原有明确仅本地安排继续有效，私有材料不进入远端。CI、产品与数据格式保持原样，文档要求不冒充平台技术门禁。
- **取舍：** 复用现有 GitHub 和检查链路，增加任务分支与发布状态核对，换取可追溯的合并依据；小任务不强制 Issue 或完整规格，公开摘要与本机证据不维护多份完整正文。未选择逐次重新申请同范围远端授权、固定一工单一 PR 或自动合并。
- **替代关系：** 部分替代 [D051](0051-lightweight-development-records.md) 的默认本机交付及不自动补充 Issue／PR 安排，保留其余质量、简短记录和按需工具决定及历史来源。D052 的本机工单集成职责继续有效，目标分支 PR 合并单独受本决定约束。
- **启用与验证：** 新任务与本次启用变更按本流程交付；在途任务保留已有明确安排，或经用户明确接入；历史材料不批量补发。以文档/格式检查、维护技能名单覆盖测试及[工作流情境](../agents/workflow-regressions.md)核对授权、材料、证据和失败边界，实际远端状态独立报告。
- **重新评估条件：** 实际任务出现重复填报、发布歧义、需求或证据失联、合并前验收遗漏时，依据具体案例调整权威入口；不从 PR 数量或一次情境通过推断整体质量提高。
