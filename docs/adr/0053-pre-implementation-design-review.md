# D053：按影响前置系统设计核对

- **记录日期 / 状态：** 2026-10-29 / 有效；流程验证随交付记录保存，实际效果待后续使用观察。
- **来源：** 用户先询问当前系统设计如何把控，再问“怎么优化”，在助手提出按影响前置设计核对、复用现有记录和审查的建议后，调用 `ask-matt` 要求“继续”。本次据此推进本地流程改造；具体触发条件与入口安排为实施选择，不把助手建议记为用户逐项指定的硬要求。
- **问题：** 现有流程已有职责与接口原则、高风险前置验收和最终独立审查，但系统设计的核对时机及设计改变后的处理分散在多个入口，拆单前的责任与契约判断缺少统一交接要求。此为规则核对发现，尚不能据此归因历史返工。
- **决定：** 在[变更共用规则](../agents/change-workflow.md#实施前设计核对)集中维护按影响触发、独立核对、变化补查与完成条件；[代码库设计](../../.agents/skills/codebase-design/SKILL.md#系统设计核对)维护判断内容，规格、拆单、实施和审查入口按需引用。在确定相关工单边界或编码前复用 Spec 的独立目标判断，再对照设计方案，与适用的高风险验收核对合并安排；多工单由主协调者承接。
- **原因与取舍：** 前置检查完整路径中的职责、状态与失败处理，使关键设计缺口能在依赖它的实现展开前暴露。与保持原有分散入口相比，增加少量触发与交接规则；与独立设计技能、固定评审文档或新角色相比，复用现有材料与审查可控制维护成本。方案比较只针对真实选择。
- **保留条件：** 局部变更继续简短核对；草稿可保留未知，关键未知影响的拆单与实施等待解决；前置结论不增加授权、不替代最终两轴审查。受审决定变化仅补查受影响范围。沿用 D051 的短记录、按需工具与统计，以及 D052 的协调职责；产品、工具和 CI 行为保持。
- **替代关系：** 细化 [D051](0051-lightweight-development-records.md) 保留的前置核对与 [D052](0052-coordinator-owned-ticket-review.md) 的协调责任，不替代其决定；此前流程由提交 `d02a0e72869c1712e8a62b2a4b2771382491e2ad` 保留。
- **重新评估条件：** 后续涉及数据所有权与跨模块契约的任务显示重复审查、无收益等待、设计变化未被补查，或关键问题仍在交付后出现时，依据实际材料调整触发和交接；不以一次情境验证推断整体效率改善。
