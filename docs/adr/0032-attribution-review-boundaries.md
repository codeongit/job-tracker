# D032：归属证据不足时停止自动更新，人工状态与证据确认分开

- **记录日期 / 状态：** 2026-09-28 / 分项决定已确认；设计已整理，等待用户确认整体理解，尚未实施。
- **来源：** 用户在归属校验方案中选择“暂停该条自动更新”，并在 `grill-with-docs` 访谈中确认 Q1–Q9 均选 A。
- **已确认决定：** 新的自动简历状态应用必须有足够的归属依据。材料不足时保存未验证观察，暂停该条自动更新。用户核对后通过现有岗位编辑设置人工简历状态；该编辑不确认平台观察的归属，也不把它标为已验证。
- **历史范围：** 既有已应用记录保持原样，不做批量历史审计或自动回退。尚未应用的旧队列和待重放观察属于后续应用范围，不能因为采集时间较早而绕过新关卡。
- **取舍：** 用户接受一部分真实发送无法自动更新，优先减少误关联造成的状态改写。首版采用人工编辑岗位的流程，不增加逐条确认观察归属并恢复自动应用的流程；避免人工业务判断被误当作采集身份验证。
- **启用顺序：** 先启用严格关卡，归属材料不足的观察停止自动应用；随后通过实际样本完善支持。用户接受自动更新数量可能暂时下降。不能假设尚未证实的响应字段存在，也不能用复制的请求目标冒充独立响应证据。
- **提醒处理：** 每条提醒提供“已处理，收起提醒”操作，只收起对应提示，原观察仍保持未验证。编辑岗位不自动批量收起其相关提示；提醒处理不意味着归属确认或故障已解决。
- **提醒重新出现：** 重复采集同样的证据不重新提示。出现新的矛盾或不同消息时重新提示；例如原先缺少岗位身份，补证后发现岗位不匹配。收起仅针对当时看到的问题，不能永久屏蔽同一消息的后续异常。
- **跨设备一致性：** 提醒处理状态进入正式数据，保存在备份中，并参与现有的手动同步；服务重启或换页面后保留。私有诊断材料仍只保存在本机，不随提醒处理状态同步。不启用自动同步。
- **补证触发：** 同一条消息缺少身份字段时，不因此单独安排自动重试。后续会话有新变化或用户明确补查时可重新评估。网络超时继续沿用原有重试规则，仍受既有平台授权和预算约束。
- **冲突隔离：** 出现明确归属矛盾时隔离该会话的相关历史采集及简历自动应用。其他会话继续处理；普通新消息或列表指纹变化不能清除归属冲突隔离。收起提醒也不清除隔离。只有用户主动“重新核对”，且新的归属校验通过，才能恢复；账号身份异常仍按现有规则暂停整个账号。
- **定点补查授权：** “重新核对”只在对应账号跟踪运行时可用；停止或暂停时提示用户先明确启动或恢复跟踪。补查只针对选定会话，串行执行并受已有平台预算限制，不自动启动跟踪、不解除其他隔离。补查仍缺证据或发生冲突时保留原隔离；网络失败也不能解除隔离。
- **整体确认：** 上述产品选择均已逐项确认；按用户调用的 `grilling` 流程，先核对下述实现与验收约束，并在用户确认整体理解后实施。
- **替代关系：** 实施后收紧 [D025](0025-controlled-conversation-detail-read.md) 中“缺岗位 ID 时允许使用会话唯一岗位关联”的自动应用前提；保留 D025 和 [D030](0030-reject-misattributed-resume-observation.md) 已确认的文案含义，以及 [D031](0031-explicit-resume-semantics.md) 的观察、语义和应用分层。
- **重新评估条件：** 真实响应提供可独立验证的新归属材料、人工处理负担过高，或用户明确要求历史审计、逐条归属确认。

## 实现约束

- 归属判断使用 `verified`、`insufficient`、`conflict` 三种结果及固定原因码。明确区分请求目标、平台响应提供的身份和转换推断值；请求目标的复制、单行返回、同名公司或唯一岗位关联均不能单独作为独立验证依据。`friendId` 与 `bossId/uid` 不作相等假设。只有消息自身具有岗位身份且与已验证会话关联一致，才允许自动应用简历状态；尚未确认的响应字段不能靠合成测试宣称真实可用。
- 校验覆盖采集、转换、消费及恢复重放。私有快照、检查点和队列显式升版携带归属材料；服务重算或核验与账号、会话、消息、岗位绑定的证明，不能只接受生产者的成功标志。旧格式缺少材料的新应用进入证据不足；升级不撤销已应用记录。
- 保留来源事件和语义事实的稳定 ID。既有转换补齐字段可作为兼容身份或候选线索保留，但不能继续作为自动写入依据；同一事实的新材料只能补充观察并重评待核对应用，不能被当作另一个新事实重复应用。人工字段所有权和已否决观察继续受保护。
- 提醒状态独立于来源应用状态，不能用 `protected` 或覆盖原因来表示已处理。以事实身份、归属异常类型及参与归属判断的证据摘要计算问题标识，不含采集时间、批次或重复次数。确认收起绑定用户当时看到的问题标识；证据内容改变但没有新矛盾时不重新打扰，新的矛盾或另一条消息有独立提示。
- 提醒确认通过版本化服务命令、工作区修订号及幂等键提交；旧问题标识不能收起新问题。正式共享数据从 v3 升级到 v4，新增归属判定和提醒处理信息；完整迁移 data、base、pending 及冲突双方，保留旧工作区。兼容合并独立保留与问题标识匹配的提醒确认；确认只适用于对应问题，不能通过同步屏蔽新的冲突。旧客户端遇到新格式停止写入。
- 页面显示证据不足和归属冲突的计数、原因、只读详情与单条收起入口。缺少可靠岗位归属时显示在全局待核对中，候选岗位明确标为候选；不得以确定归属的形式放进某岗位的事实记录。“重新核对”通过独立的定点命令处理，绑定账号、会话和隔离版本，不能复用只处理详情标签的 `resume-details`。
- 最小诊断只保存版本、运行时间、阶段、身份摘要、字段存在情况、消息类型、比较结果和原因码，留在本机私有目录，目录/文件权限为 0700/0600；不保存聊天正文、附件内容或访问凭据，不随正式数据同步。按同一问题和证据摘要去重；提醒收起不删除材料，首版不新增自动清理。诊断落盘失败不得推进配套检查点或宣布验证完成。

## 验收条件

- 合成响应覆盖错联系人、错参与者、错岗位、身份缺失、岗位缺失及正常发送；当前历史入口、兼容入口、DOM 和列表转换均不能绕过关卡。
- 缺证据或冲突时，简历、消息状态及招聘阶段保持原样；旧队列、检查点恢复和重复消息不能重复应用或复活人工否决。
- 重复证据不会恢复已收起提示；同一消息出现新矛盾和不同消息能重新提示。确认时发生工作区或问题版本变化应拒绝，不能收起用户尚未看到的新问题。
- 验证跨设备手动同步、备份恢复与完整格式迁移；新矛盾不会被另一设备的旧确认隐藏，未知格式或未知字段仍停止写入。
- 新消息不能清除归属隔离；仅跟踪运行时接受定点补查，且只有验证通过才解除对应隔离。缺字段不额外重试，网络重试、预算和串行规则继续有效。
- 验证诊断权限、去重和写入失败恢复，以及不泄露正文和凭据；完成全量非浏览器测试、静态检查和格式检查。
- 真实字段及页面验收由用户完成，按需明确启动跟踪。样本缺少独立字段时应正确显示证据不足，不能为获得自动更新而放松规则；所有信息内部一致但实际错误的情况仍可能需要人工对照聊天。
