# D057：允许 Archify 在隔离浏览器中检查生成物

- **记录日期 / 状态：** 2026-10-30 / 已获用户授权。
- **来源：** 用户要求用 Archify 绘制项目架构图；生成物的浏览器检查因 R023 被自动审批拒绝后，用户明确表示“可以对于这个技能放开浏览器限制”。
- **问题：** 项目应用的人工浏览器测试分工被套用于独立图表，阻止 Archify 完成自身的交付检查。
- **决定：** 在已获授权的 Archify 任务中，代理可启动和控制隔离浏览器，对该技能生成的独立 HTML 图表或说明页执行浏览器检查、截图、视觉复核，以及任务所需的预览和导出。`finalize`、`browser-check`、`visual-check` 等生成物操作无需逐次重新索取浏览器授权；技能自身对可选预览等操作的触发条件继续适用。
- **边界：** 使用临时 profile 或技能提供的隔离浏览器上下文，只加载本次生成物及其必需的本地资源；使用已有浏览器，安装浏览器依赖仍须另行授权。该例外不授权连接用户日常浏览器、BOSS 平台、正在运行的工作区或私有 GitHub 数据，也不授权借 Archify 执行项目应用回归、`pnpm test:browser` 或 `pnpm verify`。
- **验证：** 按技能交付要求检查生成物，分别记录结构检查、自动浏览器检查和实际视觉复核；未执行的检查不宣称通过。图表验证不替代项目应用的人工验收。
- **原因与取舍：** 独立生成物可在隔离环境完成验证，避免同一技能反复请求已给出的授权；项目应用仍保留原来的测试责任与私有数据边界。
- **替代关系：** 为 [D017](0017-manual-browser-testing.md) 的浏览器限制增加 Archify 生成物例外；D017 的项目应用测试分工、CI 和人工验收要求继续有效。
- **重新评估条件：** Archify 需要访问真实应用、平台或私有数据，或用户要求调整其他技能及项目应用的浏览器测试分工时，另行明确范围。
