# D031：简历观察、含义和应用条件显式分层

- **记录日期 / 状态：** 2026-09-24 / 有效；真实浏览器待验收。
- **来源：** 用户要求通过建模和枚举减少平台文案的语义误判，并同意将平台观察、业务含义和应用决定分层。
- **决定：** 将观察类别、持久标识、精确文案、业务含义、展示标签与状态转换集中到共享规则模块。采集、转换、校验和展示共用定义。账号、会话和岗位归属以及人工字段保护仍独立验证，识别成功不表示允许写入岗位。
- **原因与取舍：** 分散的字符串分支容易导致同一文案含义漂移。集中定义并使用独立业务样例测试后，语义变更可在一个位置检查；枚举本身无法证明业务含义或来源归属正确，仍须核对已确认场景。
- **兼容：** 保留既有观察枚举值与来源事件/事实 ID，避免语义命名改进改变去重身份。旧 `request_sent` 明确映射为简历已发送。未知类型拒绝应用，普通卡片只作观察，人工否决不能被自动重放覆盖。既有数据不因重构重新解释或重放。
- **行为收紧：** 兼容历史采集入口采用与当前入口相同的精确系统文案识别，普通聊天和嵌套引用不再构成发送证据。
- **替代关系：** 落实 [D025](0025-controlled-conversation-detail-read.md) 与 [D030](0030-reject-misattributed-resume-observation.md) 的业务含义，不替代其身份校验、只读或人工验收边界。
- **重新评估条件：** 新增平台状态、真实样本否定现有含义，或需要改变持久枚举标识与数据格式。
