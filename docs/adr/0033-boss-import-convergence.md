# D033：BOSS 导入统一归属判断与处理链路

- **日期 / 状态：** 2026-09-29 / 已实现；真实平台和浏览器待人工验收。
- **来源：** 用户确认整体收敛计划，选择分阶段覆盖完整流程、延后复杂异常交互，异常集中在 BOSS 导入状态展示，并明确要求实施。
- **决定：** 采集报告平台实际身份依据；唯一归属模块返回 verified、insufficient、conflict；正式应用前重新校验。增量与回填共用消息处理，旧格式仅在读取入口兼容。候选岗位不能作为身份验证。
- **最小异常处理：** 未确认观察不改变简历及其联动字段，复用 waiting/review 与原因。本机状态展示只读摘要，不创建行动任务，不新增提醒收起、跨设备提醒同步、长期会话隔离或定点重新核对。
- **数据：** 正式共享数据保持 v3；私有协议显式升版携带依据，旧队列缺依据的新应用停止。事件及事实 ID 保持，批次新版本摘要绑定归属材料。历史已应用记录保持原样，人工否决不重放。
- **取舍：** 先严格阻止无法证明归属的应用，接受实际路径暂时全部证据不足。真实平台字段没有核实前不能以合成测试声称支持。降低异常流程和数据迁移成本，保留必要的持久化与恢复保障。
- **约束：** 只读、串行、显式授权、动作预算、单写者、恢复缺口检查、人工字段所有权及手动同步继续有效。诊断限本机最小材料，不保存正文或凭据。
- **替代关系：** 收紧 D025 唯一岗位候选的应用前提；保留 D030/D031 的简历含义。部分替代 D032：严格关卡保留，复杂异常交互延后，冲突仅阻止相关观察应用，不增加持续会话隔离。
- **重新评估：** 人工提供可核对的平台身份材料、未应用负担影响使用，或明确需要同步提醒和异常恢复流程。

## 实现与验收边界

- 正式共享数据 v3 不变；私有快照 v4、队列 v3、历史检查点内容 v2（沿用原检查点路径）。旧快照及队列仍可读，旧材料不能作为新的已确认应用依据。
- v0.9.2 从联系人响应的直接 `uid` 与 `friendSource` 保留映射字段，本人身份复用页面与列表账号的一致性检查；消息保留 `mid`、`from.uid`、`to.uid`。请求目标与列表候选不作为缺失响应字段的替代。消息岗位证据仍是独立必要条件，不能因联系人和参与者相等就确认岗位归属。
- 增量与回填共用请求表达式、转换与应用；同一事实补充依据可重新进入增量批次，不改变事件 ID。同批冲突依据拒绝提交。
- 诊断保存在各自私有根目录的 attribution-diagnostics；先落诊断，再提交检查点、快照、队列或应用。只保存摘要、字段存在情况、观察类型、判定及首次记录时间，不保存正文和原始身份。
- 设置页与 CLI 使用当前应用结果生成归属摘要；最近采集缺稳定消息身份的异常按会话和原因去重显示。收起、同步提醒和长期隔离未实现。

## 2026-10-03 字段核实进度

用户执行正常采集及公平补录后，本机脱敏样本中能核对联系人响应 `uid`、`friendSource` 与请求目标，以及两处本人账号和消息参与者的相等关系。v0.9.2 接入这些已观察到的字段，缺失或矛盾继续由统一关卡处理。该结论限于取得的样本，不构成平台接口契约。

已检查的消息岗位白名单路径（消息直接字段、body 及 body.job 下的 `encryptJobId` / `jobId`）均缺失；白名单外路径没有检查。故自动简历联动未恢复。此前问题涉及的另一条会话尚未取样，原始误关联原因尚未查明；临时取样仍待完整核实后删除，本机依据保留，公开测试只用合成数据。

## 2026-10-03 一次性核实收尾范围

用户要求减少重复采集，选择受限结构诊断并确认继续一次性双会话对照。v0.9.4 使用本机临时任务复用人工补录入口，只诊断两个指定的已加载会话，最多 6 次历史相关请求；正常跟踪不增加异常驱动请求。任务不应用简历、不推进原业务历史检查点和游标，开始后不自动重试；不新增永久定点重核对功能。此一次性排障授权不改变 D033 延后长期隔离与定点重新核对的决定。

批准的结构和候选身份编号同时取样；未知键名、正文、简历与凭据不落盘。材料仍可能缺失或截断，候选名称和编号相等不能证明归属。真实核实未完成，自动简历联动未宣称恢复。取得本轮材料后，以可靠依据、明确冲突或无法确认之一结束本轮并清理临时代码；未确认路径仍保持证据不足。

## 2026-10-03 一次性对照结论与清理

两个目标会话均取得联系人和历史消息响应。联系人行的 `encryptJobId` 与列表岗位一致，直接 `uid` / `friendSource` 和消息 `from.uid` / `to.uid` 对应；本轮未发现这些身份关系的冲突。联系人行还返回数字形式的 `jobId`，它与加密岗位编号是不同表示，本轮不据此建立未经确认的映射。

批准检查的消息岗位路径仍未返回标识；部分 `body.extend` 是字符串，按约定未解析，未知键名也未保存。因此结论为“消息岗位证据不足”，并非平台不存在岗位依据或列表与消息无法对应。原始误关联原因未查明，自动简历联动未恢复。

v0.9.6 删除全部临时身份取样、结构诊断和双会话任务代码及专用测试，保留直接联系人和本人账号提取修正、统一关卡与合成回归。本机脱敏依据和固定结论保留。排查到此结束，不继续循环补录；后续若要求新的字段范围，须单独确定范围后安排。既有严格规则和延期项不变。
