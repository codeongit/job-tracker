# D035：允许依据会话关联应用简历观察

- **日期 / 状态：** 2026-10-04 / 已实现；真实浏览器验收待用户确认。
- **来源：** 用户明确要求“先不要求有岗位信息改”，并确认统一应用于新消息和历史等待项、保留身份检查、跨岗位拦截及人工保护。
- **决定：** 消息自身岗位身份不再必填。账号、观察身份、联系人响应与消息双方完整对应，有会话关联候选岗位并唯一绑定到现有岗位时，允许依据该关联应用。消息自身岗位身份若存在，仍校验与候选一致；会话曾关联不同岗位而消息缺自身岗位身份时等待，同消息不同候选岗位继续冲突拦截。
- **范围：** 新观察、已有 waiting/review 项、历史补录和经明确核对的恢复重放共用规则，不建立启用后新增消息基线。旧队列缺联系人或消息参与者依据仍不能应用。已应用、人工保护、人工否决和删除记录不自动重新应用或恢复。
- **取舍：** 采用已有会话关联作为应用依据，接受它不等同于消息岗位身份证明。平台按岗位隔离历史的契约尚未核实，未发现跨观察异常也不能保证归属正确；未知的招聘者跨岗位历史仍可能误关联。用户选择统一处理历史等待项而非只处理新消息。
- **记录与兼容：** 内部 verified 表示满足所选应用规则，缺消息岗位身份时判定原因为 attribution_conversation_association，不声称消息提供了岗位身份。应用或无效果记录的原因追加 conversation_association 后缀，人工保护和否决原因保持。应用规则 v6，共享数据仍 v3，原事件/事实 ID 和私有协议不变。
- **替代关系：** 部分替代 [D033](0033-boss-import-convergence.md) 的消息自身岗位身份必填前提；保留 [D034](0034-boss-cross-observation-attribution.md) 跨观察拦截，以及 D030/D031 的简历含义与人工保护。
- **运行与重新评估：** 不增加平台请求，不自动重启服务或恢复 BOSS 跟踪。真实验收由用户完成；发现新的误关联或取得岗位专属会话依据时重新评估该规则。

## 身份排查收尾（2026-10-04）

用户确认 BOSS 会话可以绑定岗位，并明确要求身份核实先收尾。继续采用本决策的会话绑定应用规则，保留账号、联系人、消息参与者、跨岗位关联及人工保护检查；不再把取得消息自身岗位字段作为排查待办，不安排额外临时取样或重复补录。

已有真实样本支持联系人响应与列表岗位、本人账号与消息参与者的对应关系；用户授权执行的单条消息预览也已完成。临时诊断和预览代码、执行任务标记已清理，本机脱敏依据保留。消息自身岗位身份及平台历史隔离契约未作全面验证，原始误关联原因未确定；这些是本轮结论边界，后续有新误关联时再按具体问题排查。身份排查收尾不等同于业务联动全项验收，持续跟踪仍需显式启动。
