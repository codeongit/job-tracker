# D016：两个业务入口与统一岗位详情保留浏览上下文

- **记录日期 / 状态：** 2026-09-14 / 有效；看板及列表/看板切换安排由 [D018](0018-simplified-status-paginated-jobs.md) 调整，全部日期下的排序由 [D021](0021-newest-jobs-first.md) 调整，筛选、日期语义与详情上下文规则继续有效。
- **来源：** 用户指出四个页面动线混乱、选择岗位后筛选丢失，确认“行动、岗位”两个业务入口、日期筛选合并与统一详情，并明确要求实施。
- **问题：** 岗位列表和看板重复占据导航，日期查询又分散在独立页面；打开或处理岗位会清空查询，让连续处理被打断。
- **决定：** 行动分今天、接下来、待整理；今天新增且未安排的岗位通过带数量的入口直达待整理。岗位以列表/看板切换呈现，关键词、当前阶段和日期共用且取交集；默认全部阶段、全部日期，列表每页 10 个，含已结束岗位。日期列表展示完整当天事件，看板展示当天数量，统一详情可查看当天事件。
- **交互：** 所有入口共用详情；桌面使用右侧面板，手机使用全页详情。打开/关闭、编辑保存、草稿恢复及切换展示或页面时保留筛选、页码、滚动位置；主动修改筛选从第一页开始。编辑后不再匹配筛选时保留详情并提示，删除时关闭；关闭后恢复原位置与触发控件焦点，控件已消失时聚焦结果标题。详情集中提供记录沟通、安排下一步、更新阶段，仍需明确提交。
- **日期与默认值：** 保留 D015 的计划日、完成/取消本地日、沟通日、首次联系日、同日行动及导入里程碑去重规则；历史查询显示当前阶段。查询日期不改变新增记录默认日期或实际完成时间。刷新默认进入行动今天，岗位筛选恢复全部；会话中的条件不写入共享数据。
- **原因与取舍：** 同一批岗位共用查询和操作入口，既可按天查询，也能连续处理筛选后的结果；不引入额外路由、历史状态快照或数据字段。
- **约束：** 保留 D013 核实事项可确认、可转行动及无关待办不遮挡的规则；保留 D011 草稿、中文组合输入和同步期间输入保护。删除记录不参与查询，无日期记录可在全部日期下查看。数据、同步、备份及草稿格式不变。
- **替代关系：** 替代 [D015](0015-date-based-daily-record.md) 的独立页面和刷新后查询今天安排，保留其业务日期语义；调整 [D013](0013-actionable-today-view.md) 的展示位置，保留其核实规则和原有原因。
- **重新评估条件：** 需要跨设备保留浏览条件、日期范围/月历、历史阶段还原，或需要独立可分享的岗位链接。
