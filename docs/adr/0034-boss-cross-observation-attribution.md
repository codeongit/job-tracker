# D034：BOSS 跨观察归属防错

- **日期 / 状态：** 2026-10-04 / 已实现；真实浏览器验收待用户确认。
- **来源：** 用户确认跨观察防错计划并要求实施；选择明确消息岗位依据仍可应用、跨岗位重复阻止新增应用且不回退历史。
- **决定：** 在 D033 的唯一归属模块中，用当前未删除来源观察与整个待处理批次构建临时上下文。同账号同稳定消息 ID 关联不同候选岗位时进入 review；同会话曾关联不同岗位且消息缺少自身岗位身份时等待。账号隔离，普通消息与简历观察均参与候选检查；人工否决不删除原观察线索，也不因此恢复应用。
- **原因与取舍：** 单条观察核对不能发现跨会话或跨批次的候选矛盾。采用保守拦截而非只记录异常；跨岗位重复表示关联矛盾，不能据此认定平台返回错误。会话岗位变化不等于整个会话错误，明确消息岗位依据继续接受原有检查。
- **应用与恢复：** 同批先收集全部候选，再处理，避免事件顺序影响结果。只重评本次处理的新观察和 waiting/review 项；已应用、人工保护、人工否决与删除记录遵循原处理规则。恢复从当前数据重建上下文，回执不能替代事实存在检查。
- **诊断与兼容：** 采集和队列诊断限于该阶段可见材料；消费使用当前工作区与批次，保存失败不确认相关交付。复用固定原因、只读摘要和权限边界，不保存正文或原始身份。共享数据仍 v3，应用规则 v5，事件/事实 ID 和私有协议保持不变，不新增持久化索引、实体或操作入口。
- **替代关系：** 补充 [D033](0033-boss-import-convergence.md) 的跨观察异常检查，不放宽其归属前提；保留 D030/D031 简历含义和人工保护。
- **限制与重新评估：** 未发现重复不证明归属可靠。岗位专属会话尚未核实，不启用该自动归属路径；不新增平台请求或恢复跟踪。若证明消息 ID 并非账号内稳定身份，或取得可核对的岗位专属会话依据，再明确评估对应规则。
