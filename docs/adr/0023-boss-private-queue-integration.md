# D023：BOSS 私有队列接入与 2026-09-18 首批规则

> 2026-09-21：以下为已实施的 v0.7 历史方案。首批快照、日期、人工保护和不推断语义继续有效；IndexedDB 权威存储、schema v2、45 分钟/每日 16 次限制与单轮运行方式由 [D026](0026-local-authoritative-workspace.md) 替代，精确简历状态由 D025 补充。

- **记录日期 / 状态：** 2026-09-19 / 有效。
- **来源：** 用户确认“BOSS 接入与 2026-09-18 首批录入”完整实施计划，明确首批范围、正式建档规则、手动触发方式、频率与验收要求。
- **决定：** 采用“固定采集脚本 → `.local/boss-integration/` 不可变队列 → 工作台 IndexedDB 事务”的链路。CLI 提供 `preview`、`enqueue`、`check`、`status`；工作台打开时由同源随机会话读取队列，多标签串行消费，正式数据与来源事件同一事务提交后才写回执。正常链路不调用模型，不直接修改磁盘备份或远端 JSON。
- **首批规则：** 锁定用户指定的 2026-09-18 已保存快照、`Asia/Shanghai` 及策略版本。30 条明确 `HH:mm` 的完整记录进入授权批次；10 条“昨天”和 60 条空时间标签不进入本批。新岗位阶段为“已触达”，`appliedAt=2026-09-18` 且来源标记为用户确认的本批首次联系日，`createdAt` 使用实际工作台录入时间；精确关联到已有岗位时不覆盖阶段、首次联系日或其他人工字段。
- **后续规则：** `check` 仍由人工执行；完整且无冲突的新岗位可直接建档为“已触达”，没有可靠日期时 `appliedAt` 留空。来源绑定按平台、账号和岗位 ID 隔离，多招聘者可指向同一岗位；歧义、公司冲突、删除标记及资料缺失进入待整理。人工改动和主动清空优先，旧批次只能补证据，不能回退较新的自动字段或复活岗位。
- **观察语义：** 已读、送达、入站和未知按具体会话、消息与采集顺序保存为“平台观察”，不写成人工 `readState`，不推断简历发送、面试、Offer、拒绝或精确阅读时间。共享数据升级为 v2 的 `sourceBindings`、`sourceEvents`；工作区和备份外层版本保持 v2，所有 v1 入口显式迁移，未知格式停止写入。
- **运行边界：** 浏览器检查至少间隔 45 分钟、每天最多 16 次；详情补齐每批最多 3 个且每天最多一批、导航间隔至少 60 秒。首版不创建周期任务、不自动重试、不自动 GitHub 同步。登录、验证码、账号不符或结构异常立即暂停，并在私有目录以 `0700/0600` 权限保留最小故障材料。
- **验收边界：** 脚本、迁移、队列、合成数据与静态检查由代码测试完成；真实工作台页面的来源绑定、30 条事务结果与显示按 D017 由用户打开页面后验收。入队成功不等于已经录入。
- **替代关系：** 将 D022 的接入建议落实为首版功能；不替代 D003 的手动云同步、D009 的不推断缺失事实、D017 的真实浏览器人工验收或 D019 的人工简历联动。
- **重新评估条件：** 启用周期调度、扩大招聘平台写操作、改变首批范围、自动同步 GitHub、跨账号自动合并岗位，或让模型直接提交业务阶段。
