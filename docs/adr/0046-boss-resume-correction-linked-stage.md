# D046：简历误判纠错同时撤回自动联动阶段

- **日期 / 状态：** 2026-10-08 / 已确认；实现与验收见版本记录。
- **来源与问题：** 用户指出已授权的卡片发送误判清单纠正后，“沟通中”没有回退。D045 的初次实现只修正简历字段，留下了被错误发送判断推进的招聘阶段。
- **决定：** 既有 `correct_boss_resume_semantics` 命令继续按明确清单核对事实、账号、岗位、自动字段和独立发送支持；简历纠正为未知时，将仍由自动维护、当前值与 last-auto 均为“沟通中”、且没有人工沟通活动的阶段回退为“已触达”，更新必要的阶段来源记录。人工阶段、值已偏离自动记录或面试及后续阶段保留，消息已读状态仍保留。
- **补偿与重试：** 已是 `protected / user_rejected_wrong_resume_semantics` 且简历为自动未知的所选事实，可以通过新命令 ID 与当前已审阅 revision 补偿同一阶段遗漏，原人工否决时间和决定保持。其它保护原因不准入，独立发送或接收依据继续阻止回退。原 commandId 精确重试只返回原持久结果，不能以改变实现重算旧命令；新请求无业务变化时不追加提交。
- **恢复保护：** 同一事实、应用、目标与有效原始观察仍在时，旧备份恢复继续保留人工否决。当前岗位已纠正为自动已触达、没有独立发送支持且恢复的自动阶段符合条件时撤回错误联动，简历已是未知也不能跳过阶段保护；人工所有权、真实新发送、缺失材料、删除标记及 pending 两侧保护继续遵循 D045，不补造证据、不复活记录。原先仅纠正简历的决定不在恢复时扩大为阶段回退，人工沟通活动继续保护。
- **取舍：** 一律保留招聘阶段会留下错误联动，一律回退沟通中又可能撤销人工进展。因此仅撤回明确清单中可核对的自动联动；普通消息和回执仍按原规则处理，不从有聊天推断已发送简历，也不从缺发送依据断言未曾发送。
- **替代关系：** 部分替代 [D045](0045-boss-reviewed-resume-semantics-correction.md) 中“招聘阶段及其自动来源记录保持”的边界。D045 的明确清单、人工否决、账号与身份验证、原子提交、独立发送保护和恢复缺口规则继续有效；[D019](0019-boss-resume-status-link.md) 的正常发送推进仍保持。
- **格式与运行：** 应用 0.10.17，规则 v12；共享数据 v4、工作区 v3、完整备份 v2、服务协议 v1 和私有格式不变，无迁移。不新增平台采集、页面入口或 GitHub 同步，服务重启不恢复跟踪。
- **重新评估条件：** 将来普通聊天也独立维护招聘阶段，或引入更完整的字段变更来源时，应重新核对阶段支持材料与回退条件。
