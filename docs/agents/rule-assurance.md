# 规则保障表

本表将 [AGENTS.md](../../AGENTS.md) 中的规则连接到已有实现、检查、审查和人工验收入口，不另行定义业务规则。初次编号对应原有 30 个列表条目；六行文档索引仍是阅读入口，不另计规则。一条规则可能包含多个要求，以下分别说明已覆盖的部分与剩余边界。

编号随原规则保留，调整位置不重编号；新增规则使用下一个未使用编号，删除的编号不复用。新增、拆分、删除、替代及历史编号是否稳定，由差异审查核对；只检查当前文件无法证明历史没有重编号。

本表使用下列固定六列表头，每条映射占一行，连续排列在分隔行后；所有列必填，缺少保障或证据时填写“暂无”。单元格中的竖线写成 `\|`。示例放入代码块或引用块，避免混入正式映射。

`pnpm check` 检查规则与映射是否一一对应、编号是否缺失或重复，以及本地链接和受支持的文档标题锚点。它只验证结构，不运行表中的验证入口，不检查代码符号或测试断言含义，不判断是否已取得用户授权。代码或测试文件存在不等于测试通过，也不等于规则已被完整保障。链接到原文章节后，以 ID 定位具体条目；代码链接只指向文件，文字说明要核对的机制或场景。

表中“验证入口”是后续验证的起点，不保存本次运行结果或永久通过状态。每次任务按影响选取规则，在现有任务或 PR 记录中保留版本、实际检查结果、独立审查与未验证项，流程见[变更共用规则](change-workflow.md)。浏览器入口由用户或人工测试者执行，适用[真实浏览器测试分工](../MAINTENANCE.md#真实浏览器测试分工)；链接到浏览器脚本不构成代理运行授权。
