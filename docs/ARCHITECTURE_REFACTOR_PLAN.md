# 架构整理与后续重构清单

记录基线：`6fd11e498ceae77578a7ae7458c86227fbe16f93`，应用 `0.10.17`。代码位置均指该基线，后续实施前需重新核对。

本轮范围是整理现状文档与后续清单。下列代码阶段均为**待实施**；拟定的 module、interface 和 adapter 职责是设计建议，尚未形成新的源码接口。本文不表示已经完成代码重构或人工验收。

## 选择依据与保留范围

用户同意本轮整理现状文档与后续清单；以下代码阶段仍是待评估建议。依据是[现状架构](ARCHITECTURE.md)、[数据与恢复](DATA_AND_RECOVERY.md)、[维护流程](MAINTENANCE.md)及[改动工作流](agents/change-workflow.md)。后续实施按用户任务确定具体范围，每项开始前分别核对现有机制与用户要求，并记录该项的新基线。

已有共用规则继续保留：`collector/boss/job-evidence.mjs` 的资料证据判断、`dist/local-workspace.js` 的串行命令交付、`dist/resume-rules.js` 的简历含义与转换、`dist/boss-attribution.js` 的归属判断、`dist/source-identity.js` 的稳定身份。`dist/storage.js` 继续负责模式路由与缓存/事务，`scripts/workspace-store.mjs` 继续负责正式提交与持久命令；拆分其他 module 不另造写入链路。

按调用者实际需要确定 interface：集中规则、顺序和错误处理，让调用者少了解内部状态。只有具体变化、复用或测试需求才设置 seam；文件长度本身不构成拆分理由。保留原生 ES modules、当前数据库和不可变 JSON 工作区，技术栈或存储选择的调整另行讨论（[D008](adr/0008-lightweight-static-architecture.md)、[D026](adr/0026-local-authoritative-workspace.md)）。

## 阶段 1：整理现状文档

- **问题证据：** 架构说明同时包含当前职责和版本演进细节；阅读一条保存、采集或同步链路时，需要跨越多段说明核对入口与所有者。
- **文档责任：** 架构说明集中呈现运行方式、主要 module、调用方向及所有权；恢复细节、运行步骤与决定理由分别引用现有专门文档和 ADR。本清单仅记录后续工作。
- **主要使用者：** 后续实现者、审查者与人工验收者；源码调用者不受本阶段影响。
- **保持结果：** 当前两种模式、只读授权、单写者、手动同步、恢复与隐私规则准确呈现；不把历史人工验收状态改为已完成。
- **验证与完成条件：** 对照实际入口及主要调用点，检查文档差异、相对链接和格式；无需版本、协议或迁移改动。
- **停止或重新讨论：** 发现文档与代码矛盾时，先标明来源并核对；需要改变既有业务决定的内容不能当作文字整理直接落定。

## 阶段 2：隔离 BOSS 纯业务与网页 adapter

- **问题证据：** [boss-integration.js](../dist/boss-integration.js) 同时包含批次应用 `applyBossBatch`（1300）、人工纠错 `correctBossResumeSemantics`（609）、恢复保护 `preserveBossResumeCorrections`（811），以及网页发现（1511）、HTTP client（1530）和页面 consumer（1644）。服务与恢复流程因此从同一文件取得业务规则，网页依赖的所在位置不够清晰。
- **拟定 interface 责任：** 纯业务 module 接受当前数据、标准批次及显式上下文，维持批次校验、归属重算和业务应用，返回结果或固定错误；网页 adapter 管理会话发现、HTTP、Web Locks 与页面状态通知。先隔离网页 adapter，再根据维护收益判断批次应用、人工纠错与恢复保护是否需要内部拆分；不强迫三者共用一个入口。具体文件名与导出名待实施时确定。
- **主要调用者：** `scripts/workspace-consumer.mjs` 调用批次应用及缺口判断；`scripts/workspace-store.mjs` 调用绑定、忽略和人工纠错；`dist/workspace.js` 调用恢复保护；`dist/app.js` 创建页面 consumer；详情、设置与同步冲突视图读取业务展示查询。
- **保持结果：** 批次校验、摘要与稳定 ID，归属判定、来源事实/应用、计数及错误码保持；人工否决与联动阶段纠错不因导入或恢复复活。服务模式页面继续只读消费状态，既有兼容消费路径和提交后回执顺序保留。
- **验证与完成条件：** 纯业务导入及测试不需要 DOM、`location`、`localStorage`、`navigator` 或网络；调用者通过各自实际使用的 interface 验证。复用 `boss-consumer`、`workspace-consumer`、`boss-stable-attribution`、`boss-resume-correction*` 等合成测试，比较完整输出、身份、计数和失败结果，而不只验证 import 成功。
- **停止或重新讨论：** 若拆分引入依赖循环、迫使服务创建网页环境、复制共享规则，或需要改摘要/枚举/错误语义，先调整设计。若现有缺陷阻止行为保持，把修复范围与独立预期明确记录，再继续重构。

此阶段遵循 [D031](adr/0031-explicit-resume-semantics.md)、[D033](adr/0033-boss-import-convergence.md)、[D040](adr/0040-boss-repeated-work-and-stable-reevaluation.md)、[D045](adr/0045-boss-reviewed-resume-semantics-correction.md)及[D046](adr/0046-boss-resume-correction-linked-stage.md)，不借模块移动重新解释平台含义。

## 阶段 3a：收敛共用详情导航

- **问题证据：** [app.js](../dist/app.js) 的 `openDetail`（352）同时管理选中项、来源位置、详情展开、渲染和焦点；BOSS 相关岗位及候选路径（1272、1309）还在调用后直接改 `detailOrigin.scrollY`。调用者需要了解导航内部状态。
- **拟定 interface 责任：** 详情导航 module 接受岗位、来源位置与可选目标区域，统一打开、关闭及返回；来源位置由入口明确提供，module 内部保存详情会话。DOM 操作通过现有渲染与焦点 adapter 完成，不把 app 的全部全局状态包装进新 module。具体名称待定。
- **主要调用者：** 行动与岗位列表、BOSS 核对和相关岗位入口、保存岗位后的详情打开、草稿恢复与删除流程。
- **保持结果：** 筛选、页码、滚动、焦点、详情展开和有效勾选保持；编辑后不匹配筛选仍保留详情，删除后关闭；手机全页与桌面面板行为保持。查看或编辑候选不确认来源归属（[D016](adr/0016-two-entries-unified-detail.md)、[D042](adr/0042-data-sync-guided-resolution.md)）。
- **验证与完成条件：** 用合成数据及可替换的渲染/焦点 adapter 验证导航状态与目标选择，覆盖来源控件消失、切换岗位、返回及删除。人工核对行动、列表、BOSS 清单三类入口的往返；真实布局和焦点仍待用户确认。
- **停止或重新讨论：** 若新 interface 暴露大量 app 状态、增加隐式回调顺序，或改变日期、刷新默认值与查询语义，缩小抽取范围并重新核对收益。

## 阶段 3b：收敛岗位编辑

- **问题证据：** `app.js` 的 `openEditor`（732）与 submit 路径（851）集中处理 HTML、表单默认值、简历联动、草稿、并发比较、人工字段、正式保存及提交后导航；界面和纯编辑规则交织。
- **拟定 interface 责任：** 编辑 module 接受原记录及表单输入，集中准备白名单变更、联动和人工字段信息；网页 adapter 负责控件、中文输入、草稿绑定和错误展示。正式写入继续调用已有 `change`/storage 路径，提交后导航使用阶段 3a 的 interface；命名与参数在实施前核对。
- **主要调用者：** 新增/编辑岗位、BOSS 候选编辑、岗位草稿恢复；保存继续经过 `dist/storage.js` 与 `dist/local-workspace.js`，由服务重跑业务校验。
- **保持结果：** 旧状态兼容、BOSS 简历联动、平台职位状态与招聘阶段分离、阶段变化记录、结束岗位取消待办，以及主动清空的人工所有权保持。草稿仍需明确提交，恢复使用新 ID，成功只清理提交的不可变版本；草稿清理失败不否定正式保存。
- **验证与完成条件：** 通过实际编辑 interface 验证合成输入、原记录比较、联动与所有权；复用状态、简历、草稿、中文输入和本机命令测试。人工核对新增、编辑、草稿恢复、中文输入及保存后返回位置，未确认前保留待人工验收。
- **停止或重新讨论：** 若拆分要求改变草稿结构、字段所有权、保存命令或默认值优先级，先明确行为与兼容范围；不将纯重构扩大为表单规则改写。

## 阶段 4：按收益整理手动同步编排

- **问题证据：** `app.js` 的 `synchronize`（1195）负责入口门槛、快照、锁、创建确认、冲突和反馈；[github.js](../dist/github.js) 的 `syncWorkspace`（150）已有共用的读取、合并、上传、超时核对与确认。现有分工基本成立，需要先证明剩余复杂度值得集中。
- **拟定 interface 责任：** 若收益成立，用同步编排 module 集中一次手动同步的生命周期，返回明确结果；页面 adapter 提供确认、冲突展示和通知，REST/SSH adapter 继续提供既有传输能力。保留共用 `syncWorkspace`，不另造一套合并或上传算法；具体 interface 待评估。
- **主要调用者：** 设置页与现有同步入口、冲突解决后的再次手动同步；下游仍是 REST/SSH client、storage 与本机工作区命令。
- **保持结果：** 用户手动触发，快照失败中止配套操作；私有仓库/分支与固定 JSON 路径检查、上传字节限制、base/local/remote 合并、删除标记、冲突双方、上传期间新编辑及超时读回保持。本机一次性同步事务与服务重新核对保持，令牌只留页面内存。
- **验证与完成条件：** 先列出能消除的调用者知识和重复规则；没有明确收益可结束评估并保留现有分工。实施时复用 `sync`、`ssh`、`local-workspace`、`workspace-store` 测试，验证创建门槛、409、未知响应、目标变化及上传中编辑；人工验收保存冲突后仍待上传和明确触发同步。
- **停止或重新讨论：** 需要自动上传、通用远端写入、合并模式差异、放宽服务事务或扩大凭据生命周期时停止本阶段，按新的用户要求另作设计与决定。

## 各代码阶段的共同验收

1. 使用公开源码、合成记录和临时目录。记录修改前基线与调用者；业务预期来自用户规则及既有契约，重构前输出只作保持行为的对照，不能证明业务含义正确。
2. 根据影响核对完整数据输出、旧事件/事实/应用 ID、批次 digest、重复执行结果和固定错误。相同材料不制造新业务提交；未知字段、未来格式或无效材料继续拒写，不丢字段后保存。
3. 正式写入仍由既有单写者、expected revision/CAS 和持久 commandId 交付。响应不确定时精确重试同一请求；revision 冲突重新核对，不盲目重放。提交与回执顺序、快照失败及缓存失败语义保持。
4. 检查人工字段、否决/忽略、已应用历史、删除标记、账号隔离、岗位依赖冲突和 pending 双方。恢复仍是新编辑；缺事实或观察保留恢复缺口，不从回执补造、复活或推断已录入。
5. 正常重构验证不访问招聘平台、不读取真实工作区、不新增采集或自动 GitHub 同步。服务启动不授权跟踪；公开文件、测试与 `dist/` 不包含真实记录、简历、私有材料或凭据。
6. 代理运行相关非浏览器测试、`pnpm check` 与 `pnpm format:check`；发布前运行完整 `pnpm test`。不运行 `pnpm verify`。按[D017](adr/0017-manual-browser-testing.md)提供简短人工清单，真实浏览器由用户负责，CI 结果不替代人工确认。
7. 按[改动工作流](agents/change-workflow.md)完成现状/目标的独立核对及 spec、standards 两轴审查。每阶段记录完成证据、待人工项和剩余风险；尚未完成的项目继续明确标为待实施或待验收。

本轮纯文档不改应用版本、协议或格式，也无迁移。未来代码阶段按实际发布与行为范围维护 `package.json`、`dist/version.js` 和 `CHANGELOG.md`；若改变关键决定，新增下一个 ADR、保留旧记录并更新决策索引。不能用本清单提前宣称某项行为调整已获确认或已实施。
