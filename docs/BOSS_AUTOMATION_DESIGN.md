# BOSS 采集、队列与本机录入

更新日期：2026-09-23；实现版本：v0.8.4。脚本、协议和合成数据测试不等于真实环境验收；任务页连接和关页运行仍由用户验收。

当前规约见 [AUTOMATION_POLICY](AUTOMATION_POLICY.md)，架构决策见 [D026](DECISIONS.md#d026本机权威工作区与显式持续跟踪)。v0.7 的首批日期和只读边界继续有效；“工作台关页只能积压”“每次只手动 check”“45 分钟/每天 16 次”等历史限制已被本版替代。

## 运行与入口

本机服务和 BOSS 跟踪是两个独立生命周期。服务仅监听回环地址，启动后读取本机工作区、处理已授权的本地队列，不访问 BOSS。没有登录自启、系统定时任务或自动 GitHub 同步。显式开始跟踪后，服务内部才按间隔运行采集；服务重启后不恢复跟踪授权，预算和检查点保留。

状态诊断也必须区分执行上下文：宿主机终端能够访问服务监听的 `127.0.0.1`，Codex 沙箱、容器或其他受限环境则可能只能读取共享目录、不能访问宿主机回环端口。后者出现 `SERVICE_UNAVAILABLE` 仅代表该执行上下文不可达，不能证明宿主机服务已停止。实时状态以宿主机终端执行 `pnpm service status` 和 `pnpm boss status` 的结果为准；磁盘中的 tracking、运行记录和工作区 HEAD 表示最后持久化状态。服务运行、BOSS 跟踪运行以及 BOSS 跟踪暂停是三个不同结论，报告时必须分别说明。

| 命令                                            | 作用                                                                      |
| ----------------------------------------------- | ------------------------------------------------------------------------- |
| `pnpm service start/status/stop`                | 启动、只读查询或安全停止本项目服务；停止前校验实例身份，不按陌生 PID 强杀 |
| `pnpm boss start`                               | 校验工作区与固定采集配置，建立/复用任务页，开始持续跟踪                   |
| `pnpm boss run` / `pnpm boss check`             | 请求单轮采集；同一轮在执行时复用结果，不堆积补跑                          |
| `pnpm boss pause` / `resume`                    | 停止后续采集或在原因排除并校验后恢复；不清空预算                          |
| `pnpm boss resume-details`                      | 只解除详情所有权技术阻断；不访问浏览器、不改变账号生命周期或清空岗位退避  |
| `pnpm boss stop`                                | 等待在途轮次结束并停止跟踪，不关闭用户原 BOSS 标签                        |
| `pnpm boss recover-page`                        | 仅停止/暂停状态下显式恢复任务页；不自动刷新原标签                         |
| `pnpm boss recover-saved`                       | 纯本地补交已保存快照并消费队列；保持停止，不访问 BOSS 或占平台额度        |
| `pnpm boss status` / `doctor`                   | 查看跟踪生命周期、预算、服务状态与诊断                                    |
| `pnpm boss preview/enqueue`                     | 兼容首批快照的本地预览与授权入队                                          |
| `pnpm boss enqueue-yesterday --date YYYY-MM-DD` | 兼容用户明确确认日期的标签补录，不从当前日期猜测                          |
| `pnpm boss enqueue-resume`                      | 兼容已保存快照的简历观察入队                                              |

采集器源码固定在仓库 `collector/boss/`，账号标签及固定历史快照由私有配置指定；网页不能传任意脚本、路径或平台请求，旧 `trackerRoot` 配置不再决定执行位置。私有快照、连接、运行状态和 Chrome profile 固定保存在 `.local/boss-collector/`。连接使用直接 CDP 与已核验账号的任务专用后台标签，不要求每轮把用户 BOSS 标签选到前台。无平台请求副作用的调试通道传输中断可按 2、10、30 秒最多三次重连，计数和下一次时间跨轮次持久化；已发出的历史请求若结果未知则按一次保守计数、不在重连中重放，待页面内 15 秒超时后由下轮从持久页码继续。任务页、浏览器实例、URL、登录或账号身份异常不重试并停止，带创建、导航、切换或关闭副作用的命令也不自动重放。每次平台轮次还必须原子消费控制器签发、绑定精确额度的短时单次票据；旧脚本不能绕过统一调度。显式恢复不是无限刷新或自动登录。

## 数据链路

```text
明确开始跟踪 → 固定采集器串行读取
  → 不可变快照与检查点 → 确定性事件批次 → 私有队列
  → 本机单写者校验/业务应用 → 不可变完整工作区提交 + 原子 HEAD
  → 提交成功后回执 → 页面读取正式状态
  → 用户手动 GitHub 同步
```

正常链路不调用模型。每轮分别记录采集、排队、业务应用及回执结果；“快照成功”“已入队”均不等于“已正式录入”。工作台页面关闭时，本机服务仍可消费已绑定账号的队列；持续采集还要求跟踪已开始、Chrome/CDP 与登录有效。电脑休眠或进程停止期间不运行，不在恢复后补跑漏过的轮次。

首次迁移由用户在保存正式记录的浏览器明确确认。页面先导出含草稿的完整备份并显示数量与 SHA-256，再允许提交；缺少原工作区、来源全空或导出后记录/草稿变化都会停止。服务保存迁移前原始工作区并验证全部结构，再将账号归属从旧浏览器来源迁移到稳定服务工作区 ID。尚未迁移或账号尚未绑定时不擅自创建空正式工作区。手机/公开静态版继续以自己的 IndexedDB 独立编辑，通过手动 GitHub 同步交换共享数据；它不远程控制本机采集。

## 频率与实际动作预算

持续运行默认在上一轮结束 2 分钟后开始下一轮；列表读取不导航、不刷新、不滚动。旧 45 分钟/每日 16 次尝试限制取消，预算针对实际发出的平台动作，而非整个失败命令。

| 动作                   | 默认上限                                                          |
| ---------------------- | ----------------------------------------------------------------- |
| 历史消息只读请求       | 每轮 20 次、滚动 1 小时 60 次                                     |
| DOM 会话补采           | 每轮最多 1 次、相邻切换至少 30 秒；默认禁用，私有页面验收后才允许 |
| 岗位详情导航           | 每轮最多 20 个；相邻导航至少 10 秒                                |
| DOM 切换与详情导航合计 | 滚动 1 小时最多 60 次                                             |

详情岗位失败采用持久的 30 分钟、2 小时、24 小时三段退避；第四次实际失败进入本机技术隔离。退避/隔离项让出公平游标，成功补齐后清除重试状态。详情标签丢失、网址变化和读写超时只形成 `failureScope=detail`，不会累计账号级连续失败；所有权不一致额外阻断详情阶段。登录、验证、账号、浏览器实例或主任务页异常为 `failureScope=account`，仍立即或按账号规则暂停。
| 并发 | 每账号串行，一次仅一轮；重复触发合并，不排队补跑 |

生命周期命令按调用顺序串行；`start`、`resume`、`recover-page` 在操作 CDP 前等待调用前已经开始的轮次收尾，`pause/stop` 的持久状态优先于晚到轮次结果。

可确认未触发平台动作的本地预览、校验、断链失败和队列处理不占平台动作额度；已经发出但失败的动作仍计数。平台轮次开始前先持久化本轮可用上限作为保守预留；拿到结构化用量后替换为实际值，进程崩溃或输出损坏时保留预留，不按零次处理。常规轮次读历史接口，不自动点击聊天；DOM 额度是受控补采上限，不代表已启用自动切换。历史分页逐请求保存会话和页码续点，续点未完成前不推进公平游标，遇已知消息停止回溯；预算耗尽只延后有关阶段。预算持久化，重启、暂停或恢复不清零。上述值是本工具的保守默认值，不是平台承诺的安全阈值。

## 身份、字段与业务规则

- 会话使用平台账号 namespace、`friendId`、`friendSource` 并核对 `uniqueId`；岗位独立使用 `encryptJobId` 和规范链接。名字、公司不能独立充当主键，跨账号不自动合并。
- 已有来源绑定优先；唯一且相容的平台岗位 ID/链接才可关联既有岗位。多招聘者可关联同一岗位，同会话换岗不继承旧岗位名称、确认状态或业务阶段。
- 列表范围是当前已加载会话，不自动滚动加载全部历史；缺席不代表删除。岗位名只接受实际 `jobName` 或经核对详情标题，不用招聘人职务、分类、摘要替代。
- 来源字段记录上次自动值及人工所有权。人工修改和主动清空均受保护；不能因后来值恰好等于自动值就夺回写入权。
- 新的完整、无冲突岗位可建为“已触达”。增量列表的具体 `HH:mm` 以快照 `capturedAt` 对应的上海日期为证据和新岗位首次联系日；它不随延迟导入日期变化。“昨天”、空标签等缺乏可靠日期时留空。旧岗位首次联系日、人工阶段与删除标记不被普通采集覆盖。
- 消息已读、送达、入站、未知按具体会话和消息保存。送达不等于未读，旧消息已读不移给新消息，不推断精确阅读时间、面试、Offer 或拒绝。

共享数据 v3 保留 `sourceEvents`，新增 `sourceFacts`（事实）和 `sourceApplications`（业务应用结果）。事实 ID 仅由平台、账号、会话、消息 ID 和事实类型组成；岗位名、联系人、采集时间及规则版本不参与，不同回执状态是不同事实类型。没有稳定消息 ID 时只保留带独立事件 ID 的等待证据，不创建岗位、语义事实或业务应用，待补齐后重新求解。旧事件 ID 原样保留，通过确定性映射连接语义事实，不自动重演旧状态；事实存在、业务已经应用和队列已经回执是三个独立判断。跨浏览器手动同步保留同一事实与应用 ID，不能换浏览器就再次新建岗位。

应用结果区分：`applied` 已应用、`protected` 人工保护、`waiting` 等待依赖、`review` 真实歧义、`no_effect` 无业务变动。普通简历卡片只保留观察，不列为“必须人工核对”。缺材料且规则明确的等待项可在后续证据齐全后重新评估；身份歧义、公司冲突、人工保护和删除记录不靠猜测自动消解。

### 精确简历状态

以下是用户确认并有来源证据的白名单：

| 平台状态                             | 本机简历状态 |
| ------------------------------------ | ------------ |
| 附件简历请求已发送                   | 已发送       |
| 对方已同意，您的附件简历已发送给对方 | 已发送       |
| 您的附件简历 … 已发送给Boss          | 已发送       |
| 对方已查看了您的附件简历             | 对方已接收   |

第三类仅允许附件名位于固定首尾之间，不做宽泛关键词匹配。普通 `type=4` 简历卡片不直接代表发送或查看。优先读历史消息接口，保存稳定消息 ID、方向、平台时间及最小状态证据，不保存完整聊天正文；DOM 补采证据使用独立来源标识，生产默认关闭，只有私有样本验收确认唯一行、稳定身份和 `unreadMsgCount === 0` 后才可启用。

精确状态仅单向提升已唯一关联岗位，人工字段优先，不回退更高状态。缺岗位 ID 时仅允许复用会话唯一岗位关联。成功提升后可联动本机消息为已读，并把“已触达/旧待联系”推进到“沟通中”；面试、Offer、已结束保持不变。这是工作台本地业务更新，不是向 BOSS 发送简历或改变平台消息。

### 已授权历史日期

首批固定快照 `2026-09-18T14-49-59-473Z_ae82d08d-b89d-46a4-b8ec-cb855214bd5a.json`、摘要、策略及 `Asia/Shanghai`：30 条时分纳入、10 条昨天排除、60 条空标签未知。仅首批新岗位 `appliedAt=2026-09-18`，来源是用户指定的本批首次联系日；`createdAt` 为实际录入时间。此规则不复用于持续跟踪。

`enqueue-yesterday --date 2026-09-20` 等补录以保存快照的原始标签和用户明确日期为依据，不能按运行当天重新解释“昨天”，也不覆盖已有关联岗位的日期和阶段。

已成功落盘但转换失败的快照使用 `pnpm boss recover-saved` 恢复。该入口等待在途轮次结束，严格核对账号、检查点、摘要、持久会话身份和队列批次，随后消费正式队列；它不调用采集器/CDP、不预留平台预算、不启动两分钟调度。只有本地快照/检查点类暂停在完整恢复后可清除；登录、验证码、账号和任务页类暂停仍须按正常 `resume`/`recover-page` 流程处理。

## 事务、并发与故障

本机正式数据在 `.local/workspace/`：稳定身份、不可变完整提交、原子 `HEAD.json`、写者锁及迁移原件。固定 API v1 使用随机会话、协议版本与 Host/Origin 校验；写命令包含 `commandId` 和 `expectedRevision`。网页只能发送编辑业务记录、切换同步配置、暂存/解决冲突、确认同步、恢复及来源绑定等固定命令，不能提交通用整工作区覆盖，也不能用业务编辑伪造来源账本。CAS 失败先读最新状态，不盲目重放用户编辑；相同命令丢失响应可幂等取回原提交结果。未知格式、损坏提交链、外部改动 HEAD 或别的活动写者都停止写入。

同一批岗位变更、事实、应用记录和命令结果随完整工作区一次提交；回执只在提交成功后写。回执丢失重放复用已提交结果。队列坏批次隔离留诊断；已知账号失败暂停该账号后续依赖，其他账号可继续。同步冲突按岗位及其任务/沟通/来源依赖隔离，无关岗位的后台应用与人工编辑仍可提交，并把变化重基到 pending 候选；批次重基时新发现的岗位冲突会自动重新求解为等待项，只有账号身份、全局记录或无法隔离的结构冲突才停止整批。

三方同步对同一记录的独立字段自动合并；岗位的阶段/结束原因/简历/已读状态、平台/链接/外部 ID，以及任务的状态/完成时间分别作为原子字段组。组内或同字段分歧仍由用户选择，冲突两侧都携带已经确认的独立字段变化，选择后不会把其他字段改动丢掉。

登录、验证码、账号/目标/页面结构异常立即暂停；暂时故障连续三轮后暂停。保存最小错误码、运行阶段、最后成功快照、完成项与剩余项，然后等待显式处理。暂停不会清空材料或预算，任务页失效不能靠反复刷新修复。恢复旧备份后也不能仅凭磁盘回执说“已录入”；事实或应用缺失先显示恢复缺口，只有用户明确发起带当前 `revision` 的固定重放命令才修复来源账本，且不能复活删除岗位或覆盖人工字段。

私有 `.local/boss-integration/` 保存 inbox、receipts、runs、incidents、control 和 tracking 状态；`.local/boss-collector/` 保存采集器原始快照、连接、运行材料和浏览器 profile。目录 `0700`、文件 `0600`；终端只输出统计、错误和路径。原始快照、聊天正文、截图、令牌不进入 `dist/`、`collector/` 或公开测试。

## 升级与验收

先备份并关闭旧客户端，再升级服务、刷新当前工作台，明确执行首次迁移和账号归属确认；后续普通采集、入队或导入不需要改代码、重启服务或刷新。只有服务代码/配置升级等场景需要重启，重启后须重新明确开始跟踪。

人工验收最少覆盖：本机与静态模式身份提示；原工作区、基线、冲突双方和草稿完整；连接后切到其他应用不抢焦点；关工作台后采集并正式录入；重复批次零新增；人工清空不回填；冲突只阻塞有关岗位；登录/任务页丢失暂停且不刷新；停止/重启不恢复跟踪；手动云同步往返不重放旧状态。未完成这些步骤前不能宣称真实环境已验收。
