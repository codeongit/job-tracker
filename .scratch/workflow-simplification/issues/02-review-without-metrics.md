# 02 独立审查不依赖统计启动

## 来源与决定

来源为[流程精简规格](../../../docs/specs/workflow-simplification.md)的 S1–S3、“可选工具与审查材料”、A2、A9；规格基线为 `cd117913753e341d5c47adc2085502a0f5690b52`。

已确认决定是让审查统计按专项观察需求启用。普通任务不运行统计命令、不填写统计 JSON，仍须进行完整且独立的 Spec 与 Standards 审查，并保留现有 Spec 两阶段目标核对。

拆单时的基线行为见[审查技能](../../../.agents/skills/code-review/SKILL.md)：准备材料前必须 `review:metrics start`，审查使用其生成的编号、目录和规则副本，收尾必须 `finish`。解除这个启动依赖时，必须保留它目前承载的版本固定能力。现有工具入口及测试可从[统计脚本](../../../scripts/review-metrics.mjs)和[非浏览器测试](../../../test/review-metrics.test.mjs)核对。没有阻断性待决事项。

## 交付结果与约束

交付不启用统计也能从完整材料得到独立结论的审查路径。固定提交，或保存完整工作树差异、相关新增文件及必要基线，均可供两轴使用；原始要求、适用规则版本与目标版本须可定位。材料可放在已有本地记录附近，不再依赖统计编号、目录或必须由 `start` 生成的副本，不新增材料管理系统。

Spec 第一阶段仍独立读取原始要求、基线及既有规则，第二阶段才收到新方案与差异；Standards 独立审查同一版本。相关内容变化后补充材料、重跑受影响检查并复查，不能以统计数量、报告存在或旧版通过代替结论。

同步维护共用规则中的审查、交付条款及所有入口中“必须提供统计编号／摘要”的要求。未启用统计时，结论可以直接保存在现有本地记录，必要细节使用引用。此项可使用现行记录格式，不依赖 01 的短模板。

明确选择专项观察时继续使用现有 `start / finish / feedback / stats`，从实际启用时记录，不补记过去未观察的审查。已有工具接口、记录、固定首报、历史有效性和统计口径保持；只需解除流程默认依赖，不预设必须改写脚本。记录流程不自动向 Issue／PR 写入。

## 验收条件与验证

- [x] **A2：** 不运行任何统计命令，分别对固定提交、含暂存／未暂存修改及相关新增文件的工作树完成独立两轴审查。两轴取得同一版本的完整范围、原始来源和规则依据；缺失新增文件或版本依据时不得判为通过。
- [x] **A2：** 能核对 Spec 先基线后差异的实际材料交付顺序，以及 Standards 的独立结论。已有有效局部结论可按范围复用，不能把未审部分推定通过。
- [x] **A3 的审查部分：** 初次审查后改变相关文件或规则，旧结论明确失效或需补查，补充材料后只对受影响范围复查；保持未变化且仍适用的证据，最终两轴结论对应同一版本。
- [x] **A9：** 普通审查不会创建统计样本；专项统计从实际启动时计时，保留首报及反馈语义。旧记录可读取，未知项不补造，样本不足不作趋势推断。
- [x] **A6 的审查部分：** 修复后的有效发现保留原编号和历史判定，当前阻断状态由实际修正版本及复查依据决定；无统计时同样能追溯，启用统计时不把 `valid` 改成 `false_alarm`。
- [x] 共用流程、审查技能、交付引用、手册及保障映射不存在残留的“未运行统计就不允许审查或交付”要求；两轴、阻断项处理及必要检查不被删除。关键决定记录实际落地范围。

沿用[流程回归](../../../docs/agents/workflow-regressions.md)的 W04（变更后复查）、W09（历史发现）、W11（恢复审查与调度），补充 A2 的未启用统计场景。保留独立上下文、同版本材料和实际动作记录；恢复后的日志不可补造，槽位充足时沿用现有并行安排。工具兼容性可使用临时仓库及合成记录运行既有 `review-metrics` 测试，不对真实历史记录进行实验。文档检查、适用脚本测试和审查按[总览](../README.md#共同约束与交接)执行，浏览器不适用。

- **材料充分性：** 已明确；无阻断性设计缺口。
- **执行授权：** 规格 S7 已授权本地实施与验证；沿用该授权，不向远端写入。
