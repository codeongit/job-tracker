- **保存方式：** 工单按技能默认位置保存在本目录，并随 Git 管理；实际执行产生的交付记录仍放在被 Git 忽略的本机目录。工单不是交付记录。

依赖关系为 **01、02 可并行 → 03**。前两项分别交付记录路径和审查路径，无互相阻塞；它们会维护部分相同正文，集成时保留双方变化并复查。03 承担“不强制 UUID、证据和统计”的完整任务路径，必须使用前两项的结果，不仅验证证据开关。

每项同时维护其行为涉及的共用规则、技能入口、说明及回归依据，不另拆“只改文档”或“最后补测试”的工单。实际开始前重新核对当前基线和有效授权；材料充分不等于可以开始实施。

## 共同约束与交接

- 正式规格由仓库 Markdown 承载；每次交付保存本地简短记录，即使已有 Issue／PR，也不因此向远端追加正文或链接。没有新增远端发布授权。
- 保留必要非浏览器检查、两轴独立审查、Spec 两阶段目标核对、阻断项处理、版本适用性及高风险前置验收。未知时间、验收和使用情况保持未知。
- 保留证据和统计工具及旧资料；不新增任务状态机、统一任务命令、自动报告、看板或交付发布系统。固定技能校验环境不在本次范围内。
- 每项流程行为变化按 [ADR 维护约定](../../docs/adr/README.md#如何维护)记录实际落地的决定与范围，保留历史理由；不预占 ADR 编号，不把其他工单的目标提前标成已实施。
- 验证沿用[流程回归协议](../../docs/agents/workflow-regressions.md#复现协议)：隔离临时副本、公开或合成材料、独立执行与裁定，保留实际动作和结果。前向试验与确定性工具测试分别报告，文字匹配不能替代执行证据。
- 各项文档运行 `pnpm format`、`pnpm check`、`pnpm format:check`；工具或检查器确有修改时运行对应非浏览器测试。浏览器分工沿用 [D017](../../docs/adr/0017-manual-browser-testing.md)，不运行 `pnpm verify`，CI 和产品行为保持原样，不为流程文档提升应用版本。
