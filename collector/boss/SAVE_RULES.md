# BOSS 会话与岗位保存规则

## 自动化执行规约（2026-09-18 补充）

用户明确要求：正常人的查看节奏、平台只读且不回复或执行计划外动作、固定脚本优先、异常保留必要现场后再介入。长期规约已保存到 [工作台自动化操作规约](../../docs/AUTOMATION_POLICY.md)，本目录 [AGENTS.md](AGENTS.md) 同步列出执行边界。

工作台 v0.8.2 后台运行器统一负责低频串行、小批处理、账号级持久预算与暂停；采集器的 `run` 只执行控制层下发的一次有界周期。采集器本身不安装调度任务，也不绕开控制层单独重复访问平台。

## 身份与关联

- 正式会话键只使用已验证的账号 namespace、`friendId` 和 `friendSource`，并核对 `uniqueId`。
- 联系人、公司、招聘人职务都是可变化属性，不参与会话去重；缺失平台 ID 时不退回姓名主键。
- 岗位按 `encryptJobId` 独立识别，会话和岗位用关联记录连接。不同会话可以共享一个岗位；同一会话换岗位时旧关联改为历史。
- 姓名＋公司只允许在旧 v1 迁移时做双方唯一的推定映射。岗位冲突或任一侧重复时进入 quarantine。

## 消息与回执

- 聊天摘要和 `latestMessageId` 是独立字段；摘要变化只能称为列表摘要变化。
- 只有前后 `latestMessageId` 相同且非空时，才记录同一条摘要的回执变化。
- `[已读]` 与 `[送达]` 只接受页面明确、可见且标签与样式一致的 DOM 证据。
- 送达不等于未读；无回执、离屏行和不认识的状态都记为 `unknown`，不能当作 0。
- 列表缺项不表示删除、拒绝、下架或沟通结束；历史会话继续保留。

## 简历事件

- 优先通过求职端只读历史消息接口采集，不点击用户可见聊天；允许使用任务独占后台页，但 UI 切换一旦可能改变未读状态就停止。
- DOM 补采默认禁用。只有账号绑定的人工验收策略存在、目标平台身份和最新消息 ID 唯一、且已验收字段明确给出入站未读数为 0 时才允许切换；缺失不推定为 0。每轮最多一次、间隔至少 30 秒，结果未知时保留检查点且不自动重试。
- DOM 系统消息必须同时取得稳定消息 ID 和平台时间，来源保存为 `dom_chat_status_message_v1`，不得标记成历史接口来源。当前选择器规则仍待真实浏览器验收，验收前保持禁用。
- `type=4` 只能在同时取得稳定消息 ID、发送方向和平台时间后形成简历事件证据。普通文本、列表摘要、已读或送达回执不能证明简历已发送。
- “被索要”和“对方已接收/查看”必须分别来自独立结构化动作或回执；未经真实样本验收保持未知。
- 简历事件没有岗位 ID且会话曾换岗时进入待核对，不绑定当前岗位。第一阶段只保存平台观察，不改工作台人工简历状态、消息状态或招聘阶段。

## 岗位证据

- 岗位名称只能来自列表实际 `jobName` 或完整详情标题 `「岗位招聘」_公司招聘-BOSS直聘`。
- 招聘人职务、岗位分类、公司名、相似搜索结果和聊天 ID 都不能作为岗位名称或链接来源。
- 详情链接必须是 `https://www.zhipin.com/job_detail/<encryptJobId>.html`，不保存查询参数或片段。
- 岗位名称、链接、聊天快照分别保留自己的 `observedAt`／`capturedAt`，不能互相冒充采集时间。
- 详情标题公司与会话公司不一致时，只保存候选及实际观察公司，不自动成为正式岗位名称。
- 页面暂时看不到岗位时保留旧证据，但标记关联为历史；新岗位 ID 不能继承旧岗位名称或确认。

## 人工确认

- `confirmed_user` 只作用于精确的会话键、岗位 ID 和规范 URL。
- 一条链接的确认不能传播到同公司、同岗位或其他招聘者。
- 当前已确认的 VAST 链接在迁移后继续保持原精确作用域；其他生成链接仍是未人工确认。

## 操作边界

- 用户显式运行 `start` 时允许启动专用 Chrome 用户目录，并在缺少任务页时最多创建或导航一次；兼容命令 `connect` 保持同义。日常 `resume`、`check`、`run` 不创建、刷新、导航、关闭或激活沟通页。
- 正常采集只复用已核验的持久任务标签，不调用 `bind`、`open`、`close`，任务标签无需保持可见或选中，也不得抢占用户前台焦点。
- `check` 只读任务专用页面已经加载的数据源；不滚动、不发送消息、不投递，也不访问用户原来的沟通页。独立的简历历史采集可调用已验证的只读接口或在任务独占后台页受控读取会话。
- `enrich` 通过同一 CDP 浏览器实例，只导航本次任务新建并记录 target ID 与所有权令牌的详情标签，不点击聊天。异常时只关闭仍能用浏览器实例、target ID、所有权令牌和 URL 精确核验的标签。
- 定向补齐可用 `--time-label 昨天` 限制为当前快照原始标签；不重新解释标签日期。每批最多 20 个，相邻详情导航至少间隔 10 秒；工作台另以持久的 DOM/详情滚动小时 60 次预算限制总量。
- `disconnect` 只解除任务标签绑定并删除连接记录，不能关闭、置空或导航该标签。
- 不调用旧 `fill-jobs.mjs` 的聊天点击流程，不在采集器内安装定时任务，不自动处理验证码或登录；工作台只有在用户明确开始跟踪后才按周期调用有界 `run`。
- 任务标签丢失、网址漂移或浏览器实例重启后，自动轮次不创建、导航或刷新标签；由用户显式运行 `recover-page` 最多恢复一次。正常采集不要求选中，且不得循环重连。
- 历史请求在页面内 15 秒主动超时，CDP 外层 20 秒停止等待。结果未知的已发请求按一次保守计数，不得在调试通道重连中重放；保存当前会话/页码，等下一轮继续，避免与旧请求重叠。
- 账号、任务标签、网址或绑定核验失败时不提交新快照。

## 存储

- 每次成功保存创建新的 v3 JSON；旧 v1 和旧 v2 文件均不覆盖，读取旧 v2 后只通过显式适配生成新的 v3 文件。
- 聊天状态、岗位关联、正式证据、候选和用户确认分开保存。
- 重复迁移或重复证据导入必须幂等；歧义数据保留待核验，不能静默丢弃或随意配对。
- `jobs.md` 与 `status` 必须使用同一个共享 resolver，避免正式状态和导出结果分叉。
- 终端只输出计数、状态、错误码和路径，不输出聊天正文或联系人明细。
