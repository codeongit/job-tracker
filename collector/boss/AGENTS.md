# BOSS 采集器长期操作规约

来源：用户于 2026-09-18 明确要求记录。接手本目录的开发、运行与排障时，先阅读 [工作台自动化操作规约](../../docs/AUTOMATION_POLICY.md) 和本目录的 [SAVE_RULES.md](SAVE_RULES.md)。

- 以正常查看节奏执行，低频、串行、小批量，复用连接与来源证据。采集和补齐应共用账号锁与频率预算；不得为了完成数量而连续重连、刷新或批量打开标签。
- 招聘平台只读：不回复、发送消息、打招呼、投递或发送简历，不执行原计划之外的操作。常规列表采集只覆盖页面已加载会话且不自动滚动；允许为已识别会话调用已验证的只读历史接口，或在任务独占后台页受控切换会话。若 UI 切换会改变未读状态，必须停止并使用只读接口。
- 受控 DOM 补采默认禁用；没有账号绑定的人工验收策略，或不能从已验收字段明确证明入站未读为 0 时不得点击。DOM 证据使用独立来源，不得伪装成历史接口；切换结果未知时不得自动重试。
- 日常采集、比较和数据转换优先使用固定脚本，不依赖模型逐次选择浏览器动作。模型与人工在失败后依据必要的私有现场材料介入，不自动扩大权限或动作范围。
- `start` 是允许启动专用浏览器并最多创建／导航一次任务页的显式操作；`recover-page` 是失效后的唯一显式重建入口。`resume`、`check`、`run` 等正常或调度操作只复用已保存的浏览器实例和 CDP target ID，不创建、导航、刷新、关闭或激活沟通页。页面 ID 失效时停止，不循环重建，也不要求用户反复选中。
- 异常时保留运行 ID、错误步骤、错误码、已完成结果、最后有效快照及剩余项目。不得输出私人正文、读取凭证或全量导出页面内存；故障材料先保存，再进行已核验安全的任务标签清理。
- 登录、验证码、账号不符、目标漂移或字段结构异常时停止；失败不覆盖成功快照，不清空队列或盲目重复提交。
- 工作台接入见 [接入说明](../../docs/BOSS_AUTOMATION_DESIGN.md)。本机服务通过统一控制层运行本采集器，把不可变证据写入私有队列并提交正式工作区；工作台网页关闭不影响已授权队列的本机录入。服务重启后跟踪保持停止，且始终不自动 GitHub 同步。
- 用户已授权将固定的 2026-09-18 首批 30 条明确时分记录入队，并允许符合规则的后续手动 `check` 建档；除此之外不得扩大平台操作或私有数据写入范围。
